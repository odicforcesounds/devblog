i3 Desktop — From Nothing to Hero

The tiling window manager that fits in one config file and one head. This page is the road from a bare X session to a desk that is yours: the config file, the keys, workspaces, the bar, icons that actually render, the extra software that glues a desktop together, and a complete annotated fancy config — every value explained by the line that sets it.

01From nothing

i3 is a tiling window manager for X11, created by Michael Stapelberg and friends, with two rare virtues among WMs: it is complete without a desktop environment, and it is configured entirely in one text file that you can read, version and print. Nothing is hidden behind a GUI settings tool — that is not a limitation, it is the whole culture.

  • Tiling by default: windows share the screen instead of covering each other. The mouse survives for exactly two jobs — resizing and clicking sometimes.
  • Keyboard-driven by contract: $mod (usually Super) plus a letter does everything.
  • Stable where it matters: the IPC protocol and the config language have stayed compatible for over a decade; configs from 2012 still work in 2026.
  • Siblings of the family: i3blocks, i3lock, i3status, and the Wayland rewrite sway (same config language).
$ apt install i3 i3lock i3status     # or pkg / dnf / pacman equivalents
$ echo "exec i3" > ~/.xinitrc
$ startx                            # or pick i3 at your display manager's login

First launch runs i3-config-wizard: it writes a starter config and asks one question that matters for the rest of your life — your Super/Alt preference for $mod, plus how you want Win-key alternatives laid out. Choose Super: Alt belongs to the applications Emacs, Firefox and everything in between.

Note: the wizard's output is just a normal config file. Everything it wrote can be re-edited by hand from now on, and this page assumes ~/.config/i3/config (or ~/.i3/config, whose existence it still honours as a fallback).

02The configuration file

One file: ~/.config/i3/config. Plain text, one directive per line, # for comments. There are no plugins, no modules, no scripts inside — which is why you never fear a typo breaking half of your desktop at once.

DirectiveMeans
set $mod Mod4Name a key once, use it everywhere (Mod4 = Super, Mod1 = Alt).
bindsymBind one key combo to an action or a command (bind gives named modes with fallbacks).
exec / exec_alwaysRun a program at startup; exec_always also reruns on i3 restart.
assign / for_windowSend new windows to workspaces / apply rules to matching windows (criteria in [brackets]).
bar { }The block that defines the whole bar (position, status command, colours, tray).
set_from_resourceRead a value from X resources before falling back to a literal (nice for theming).
 
# ~/.config/i3/config — smallest honest start (numbers in comments explain lines)
set $mod Mod4                          # 01: Super is the leader key
set $term xterm                        # 02: one terminal variable, used everywhere below

bindsym $mod+Return   exec $term       # 03
bindsym $mod+Shift+q  kill             # 04
bindsym $mod+h        split h          # 05
bindsym $mod+v        split v          # 06
bindsym $mod+j        focus down       # 07
bindsym $mod+k        focus up         # 08
bindsym $mod+Shift+j  move down        # 09
bindsym $mod+Shift+k  move up          # 10

bindsym $mod+1 workspace 1             # 11: one line per workspace
bindsym $mod+2 workspace 2

bindsym $mod+Shift+c reload            # 12: re-read the config, keep windows
bindsym $mod+Shift+r restart           # 13: restart i3 entirely
bindsym $mod+Shift+e exec "i3-nagbar -t warning -m 'Exit i3?' -B 'Yes' 'i3-msg exit'"

The two reload commands are different and worth knowing early: reload re-reads the config into the running session; restart replaces the WM process itself — the reason an X restart is rarely needed to fix WM problems.

Note: i3-msg is the command-line twin of the keys: run i3-msg workspace 3 from a shell to switch workspaces, i3-msg 'resize grow width 40 px' to poke the layout from scripts or i3-nagbar. i3 --moreversion also tells you at a glance if you broke something with the config when i3 refuses a reload.

03Keys first, mouse optional

The key grammar is one verb family: focus, move, workspace, layout, resize, mark. Learn it once and it survives any monitor arrangement:

ChordActionThe sentence it writes
$mod+dexec dmenu_runA launcher appears; type to run anything installed.
$mod+w / $mod+s / $mod+elayout tabbed / stacking / toggle splitEach container cycles between the three layouts.
$mod+f / $mod+Shift+spacefullscreen toggle / floating toggleEscape hatches when a tiling assumption breaks.
$mod+spacefocus mode_toggleMove focus between tiled and floating windows.
$mod+rresize (mode)Enter the built-in resize arrows mode; same keys again to leave.
$mod+Shift+s sticky togglesticky flagFloating window follows you across workspaces.
$mod+a / $mod+Shift+afocus parent / focus childWalk the container tree instead of hashtables of corners.
Note: bindsym binds the keysym; bindcode binds keycodes and survives layout switches on non-English keyboards. If your national characters breakbindsym bindings, switch those specific binds to bindcode with xev to find the code.

04Workspaces and layout

Workspaces are i3's answer to virtual desktops: ten of them by default, bound to $mod+1..10 and named whatever you like (icons in section 07 use names, not numbers):

set $ws1 "1: term"
set $ws2 "2: web"
set $ws10 "10: mail"
bindsym $mod+1  workspace $ws1
bindsym $mod+2  workspace $ws2
bindsym $mod+Shift+2  move container to workspace $ws2

Layout is a tree. Each workspace holds containers; each container splits horizontally/vertically, or switches to tabbed/stacking. The tree is why:

  • $mod+e (toggle split) flips the last container's split direction — the "swap two windows' arrangement" trick.
  • $mod+a then $mod+v / $mod+h changes where the next window appears: focus parent first, then split — the honest way to do “open my editor below my browser inside workspace 2”.
  • $mod+Shift+1..10 moves a window to another workspace, and with $mod+Shift+space first it can float instead.
# window rules on the tree (for_window + criteria)
for_window [class="^xfce4-notes"] floating enable
assign [class="^ Firefox$"] $ws2
assign [class="^thunderbird\ "] $ws10
Note: find the exact class/title strings with xprop (click the window): WM_CLASS(STRING) is what criteria use. Guess never; everyone who guesses ends up with rules that match the wrong window.

05Starting things automatically

i3 has one startup mechanism and no autostart daemon folklore: /etc/i3/config exec lines (yours, in ~/.config/i3/config).

exec --no-startup-id nm-applet        # network tray applet
exec --no-startup-id picom -b          # compositor, daemon mode (section 10)
exec --no-startup-id dunst             # notifications server
exec_always --no-startup-id feh --bg-scale ~/Pictures/wall.jpg

exec --no-startup-id xss-lock --transfer-sleep-lock --i3lock --nofork

Two honesty points:

  • --no-startup-id stops i3 from grabbing focus for the started window — desktops lose their minds less when this flag is used.
  • That is all of it. No ~/.config/autostart, no XFCE daemons, no systemd user units required here. If a program refuses to start this way (an updater that insists) put it in your ~/.xprofile file instead; but the config is where desk-startup belongs.
Note: the xss-lock line is the sane way to wire i3lock to suspend: the screen locks itself before the laptop sleeps, so the password prompt is waiting when the lid opens.

06The bar, without tears

i3's built-in bar is driven by the bar { } block in the config and a status command that prints one line of text: i3status by default, i3blocks or polybar when you outgrow it.

bar {
    position top
    status_command i3status -c ~/.config/i3/i3status.conf
    tray_output primary
    font pango:JetBrainsMono Nerd Font 10
    separator_symbol " | "
    colors {
        background #0b110d
        statusline  #eef4f0
        separator   #9aaf9e
        focused_workspace  #9fe870 #1f3a24 #0b110d
        active_workspace   #4d6b52 #16241a #9aaf9e
        inactive_workspace #16241a #0b110d #5f7a63
        urgent_workspace   #ff9d5c #3a241f #0b110d
    }
}

And a minimal ~/.config/i3/i3status.conf to feed it:

general {
    interval = 5
    colors = true
}
order += "wireless _first_"
order += "ethernet _first_"
order += "battery all"
order += "load"
order += "time"

wireless _first_ { format_up = "%quality %essid" format_down = "" }
            
ethernet _first_ { format_up = "%ip" format_down = "" }
battery all { format = "%status %percentage %remaining" }
time { format = "%H:%M:%S" }
Note: i3blocks swaps the INI above for a set of little scripts named by block; anything that can print a line to stdout can be a block. That model, plus glyph fonts (next section), is where a laptop bar stops being a battery line and starts being a dashboard.

07Icons that render

i3 has no icon system of its own — the only “icons” on an i3 desk are glyphs in a font, used in three places: workspace names, status blocks, and per-window titles (for_window rules). The one prerequisite is a font that actually contains the glyphs:

$ apt install fonts-noto fonts-jetbrains-mono fonts-nerd-fonts-meta
# or the classic trinity: fonts-font-awesome, ttf-nerd-fonts-symbols, fonts-emojione
$ fc-list | grep -i "nerd\|awesome"   # confirm the family name you will type in configs

Then the font name (exact, from fc-list) becomes the config currency:

# everywhere in the WM — the exact family name from fc-list, not a guess:
font pango:JetBrainsMono Nerd Font 10

# workspace names carry their glyphs directly (Unicode code points):
set $ws1 "1:  term"
set $ws2 "2: "
bindsym $mod+1 workspace $ws1

# and per-app window titles can too:
for_window [class="Firefox"] title_format "2: %title"

Some of the most useful code points, from a Nerd Font / Font Awesome at their conventional places (your fc-list family decides how they look, not the config):

 house  laptop  battery  wifi  volume  code  globe  mail  tv  wrench
Note: both i3status and i3blocks print these glyphs straight out of shell scripts — the block script's stdout is the bar. UTF-8 in, bar out; no plugin layer, no daemon to restart (well: killall -USR1 i3blocks if you swap scripts live, or plain restart which everyone does instead).
Warn: if a glyph shows as a box, the family name in font pango:... does not match fc-list exactly — case, hyphen and last word all count (Nerd Font, not NerdFonts; Font Awesome 6 Free, not FontAwesome6). The fix is always in one place: the font line.

08Extra software that glues the desk

An i3 install is deliberately naked. The extras below are what turn it from a WM into a desk, with the role each one plays in one sentence:

ToolFillsOne-line install shape
rofidmenu's GTK-styled cousin: launcher, window switcher and much more with themesbindsym $mod+d exec rofi -show drun
picomCompositor: shadows, transparency, vsync, no screen tearingexec --no-startup-id picom -b -c
dunstNotification daemon for real (dbus) notificationsexec --no-startup-id dunst
feh / nitrogenWallpaper setter (feh is the scripted one)exec_always --no-startup-id feh --bg-fill ~/w.png
i3lockScreen lock, with colour or blur backgroundbindsym $mod+Shift+x exec i3lock -c 000000
maim / scrotScreenshots (selection / whole screen)bindsym Print exec maim -s ~/shot.png
network-manager-appletWifi/network in the tray + password promptsexec --no-startup-id nm-applet
pavucontrolPer-app volume when hotkeys are not enoughbindsym $mod+F11 exec pavucontrol
autorandrRemembers monitor layouts per physical arrangementexec --no-startup-id autorandr --change
xss-lockTies lock/suspend togetherexec --no-startup-id xss-lock -- i3lock -c 000000

The glue lines most desks end up wanting, exactly as written:

# volume keys, PulseAudio flavour (swap pactl for amixer on pure ALSA boxes)
bindsym XF86AudioRaiseVolume exec --no-startup-id pactl set-sink-volume @DEFAULT_SINK@ +5%
bindsym XF86AudioLowerVolume exec --no-startup-id pactl set-sink-volume @DEFAULT_SINK@ -5%
bindsym XF86AudioMute       exec --no-startup-id pactl set-sink-mute @DEFAULT_SINK@ toggle

# brightness (libinput-backed laptops use the sysfs path; check `ls /sys/class/backlight/`)
bindsym XF86MonBrightnessUp   exec --no-startup-id brightnessctl set +5%
bindsym XF86MonBrightnessDown exec --no-startup-id brightnessctl set 5%-
Note: keep one launcher only. People who bind dmenu on $mod+d and rofi on $mod+r end up searching two lists to find one app. Pick rofi (or pick nothing); one door is a desk, two doors is a puzzle.
Warn: picom with experimental_backends = true was the classic tearing fix, but with vsync mis-set it becomes the tear cause. If frames stutter after enabling any compositor, the first suspect is its vsync: honest options are vsync = true (OpenGL) or no — not both worlds at once.

09The fancy config, annotated

Here is the target: one dark, gap-using, rofi-launched, notification-served i3 with iconed workspaces and a themed bar — every value explained by the comment on its line. This is meant to be read top to bottom; every number is a real knob.

# ~/.config/i3/config — the fancy build, annotated by line
# --- identity ----------------------------------------------------------------
set $mod Mod4                                  # Super; swap to Mod1 if your desk prefers Alt
set $term xterm                                # every exec below uses $term: change once
set $menu rofi -show drun                      # theme lives in ~/.config/rofi/config.rasi
font pango:JetBrainsMono Nerd Font 10          # the one font line the whole WM reads

# --- the essential keys ------------------------------------------------------
bindsym $mod+Return exec $term
bindsym $mod+d exec $menu
bindsym $mod+Shift+q kill
bindsym $mod+Shift+c reload
bindsym $mod+Shift+r restart
bindsym $mod+Shift+e exec "i3-nagbar -t warning -m 'You pressed exit shortcut. Do you really want to exit i3?' -B 'Yes, exit i3' 'i3-msg exit'"

# --- focus, like arrows on tilers --------------------------------------------
bindsym $mod+j focus down
bindsym $mod+k focus up
bindsym $mod+h focus left
bindsym $mod+l focus right
# vim keys as well, free at the same bindings:
bindsym $mod+Shift+j move down
bindsym $mod+Shift+k move up
bindsym $mod+Shift+h move left
bindsym $mod+Shift+l move right

# --- splits and layouts ------------------------------------------------------
bindsym $mod+b split h
bindsym $mod+v split v
bindsym $mod+f fullscreen toggle
bindsym $mod+s layout stacking
bindsym $mod+w layout tabbed
bindsym $mod+e layout toggle split
bindsym $mod+space focus mode_toggle

# --- workspaces with glyphs, one block each ----------------------------------
set $ws1 "1: "   # term
set $ws2 "2: "   # web
set $ws3 "3: "   # code
set $ws4 "4: "   # mail
set $ws10 "10: " # settings
bindsym $mod+1 workspace $ws1
bindsym $mod+2 workspace $ws2
bindsym $mod+3 workspace $ws3
bindsym $mod+4 workspace $ws4
bindsym $mod+0 workspace $ws10
bindsym $mod+Shift+1 move container to workspace $ws1
bindsym $mod+Shift+2 move container to workspace $ws2

# --- windows and rules -------------------------------------------------------
gaps inner 10                                  # i3 ≥ 4.24 (gaps merge) or i3-gaps: the breathing quantity
gaps outer  4
smart_gaps on                                  # no gaps when a single window fills the screen
default_border pixel 2                         # 1-2px: WM chrome you barely see but always find
default_floating_border pixel 2
hide_edge_borders smart
focus_follows_mouse no                         # focus by keys is a decision, not a hover accident

Read it again with the annotations: nothing above is magic; it is all one concept per line. The full file for a working laptop also merges the sections below — bar block, startup execs, keyranges for volume — and lands around 120 lines; not 1200. The $menu variable exists to prove the launcher slot can take any command string — swap it and the desk keeps its keys.

Note: keep the file in git. An i3 config repo earns its keep faster than any dotfile: a bad weekend of tweak-fu is undone by git checkout ~/.config/i3/config, not by memory.

10Gaps, borders and transparency

The fancy layer has exactly three ingredients, two of which live in the config and one lives in a separate program:

# colours: focused vs. the world (borders + text pairs)
client.focused          #9fe870 #16241a #eef4f0 #9fe870   #9fe870
client.focused_inactive #4d6b52 #16241a #9aaf9e #4d6b52   #4d6b52
client.unfocused        #16241a #0b110d #5f7a63 #16241a   #16241a
client.urgent           #ffb38a #3a241f #0b110d #ffb38a   #ffb38a
client.placeholder      #16241a #0b110d #9aaf9e #16241a   #16241a

Each meaning is the same 5-part colour list: border · background · text · indicator · child_border. Setting client.focused is how a desk says “this is the window I am inside” visually — the strongest single upgrade after the font.

# transparency comes from picom's config, not from i3:
# ~/.config/picom/picom.conf
opacity-rule = [
  "95:class_g = 'URxvt'",
  "100:class_g = 'firefox'"
]
shadow = true
shadow-radius = 14
vsync = true              # the bool that rules tearing; one of its two values is honest
Warn: screens look smoother with transparency, but every transparent window costs a composite. On battery-starved hardware the optional picom is the correct answer; a desk is not a benchmark of compositors.

11The scratchpad and resize mode

The scratchpad is i3's best-kept secret: a floating window that can hide and pop on any workspace. One terminal on it, summoned anywhere, is the toy desktops tend to stop rebuilding around:

# make-move-toggle ritual, bound once, used forever
bindsym $mod+Shift+minus move scratchpad          # send the focused floating window to it
bindsym $mod+minus scratchpad show                # summon/cycle scratchpad windows
exec --no-startup-id $term -name scratch
for_window [instance="scratch"] move scratchpad, scratchpad show, resize set 90 ppt 35 ppt
for_window [instance="scratch"] floating enable, sticky enable, border pixel 2

And resize mode, i3's own modal gem — $mod+r turns arrow keys into resize keys until Escape:

mode "resize" {
    bindsym h resize shrink width 10 px or 5 ppt
    bindsym l resize grow   width 10 px or 5 ppt
    bindsym k resize shrink height 10 px or 5 ppt
    bindsym j resize grow   height 10 px or 5 ppt
    bindsym Return mode "default"
    bindsym Escape mode "default"
}
Note: the scratchpad and the for_window above together are the honest template for every such desk toy: a quake terminal, a music player, a chat pane. Resize once and the numbers persist; no xdotool scripts needed, and it keeps its size on any monitor.

12Hero vocabulary

The commands and one-liners that finish the road:

SpellWhat it does
i3-msg 'workspace 3'Drive the WM from a shell or script (same grammar as bindsyms).
i3-msg restartRestart without losing your session, from a terminal.
i3-msg 'layout tabbed'Change layout of current workspace remotely.
i3-nagbar -m "text" -B "btn" actionThat yellow warning bar; very useful in your own confirm dialogs.
i3-config-wizardThe declawed starter generator — rerun freely to inspect sane defaults.
i3-diagCollect all runtime info for bug reports (also fine for “why is my bar empty”).
i3-msg exec xtermStart apps through the WM, following startup-id focus rules.
i3-dump-logWhat went wrong, in order of when it did.
xevFind keysym/code numbers for binds.
i3-config-validatorLint the config before reload rejects it.

And the man pages that finish a hero: i3 (the user guide lives here), i3status, and i3's online user guide if your man page is minimal (or if you run the Wayland twin, the same guide is almost fully applicable under sway).

Note: and the meta-skill of the whole page: i3 rewards dictating the exact one line that fixes today's annoyance, then stopping. A 120-line config you can hold in your head beats a 1200-line config you barely survive.
