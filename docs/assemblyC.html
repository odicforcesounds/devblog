Assembly Then C — From Zero To Good Code

Path: asm first for truth (registers, stack, syscalls), then C for power. Linux x86-64, NASM + GCC + GDB. All code runnable on Debian.

0 — Setup (5 Minutes)

sudo apt update && sudo apt install -y nasm gcc make gdb strace ltrace manpages-dev
nasm -v; gcc --version; gdb --version
# docs: https://www.nasm.us/doc/ | https://gcc.gnu.org/onlinedocs/ | https://sourceware.org/gdb/documentation/
Learn to read errors. strace ./prog shows every syscall. gdb ./prog + layout regs shows truth.

1 — Assembly Mental Model (x86-64 Linux)

Registers: rax rbx rcx rdx rsi rdi rbp rsp r8-r15 (64-bit), e-kind low 32, ax/al low 16/8. Syscall ABI: rax=sysnr, rdi,rsi,rdx,r10,r8,r9=args, syscall. Syscall numbers: 0=read 1=write 60=exit (see ausyscall --dump, syscall table). Stack grows down, rsp top, call pushes return, ret pops.

2 — First Program: exit(42) + hello

; exit42.asm — nasm -felf64 exit42.asm && ld exit42.o -o exit42; ./exit42; echo $?
section .text
global _start
_start:
  mov rax, 60      ; sys_exit
  mov rdi, 42
  syscall
; hello.asm — nasm -felf64 hello.asm && ld hello.o -o hello
section .data
  msg db "hi from asm", 10
  len equ $ - msg
section .text
global _start
_start:
  mov rax, 1       ; sys_write(1, msg, len)
  mov rdi, 1
  mov rsi, msg
  mov rdx, len
  syscall
  mov rax, 60
  xor rdi, rdi
  syscall
Good asm tip #1: comment every syscall with prototype. #2: xor rdi,rdi > mov rdi,0 (shorter). #3: keep .data/.bss/.text separated.

3 — Functions, Stack, Calling C

Linux user calling convention (System V): args rdi,rsi,rdx,rcx,r8,r9, return rax, callee-save rbx,rbp,r12-r15. Align stack to 16 before call.

; strlen.asm callable from C
; nasm -felf64 strlen.asm; gcc main.c strlen.o -o main
section .text
global my_strlen
my_strlen:          ; rdi = char*
  xor rax, rax
.loop: cmp byte [rdi+rax], 0
  je .done
  inc rax
  jmp .loop
.done: ret
// main.c
#include <stdio.h>
size_t my_strlen(const char *s);
int main(){ printf("%zu\n", my_strlen("hello")); }
Good asm tips: frame with push rbp; mov rbp,rsp for debug, or frameless + .eh_frame for perf. Preserve callee-saved regs. Test with gdb breakpoints + info regs.

4 — C From Zero: Build Like Assembly With Types

sudo apt install -y build-essential clang cppcheck valgrind
gcc -std=c17 -Wall -Wextra -Werror -pedantic -g -O2 -o prog main.c
# strict + debug + sanitize while learning:
gcc -std=c17 -Wall -Wextra -g -O1 -fsanitize=address,undefined -o prog main.c
// good.c — start here
#include <stdio.h>
#include <stdlib.h>
int main(void){
  char buf[128];
  if(!fgets(buf, sizeof buf, stdin)) return 1;
  printf("you said: %s", buf);
  return 0;
}
Good C rule #1: -Wall -Wextra -Werror always. #2: init every variable. #3: check every return (malloc, fopen, read).

5 — Memory Done Right (Where C Beginners Die)

// BAD: char *p = malloc(10); strcpy(p, "too long string here..."); // overflow
// GOOD:
#include <string.h>
char *p = malloc(64);
if(!p) return 1;
snprintf(p, 64, "%s", input); // bounded
free(p); p = NULL;
char dst[32]; strncpy(dst, src, sizeof dst - 1); dst[sizeof dst - 1] = '\0';

Stack vs heap: char a[64] auto-freed, malloc manual. Strings always +1 for '\0'. Use Valgrind + ASan/UBSan until clean. Harden builds: -fstack-protector-strong -D_FORTIFY_SOURCE=2 -Wl,-z,RelRO,-z,Now -fPIE -pie, verify with checksec --file=./prog (checksec.sh).

6 — Good Code Habits (Asm → C Transfer)

1) Small functions, one job, early return. 2) const correctness, size_t for sizes, <stdint.h> fixed widths. 3) No magic numbers: #define BUF 128 / enum. 4) Errors as values: return -1/NULL + errno, print with perror/strerror. 5) Makefile + format (clang-format) + cppcheck in CI. 6) Comment why, not what — asm taught you that.

CC=gcc
CFLAGS=-std=c17 -Wall -Wextra -Werror -g -O2 -fstack-protector-strong -D_FORTIFY_SOURCE=2
all: prog
clean:; rm -f prog *.o

7 — Debug Like A Pro

gdb ./prog         # b main, r, n/s, p var, bt, layout regs/src
strace -f ./prog   # syscalls; ltrace ./prog  # lib calls
valgrind --leak-check=full ./prog
gcc -g -fsanitize=address,undefined ... && ./prog  # fastest bug finder
Reproduce tiny, then fix. One bug per commit. Write the failing test first.

Asm shows cost. C spends it wisely. Write small, check all, sanitize always — good code is boring code that never surprises at 3am.
