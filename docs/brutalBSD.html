OpenBSD is the system I recommend when somebody asks me which one to read before which one to install. Not because it is easy, but because the documentation is honest. A manual that explains the whole system in the order in which the system boots is worth more than a thousand tutorials written by people who copied each other.

This page is a tribute and a set of notes. It is not a guide, and it will not replace man afterboot. It exists because the first hour with a new system decides whether the person stays, and that hour is almost entirely made of reading.

Being paranoid about security can be a little bit Evil, but if you find that others are trying to Break it, there is no Evil on it

The question is: "If you wish to break some system, which best position you should be in? Inside or Outside?"

OpenBSD ask some key tips for new users, like me or like you. Always use the more option and append the number of the email, to read the emails you will get on OpenBSD system by default. Is a Golden tip. Else you will only be able to read the last lines of your emails. For the first Welcome email, you lose all the necessary details to start, while you have access to all necessary details to participate, by sending your hw.sensors values.

In case you use the correct option to read your emails, you figure out that OpenBSD creates a map of necessary steps and readings to start configuring the system, much better than any other BSD or Linux System.

Their Welcome email, start to explain the very basics of using the man pages in the default Kshell and ask the user to type man afterboot, to start reading the first book, of many other books that are in the same OpenLibrary, which is always Open, at any hour of any day and any night. Then it gives an example on how to install new packages using their Binary package manager, some extra notes and we start reading book after book. Sometimes in a exaustive experience, since they always link the necessary Books that are related to the one we are reading. All makes sense and there is no Hidden or secret knowledge, like what happen with FreeBSD man pages, when I was stucked on creating a disk file to use the VMs. In the other hand, OpenBSD vm manual pages, have the option to create those disk-files and all steps that are needed are explained the best they can, since we have access to the /etc/examples/* files that are not empty.

By reading the afterboot book, you can know how everything is connected, how everything should work, what limitations exist, what security problems can happen, what can you do to prevent them, how to configure each service they have that are always Open, at any time of day or night.

The three commands that matter in the first hour

Every new installation is a small panic. These three, in this order, replace the panic with a plan:

  • man afterboot — the map. Read it once, slowly, with the machine beside you.
  • man security — the list of what is already protected and what is still your responsibility.
  • syspatch — the reminder that documentation does not patch a kernel. Run it, and run it again next week.

What "brutal" actually means

People call the OpenBSD documentation brutal because it does not try to be friendly. It does not congratulate you for opening a terminal. It does not produce a video. It gives you a sentence, precisely written, that stays true for the next ten years, and it assumes that you are capable of reading it.

That is not brutality, that is respect. The brutal thing is the other model: a documentation that changes every six months, hides the important paragraph behind a newsletter form, and calls the reader a "user" while treating him like a lead.

Where the philosophy touches the hardware

The same idea appears in the code. A small base system, a firewall enabled by default, privilege separation everywhere, and a maintainer culture that prefers removing a feature to auditing it forever. You can disagree with the choices and still learn from the method: decide what the system must do, remove everything else, and write down the reason.

My only real complaint is the one I have repeated many times in this blog: NVIDIA. Most of my machines carry one, and OpenBSD does not support the proprietary driver, so the tribute is written from a laptop that boots something else. A system can be excellent and still not be the system for your hardware. That is a fact about my desk, not about the project.

Reading before installing

If this page convinces you of one thing, let it be the order: read first, install second. The library is already on the machine, waiting behind a command, and it is the only library I know that opens at three in the morning, without a connection, and without asking who you are.
