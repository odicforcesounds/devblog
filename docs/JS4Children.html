01

Think like a coder

Programming is giving a computer clear instructions to solve a problem.

A computer is very fast, but it does exactly what its instructions say—not what you meant. Coding is the art of turning a big idea into tiny, unambiguous steps.

🧩

1. Understand

What should happen? What information do you have? What result do you want?

🪜

2. Break it down

Split the job into smaller steps. A recipe is an algorithm: a list of steps in order.

🛠️

3. Write and test

Tell JavaScript the steps. Try normal, tiny, huge, and surprising inputs.

🔎

4. Improve

Read what happened, fix one thing at a time, and make the code easier to understand.

Algorithm before code: packing a school bag

  1. Look at tomorrow’s timetable.
  2. For each class, add its books and supplies.
  3. If it is sports day, add sports clothes.
  4. Check the list, then close the bag.

Notice the words for each and if? They become loops and decisions in code. Before typing, explain your solution in ordinary words or draw a flowchart.

Vocabulary: An algorithm is a repeatable set of steps. A bug is a problem in a program. Debugging means finding and fixing that problem. Bugs are normal—even experts make them.
02

Your first JavaScript

JavaScript (often shortened to JS) is a programming language that makes things happen.

Try the browser console: in most desktop browsers, open Developer Tools and choose Console. Type a line and press Enter. On a phone or tablet, use an online coding environment with a trusted adult. The console is a scratchpad; it is not the same as a text message box.

console.log("Hello, world!");
console.log(2 + 3);

console.log() prints a value so you can inspect it. Text goes inside quotes; numbers do not. The semicolon marks the end of a statement. JavaScript often allows you to leave it out, but using it consistently can make code easier to scan.

JavaScript is not Java

Despite their similar names, Java and JavaScript are different languages, like a car and a carpet are different even though both start with “car”. This guide teaches JavaScript.

Try it: Change the greeting to your name. Then print the answer to 12 * 4. Predict the result before pressing Enter.
03

Values and variables

Values are the information your program works with. Variables give useful names to information.

Three useful ways to create a variable

const learner = "Mina";   // This name should keep pointing to this value
let score = 0;             // This value can be updated
score = score + 10;
console.log(learner, score);
KindUse it when…Example
constYou won’t assign a different value to this variable.const homePlanet = "Earth";
letYou need to assign a new value later.let lives = 3; lives = 2;
varMostly in older code; learn to recognize it, but usually prefer const or let.var oldStyle = true;

A variable is like a labeled box, but const means the label cannot be pointed at a different value. If a const contains an object or array, the contents may still be changed; we will see why in Lesson 09.

Common value types

const username = "Kai";       // string: text
const age = 12;                // number: includes whole and decimal numbers
const isReady = true;          // boolean: true or false
const score = null;             // intentionally no value
let nextMove;                   // undefined: no value assigned yet
const huge = 12345678901234567890n; // bigint: very large whole number

JavaScript also has symbol, used for special unique identifiers. You usually won’t need it at first. Check a value’s type with typeof—but be aware of one old JavaScript surprise: typeof null says "object".

console.log(typeof "hello"); // "string"
console.log(typeof 42);      // "number"
console.log(typeof true);    // "boolean"

Text and templates

const hero = "Nova";
const level = 4;
const message = `${hero} reached level ${level}!`;
console.log(message);

Backticks create a template literal. The ${...} parts insert JavaScript values into the text.

Changing values and naming

let coins = 5;
coins = coins + 2; // now 7
coins += 3;        // now 10
coins++;           // now 11

Use names that explain what a value means: minutesLeft is clearer than x. JavaScript names are case-sensitive: score and Score are different.

04

Math and comparisons

Computers are great at arithmetic, counting, and checking rules.

OperatorMeaningExample result
+Add, or join strings7 + 2 → 9
-Subtract7 - 2 → 5
*Multiply7 * 2 → 14
/Divide7 / 2 → 3.5
%Remainder after division7 % 2 → 1
**Power3 ** 2 → 9

Order matters: multiplication and division happen before addition and subtraction. Use parentheses to make your meaning obvious: (2 + 3) * 4.

Equality and comparisons

console.log(5 > 3);       // true
console.log(5 === 5);     // true: same value and type
console.log(5 === "5");   // false: number is not text
console.log(5 !== 4);     // true: not equal

Prefer === and !== for equality. The older == can convert types in surprising ways, so beginners should avoid it until they understand coercion. Comparisons include <, >, <=, >=.

Logic: combine yes/no answers

const hasTicket = true;
const isOldEnough = true;
console.log(hasTicket && isOldEnough); // AND: both must be true
console.log(hasTicket || isOldEnough); // OR: either can be true
console.log(!hasTicket);               // NOT: flips true/false

Think of logic like rules for a game. && means “and”, || means “or”, and ! means “not”. JavaScript’s && and || can return one of their original values, not just true or false; that shortcut is useful later.

Averages and rounding

const points = [8, 10, 6];
const total = points[0] + points[1] + points[2];
const average = total / points.length;
console.log(Math.round(average)); // 8

Computers use floating-point numbers, so some decimal calculations are tiny bit inexact (for example, 0.1 + 0.2). For money, store cents as whole numbers where possible: 199 cents is $1.99.

05

Make decisions

Programs choose different actions with conditions.

const temperature = 18;
if (temperature >= 25) {
  console.log("Warm day!");
} else if (temperature >= 15) {
  console.log("A light jacket might help.");
} else {
  console.log("Bundle up!");
}

JavaScript checks conditions from top to bottom and runs the first matching branch. Curly braces { } hold the instructions in a block. Indentation is not required by the computer, but it helps people see the structure.

Switch for a list of exact choices

const day = "Saturday";
switch (day) {
  case "Saturday":
  case "Sunday":
    console.log("Weekend!");
    break;
  default:
    console.log("School day");
}

break stops the switch from continuing into the next case. For many simple choices, if / else is easier to read.

Truthy and falsy (a later-level idea)

Conditions can use values other than booleans. Values such as 0, "", null, undefined, and NaN act like false in a condition; most other values act like true. When learning, explicit checks can be clearer.

const nickname = "";
if (nickname) {
  console.log(`Hi, ${nickname}!`);
} else {
  console.log("No nickname yet.");
}
06

Repeat with loops

Loops save you from writing the same instruction over and over.

Count with a for loop

for (let round = 1; round <= 3; round++) {
  console.log(`Round ${round}`);
}

Read it as: start at 1; keep going while the condition is true; add 1 after each turn. The three parts are separated by semicolons. Watch the condition carefully: a mistake can cause an endless loop.

Repeat while something is true

let energy = 3;
while (energy > 0) {
  console.log("Play!");
  energy--;
}

A while loop checks before each turn. Make sure each turn can eventually make its condition false. Otherwise it may never stop.

Loop through a collection

const snacks = ["apple", "toast", "yogurt"];
for (const snack of snacks) {
  console.log(`Pack: ${snack}`);
}

for...of is a friendly way to visit each item in an array or other iterable. Use break to stop early or continue to skip to the next turn.

Loop safety: If a page freezes, a loop might be running forever. Stop the page or close its tab. In your own code, double-check the starting value, stopping condition, and update.
07

Functions: reusable recipes

A function groups instructions under a name. Give it inputs; it can return an output.

function greet(name) {
  return `Hello, ${name}!`;
}

const greeting = greet("Sam");
console.log(greeting);

name is a parameter—a named input. "Sam" is an argument—the actual value we pass in. return sends a result back. A function can also do a task without returning a useful value.

Function expressions and arrow functions

const double = function (number) {
  return number * 2;
};

const triple = (number) => {
  return number * 3;
};

const quadruple = number => number * 4;
console.log(double(5), triple(5), quadruple(5));

Arrow functions are a shorter way to write many functions. If the arrow function has one expression, parentheses and braces can be shortened; that expression is returned automatically. Use braces plus return when the steps need more room.

Default inputs and input checking

function welcome(name = "friend") {
  return `Welcome, ${name}!`;
}

function add(a, b) {
  if (typeof a !== "number" || typeof b !== "number") {
    return "Please give me two numbers.";
  }
  return a + b;
}
console.log(welcome());
console.log(add(4, 6));

Keep each function focused: one clear job, a helpful name, and predictable inputs and outputs. This makes it easier to test and reuse.

08

Arrays: lists of things

Use an array when you have an ordered list of values.

const colors = ["teal", "gold", "violet"];
console.log(colors[0]); // "teal"; the first position is 0
console.log(colors.length); // 3
colors.push("coral"); // add to the end
colors.pop();          // remove the last item

Array positions are called indexes and start at zero. The last valid index is array.length - 1. A const array can still have items added or removed: the variable still points at the same array.

Useful array tools

const numbers = [2, 4, 6, 8];
const doubled = numbers.map(number => number * 2);
const bigOnes = numbers.filter(number => number >= 6);
const found = numbers.find(number => number === 4);
const total = numbers.reduce((sum, number) => sum + number, 0);
console.log(doubled, bigOnes, found, total);
ToolWhat it doesChanges original?
mapMake a new array by changing each itemNo
filterMake a new array with items that pass a testNo
findGet the first item that passes a testNo
reduceCombine items into one answer, such as a totalNo
sortReorder items (by default, as text)Yes

For numbers, sort with a comparison rule: numbers.slice().sort((a, b) => a - b). slice() makes a copy first, so the original list stays in its old order.

Arrays of arrays

const seats = [
  ["A1", "A2"],
  ["B1", "B2"]
];
console.log(seats[1][0]); // "B1"
09

Objects: describe a thing

An object groups named pieces of information, called properties.

const pet = {
  name: "Pixel",
  kind: "cat",
  age: 3,
  isHungry: false
};
console.log(pet.name);       // dot notation
console.log(pet["kind"]);   // bracket notation
pet.isHungry = true;

Objects are useful when values belong together. A property’s name is its key. Use dot notation when you know the key; use brackets when you have the key in a variable or the name has special characters.

Methods: functions that belong to objects

const player = {
  name: "Rin",
  score: 0,
  earn(points) {
    this.score += points;
    return `${this.name} now has ${this.score} points.`;
  }
};
console.log(player.earn(10));

In this method, this refers to the object that called it. this behaves differently in some kinds of functions; when that feels confusing, use a named parameter or read about arrow-function this rules later.

Destructuring and spread

const { name, score } = player; // take properties into variables
const upgradedPlayer = { ...player, level: 2 }; // copy + add
const newColors = [...["blue", "green"], "gold"]; // copy + add
Objects are shared by reference: Assigning const otherPet = pet does not make a separate pet. Both names point to the same object. Spreading with { ...pet } makes a shallow copy: nested objects still need more care.

JSON: a text format for data

const saved = JSON.stringify(pet); // object → JSON text
const restored = JSON.parse(saved); // JSON text → object

JSON looks similar to JavaScript objects but is stricter: keys and text must use double quotes, and JSON cannot contain functions or undefined. Only parse JSON you trust or handle parse errors.

10

Scope, errors, and debugging

Scope is where a name can be used. Debugging is careful detective work.

const outside = "I can be used below";
function showMessage() {
  const inside = "I only exist in this function";
  console.log(outside, inside);
}
showMessage();
// console.log(inside); // Error: inside is out of scope

let and const are block-scoped: they live inside the nearest pair of braces where they were declared. Prefer small scopes and avoid reusing the same name for different ideas.

Three kinds of problems

  • Syntax error: the code is not written in a way JavaScript understands (perhaps a missing quote or bracket).
  • Runtime error: the code starts, but something goes wrong while it runs.
  • Logic bug: it runs, but gives the wrong answer.

A calm debugging checklist

  1. Read the whole error message and note the line number.
  2. Check spelling, quote marks, brackets, and capitalization.
  3. Print intermediate values with console.log().
  4. Test the smallest example that shows the problem.
  5. Change one thing, run again, and see whether it helped.
  6. Ask: what did I expect, what happened, and what is the first place they differ?
function average(a, b) {
  const total = a + b;
  console.log("Checking total:", total); // temporary detective clue
  return total / 2;
}
console.log(average(8, 10));

Browser Developer Tools offer a debugger. A breakpoint pauses the program on a chosen line so you can inspect variables one step at a time.

11

JavaScript on the web: the DOM

HTML describes a page, CSS styles it, and JavaScript can respond and update it.

HTML

The page structure: headings, buttons, paragraphs, images.

CSS

The appearance: colors, layout, spacing, motion.

JavaScript

The behavior: reacting, calculating, updating, communicating.

The DOM (Document Object Model) is the browser’s live, tree-shaped representation of the page. JavaScript can find an element and change it.

// Example HTML: <h1 id="title">Welcome</h1>
const heading = document.querySelector("#title");
heading.textContent = "Hello from JavaScript!";
heading.classList.add("highlight");

querySelector finds the first element matching a CSS selector. textContent sets plain text safely. The DOM code works in a browser page, not in Node.js or this course’s isolated playground.

Create elements instead of building unsafe HTML strings

const item = document.createElement("li");
item.textContent = "Learn a new skill";
document.querySelector("ul").append(item);

When inserting text from people, use textContent rather than innerHTML. Treating untrusted text as HTML can create security problems.

Load your page script

<script src="app.js" defer></script>

Put this in the HTML page. defer lets the browser read the page before running the external script. You can also use <script type="module" src="app.js"> when using JavaScript modules.

12

Events and interaction

Events tell your code that something happened: a click, key press, or form submission.

const button = document.querySelector("#helloButton");
const message = document.querySelector("#message");
button.addEventListener("click", () => {
  message.textContent = "You clicked the button!";
});

This is called an event listener. It waits for a click, then runs the callback function. Keep JavaScript behavior in JavaScript rather than putting it in an HTML attribute.

Handle a form

const form = document.querySelector("#nameForm");
form.addEventListener("submit", event => {
  event.preventDefault(); // don't reload the page
  const name = new FormData(form).get("name");
  document.querySelector("#greeting").textContent = `Hi, ${name}!`;
});

Forms are better than a lone textbox for real input: pressing Enter works, and the browser has helpful accessibility behavior. Always validate input; browser-side checks improve usability but are not a security boundary.

Events travel through the page

Events often bubble from the target element up through its parents. This lets a parent listen for clicks on many child buttons (event delegation). Learn this once you are comfortable with individual listeners.

13

Waiting, timers, and async code

Some tasks take time: a timer, loading a picture, or asking a server for information.

JavaScript usually runs one piece of code at a time on its main thread. If it waited by freezing every time it fetched data, websites would feel stuck. Asynchronous tools let it keep responding while work completes.

Promise: a result that will arrive later

console.log("First");
setTimeout(() => {
  console.log("Later (after about 1 second)");
}, 1000);
console.log("This prints before Later");

setTimeout asks the browser (or Node.js) to call a function after at least the requested delay; it does not pause the whole program. A Promise represents work that may succeed or fail in the future.

async and await: read asynchronous steps clearly

async function getJoke() {
  try {
    const response = await fetch("https://example.com/joke");
    if (!response.ok) throw new Error("The server had a problem");
    const data = await response.json();
    console.log(data);
  } catch (error) {
    console.error("Could not load the joke:", error.message);
  }
}
getJoke();

This is a shape-of-the-code example; that URL is not a real joke API. fetch asks a server for data. await pauses this async function until the Promise settles, without freezing the entire page. Always handle network errors and check response.ok: a 404 response does not automatically reject the Promise.

Remember: A Promise can be pending, fulfilled (success), or rejected (failure). try / catch gives you a place to handle many errors from awaited work.
14

Organize bigger code

Modules let separate files share selected functions and values.

// mathTools.js
export function square(number) {
  return number * number;
}

// app.js
import { square } from "./mathTools.js";
console.log(square(6));

Export what another file needs; import it where it is used. In a browser, load the entry file with <script type="module" src="app.js">. Local module files are usually served over a local web server, rather than opened as a file:// URL.

Classes (a pattern for creating similar objects)

class Robot {
  constructor(name, energy = 100) {
    this.name = name;
    this.energy = energy;
  }
  speak() {
    return `${this.name} says beep!`;
  }
}
const helper = new Robot("Milo");
console.log(helper.speak());

A class is a blueprint for objects with similar data and behavior. JavaScript also has prototypes underneath; you can build many programs with plain objects and functions before classes are needed. Don’t use classes just because they seem fancy—choose the simplest design that fits.

Choose clear, small pieces

Split files by purpose (for example, game rules, screen updates, and saved data). Prefer readable names and simple functions. Avoid building a huge framework for a small project.

JavaScript and operating systems

The same language can run in different places. The environment supplies different tools.

Where it runsCommon jobsTypical tools
BrowserWeb pages, games, formsdocument, DOM events, fetch
Node.js runtimeCommand-line tools, servers, automationprocess, files, network APIs
Other JavaScript runtimesApps and server tasks, depending on runtimeTools vary; check that runtime’s documentation

Node.js is a program that runs JavaScript outside the browser. It is often used for developer tools, web servers, and scripts. Browser JavaScript normally cannot read your computer’s files whenever it wants; Node has file-system abilities because it runs with different permissions.

Example: a small Node command-line script

// greet.js — run with: node greet.js Nova
const name = process.argv[2] ?? "friend";
console.log(`Hello, ${name}!`);

process.argv contains command-line arguments. To try this, install Node.js only with a trusted adult’s help, then run the command in a terminal from the folder containing the file. Don’t paste unfamiliar commands into a terminal.

Example: reading a file with Node.js

// Node.js example (not browser code)
import { readFile } from "node:fs/promises";

try {
  const words = await readFile("notes.txt", "utf8");
  console.log(words);
} catch (error) {
  console.error("Could not read notes.txt:", error.message);
}

Modern Node.js supports top-level await in ES modules. Depending on how your project is set up, you may need a package.json with "type": "module", or use a module file extension that Node recognizes. File paths are relative to the process’s current working folder.

Servers: a browser can ask Node for a page

// A tiny Node HTTP server (modern Node.js)
import { createServer } from "node:http";

const server = createServer((request, response) => {
  response.writeHead(200, { "content-type": "text/plain; charset=utf-8" });
  response.end("Hello from a JavaScript server!\n");
});
server.listen(3000, "127.0.0.1", () => {
  console.log("Open http://127.0.0.1:3000");
});

This example is for learning on your own computer. A server listens for requests. The browser sends a request, the server sends a response. Real servers need thoughtful error handling, security, and deployment setup.

Operating system superpower = responsibility. Scripts can rename or delete files, start programs, and use the network. Start with a practice folder and harmless files. Never run an unknown script, share passwords or private keys, or use system commands you don’t understand. Ask an adult before installing tools or changing computer settings.
16

Safety and good habits

Good programmers care about people, privacy, and readable code.

Readable

Use clear names, consistent indentation, and small functions.

Careful

Check inputs. Show a useful message when something fails.

Private

Never put passwords or secret keys in a web page or public code.

Respectful

Ask before collecting personal information, sharing photos, or contacting people.

Small habits that make a big difference

  • Use const by default; choose let when the name must be reassigned.
  • Use === for equality and give conditions clear names.
  • Keep code DRY (“Don’t Repeat Yourself”), but don’t over-complicate simple code.
  • Test both ordinary and unusual inputs, including empty values.
  • Use version history such as Git only after learning with a trusted guide; it helps you revisit changes.
  • Give credit for code, images, and ideas you reuse. Check the license and ask permission when needed.

Security note: Browser code is visible to visitors. Never hide a secret key in JavaScript sent to the browser. Validate and authorize important actions on a trusted server too.

17

Projects: turn skills into creations

Pick a small idea, build a tiny first version, and keep adding features.

🧮 Level 1: Number machine

Ask for two numbers, add them, and show the result. Then add subtract, multiply, and divide buttons. Check for dividing by zero.

🎲 Level 2: Guess the number

Choose a random secret number. Let the player guess, say “higher” or “lower”, count attempts, and stop when they win.

✅ Level 3: To-do list

Use an array of task objects. Add a form, mark tasks done, remove tasks, and show how many remain.

🕹️ Level 4: Mini browser game

Make a character move with keyboard buttons. Add points, boundaries, and a restart button. Keep the rules separate from the page drawing.

🌦️ Level 5: Data explorer

Start with a small list of pretend weather readings. Calculate the average and display the warmest day. Later, learn safe APIs and async requests.

🧰 Level 6: Node helper

Write a harmless command-line program that greets the user or counts lines in a practice text file. Use only a folder made for the project.

Plan a project in six steps

  1. Describe the goal in one sentence.
  2. List the smallest features needed for version one.
  3. Sketch what the user sees and what data you need.
  4. Build one feature and test it before adding another.
  5. Try edge cases: empty list, zero, long text, repeated click.
  6. Ask a friend to try it; note where they get confused.

What will this print?

console.log(pets[1]);

A practical learning path

  1. Get comfortable with values, variables, conditions, loops, and functions.
  2. Practice arrays and objects by modeling things you care about.
  3. Make a web page respond to a click and a form submission.
  4. Learn debugging and test your assumptions.
  5. Explore promises and async / await.
  6. Try modules and then Node.js with adult guidance.
  7. Build projects you enjoy. Your curiosity is the best curriculum.
You are already thinking like a programmer whenever you break a tricky problem into steps, make a guess, test it, and learn from the result. Keep going—you do not have to know everything to make something cool.
