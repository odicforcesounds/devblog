A minha experiência com Linux é grande, mas com o FreeBSD são poucos meses. Estou a começar a Amar os sistemas BSD; o Free é mais rápido do que o Open, em termos de uso de Memória, e o Open é mais estável do que o Free.

Usar BSD, Open ou Free, é a experiência mais próxima de UNIX que alguém pode ter; e, embora normalmente gostemos de instalar um Ambiente de Trabalho, é sempre bom olhar para a base para ficar familiarizado com as aplicações por omissão. Porque, na minha experiência, o BSD Net falha sempre a instalação — não faço ideia porquê — mas gosto da versão Ghost. Para um ambiente de trabalho, o GhostBSD é estável e usa quase as mesmas funcionalidades que se encontram noutros sistemas BSD.

Usar FreeBSD para gerir um Servidor é, de facto, o objetivo principal e a melhor solução que já usei. Com FreeBSD é possível virtualizar muitas máquinas sem gastar demasiados recursos de hardware, como seria preciso se o objetivo fosse para alguma empresa. Mas, neste caso, sou só eu e o meu computador, que não é o melhor mas não é o pior. Consigo gerir entre 3 e 4 Máquinas Virtuais, com Jails ou até emulando Linux com a VM, ou com outras alternativas conhecidas como QEMU, KVM e XEN. Não sei nada de XEN e tenho pouca experiência com QEMU e KVM.

Entre Jails Finas e Jails Grossas, gosto das últimas, porque melhoram a Segurança das Jails sem dependerem do Anfitrião Principal. Preparar Jails à mão é um pouco complexo, porque os blog posts nem sempre contam alguns detalhes necessários para configurar tudo corretamente. Por exemplo, o driver vtnet, que precisa de ter uma Jail dedicada a fazer ponte para diferentes jails/anfitriões, tem de ser acrescentado ao ficheiro loader.conf antes de o tentares usar. O manual do FreeBSD não descreve funcionalidades avançadas como o driver vtnet e os nomes das placas de rede, etc. Por isso, usar ferramentas como o pot, cBSD, Bastille e outras pode simplificar a administração de Jails, incluindo o Bhyve.

Pessoalmente, quanto mais entendo de FreeBSD, mais gosto da experiência UNIX, ou seja, não preciso de instalar nenhuma interface gráfica nem de gastar mais recursos de hardware. Mantenho tudo o mais simples possível, para o tornar rápido e mínimo. Usar Tmux é a melhor forma de gerir muitos terminais no mesmo lugar. Cada separador pode ter o seu nome, para os distinguir. Como o FreeBSD usa sh como shell por omissão, podes querer criar os teus próprios scripts de Vim ou instalar o Bash para usar scripts externos que normalmente pedem Bash, usado em quase todas as distros Linux.

A listar os comandos e manuais básicos:
man rc, man rc.conf, man syslogd, man tunefs, man restore, man pf.conf, man jail, man jail.conf, man vm, man rctl, man sysctl, man top, man vmstat, man ifconfig, man route, man sockstat, man netstat, man dump, man tcpdump

Naturalmente há muitos mais, mas com estes já podes começar a criar o teu Servidor. É preciso alguma leitura, porque as coisas mudam e, normalmente, os blog posts podem estar velhos e por isso ser inúteis e propensos a erros. Por exemplo, Peter Hansteen escreveu um manual sobre o pf, onde podes confirmar várias opções que encontras na web; algumas estão desatualizadas, e sistemas BSD diferentes podem mudar a sintaxe e as opções por omissão. O autor do srobb.net escreveu outra versão sobre esta fantástica solução de Firewall, para gerir redirecionamentos e bloquear tráfego indesejado, de ligações inbound a outbound NAT, de forma mais fácil.

O maior problema do FreeBSD é o Uso de Memória, quando se usa zfs. O ZFS é extremamente útil e fácil de manter, mas custa algum uso extra de memória. Outra questão é que a Memória não é libertada depois de usada e, se não reiniciarmos a máquina, em alguns casos isso pode sobrecarregar o sistema e parti-lo. Só nesse aspeto, comparando com todas as distros que já testei, o Gentoo [FOI] a melhor distro Linux de há uns anos para gerir Memória. Agora já não sei, porque mudaram muito, e tenho de admitir que falho sempre a instalação do Gentoo. E sejamos honestos: ter de lidar com todos os problemas de pacotes que são muito comuns no Gentoo é gastar tempo numa coisa que (todas as outras distros fazem, porque se preocupam em apresentar aos seus utilizadores uma instalação por omissão que FUNCIONA!!!). Sim. Do OpenSuse ao Debian, Arch, Slackware, OpenBSD, FreeBSD, Fedora, CentOS e até Pentoo criam um sistema de instalação que funciona. Pela Documentação, o Arch Linux Wiki e o Manual do FreeBSD são os melhores de cada um, embora não possa ignorar a simplicidade e a documentação do OpenBSD, mesmo que a interface do site seja puro HTML com algum CSS claro. Não como este site usa, com imensas cores a marcar as diferentes palavras coladas.

My experience with Linux is big, while with FreeBSD have few months. I am starting to Love BSD systems, while the Free is more fast than the Open, in terms of Memory usage, the Open is more stable than the Free

Using BSD, being Open or Free is the most closer UNIX experience that someone can have, while normally we like to install a Desktop, is always good to look into the basis to be familiarized with the default applications. Because in my experience the Net BSD system always fail to install, I have no clue about it, but I like the Ghost version of it. For a Desktop GhostBSD is stable and use almost the same features that anyone can find on other BSD systems.

Using FreeBSD to manage a Server is in fact the main gold and the best solution I ever used. By using FreeBSD virtualization of many machines is possible, without using too much hardware resources, as it would be needed if this objective was for some company. But in this case, is just me an my computer, that is not the best but is not the worst. I can manage between 3 and 4 Virtual Machines, using Jails or even emulating Linux using the VM or using other known alternatives like QEMU , KVM and XEN. I know nothing about XEN and have little experience with QEMU and KVM.

Between Thin Jails and Thick Jails, I like the last ones since they improve Security of Jails, without depending on the Main Host. Preparing Jails by hand is a little bit complex, because blog posts don't always tell you some details that are needed to setup the configurations correctly. Like for example, the vtnet driver that need to have a dedicated Jail making bridge to different jails/hosts, need to be added to the loader.conf file before trying to use it. FreeBSD handbook don't describe advanced features like the vtnet driver and the name of network cards, etc. Therefor, using tools like pot, cBSD, Bastille and others, can simplify Jails administration, including the Bhyve.

Personally, the more I understand about FreeBSD, the more I like the UNIX experience, meaning that I don't need to install any Graphical interface, to spend more hardware resources. I keep it as simple as is possible, to make it fast and minimal. Using Tmux is the best way to manage many terminal in the same place. Each Tab can have it's own name to differenciate them. Since FreeBSD use sh as the default shell, you may wish to create your own Vim scripts or install Bash to use external scripts that normally ask Bash used on almost Linux Distros.

Listing the basic commands and manuals:
man rc, man rc.conf, man syslogd, man tunefs, man restore, man pf.conf, man jail, man jail.conf, man vm, man rctl, man sysctl, man top, man vmstat, man ifconfig, man route, man sockstat, man netstat, man dump, man tcpdump

Naturally there are many more, but with this ones you can start creating your Server. Some reading is necessary, because changes can happen and normally blog posts can be old and therefor useless and error-prone. For example, Peter Hansteen wrote a manual about pf, where you can check several options that you can find on the web, while some of them are old, different BSD systems can change their default syntax and options. The author of srobb.net wrote another version about this awesome Firewall solution, to manage redirection and block unwanted traffic, from inbound to outbound NAT connections in a easier way.

The biggest problem of FreeBSD is Memory Usage, when using zfs. ZFS is damn useful and easy to maintain, but it cost some extra memory usage. Another issue is that Memory is not released after being used and in case we don't reboot the machine, for some cases, can overload the system and break/crash. Only in that aspect, comparing to all distros that I already test, Gentoo [WAS] the best Linux Distro years ago to manage Memory. Right now I don't know because they change a lot and I must admit, I always fail to install Gentoo. And Lets face it, having to deal with all package problems that are very common on Gentoo, is spending time in something that (all other distros do, since they care to present to their users, a working default installation, that WORKS!!!). Yes. From OpenSuse to Debian, Arch, Slackware, OpenBSD, FreeBSD, Fedora, CentOS and even Pentoo create a installation system that works. Based on the Documentation, Arch Linux Wiki and FreeBSD Handbook are the best docs for each, while I cannot ignore OpenBSD simplicity and documentation, even if website UI is pure HTML with some clear CSS.
