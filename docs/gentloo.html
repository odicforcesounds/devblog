Porque usar Links para instalar Gentoo esconde Avisos e Alertas

Na última review do Gentoo Linux descrevi como me confundi a instalar o Gentoo a partir da ISO Minimal. Depois deparei-me com alguns problemas: ter Systemd e OpenRC na mesma página, enquanto os Avisos não são mostrados como avisos, e por isso alguns detalhes não ficam claros o suficiente para mim.

Comecei então a ler a versão Alpha da Full Installation da documentação deles e percebo que os avisos estavam lá, e a informação sobre Systemd também. Neste ponto, já não quero seguir o Handbook do Gentoo, mas construir o meu próprio, tomando notas das notas deles. É a diferença entre usar o Firefox ou os navegadores de terminal w3m/links/elinks/lynx.

Por exemplo, eu estava a queixar-me do uso de memória em tempo de compilação, mas eles têm um Aviso a dizer que usar MAKEOPTS="-j2" é a forma mais segura de não usar toda a memória da máquina, que pode ficar sem memória se usarmos um número maior de CPUs: ao compilar algo como Rust ou GCC, a máquina vai abaixo e é preciso forçar o encerramento. «É uma competência de instalação que mata a instalação.» :D

Outra curiosidade é o Sakaki (um utilizador japonês que partilha o seu processo de instalação), dedicado a um possível Handbook exclusivo para Systemd com muitas melhorias se o compararmos com o manual oficial e padrão do Gentoo, enquanto o primeiro aviso no topo da página nos diz para não seguir esse guia. Então pergunto-me: porque é que esse guia ainda está lá? Não sei, mas se assumo que alguns detalhes estão «desactualizados», ou os actualizamos ou movemos o artigo desactualizado para a pasta «Archive». Quer dizer, eu escondia-o, para não confundir os utilizadores que usam «Links» para ler as páginas do manual disponíveis nos sites do Gentoo.

É apenas uma perspectiva de novato, eles fazem o que quiserem. Mas sim, podiam gastar alguns minutos a actualizar a documentação, ou alguns segundos a mover esse artigo para uma «pasta de arquivo»... mv article archive/ ... algo que qualquer utilizador de Linux faz em menos de um dia.

Consegues imaginar quanto tempo vais gastar em compilações, só para ter uma versão «estável» durante alguns dias? Quer dizer, numa máquina antiga, com MAKEOPTS="-j3", no fim de actualizar o Chromium já existe uma nova versão, e passas mais uma semana a compilar a nova versão e a actualizar outra vez depois de terminar a compilação da última actualização. Nesse aspecto é Insano (no Cérebro).

Então, nesta perspectiva de consumo de tempo, como vamos compilar o nosso próprio kernel pessoal com os módulos e funcionalidades que queremos, talvez ACCEPT_KEYWORDS="amd64" com versões estáveis seja a melhor escolha, já que as actualizações são um pouco mais lentas. Mesmo assim, eu só actualizaria o Gentoo se fosse estritamente necessário. É como o Slackware, as actualizações são lentíssimas, podem levar um ano, enquanto continuam a usar apenas OpenRC. Portanto, nunca actualizes o Gentoo e, naturalmente, nunca acrescentes demasiadas keywords ao USE="X" no ficheiro /etc/portage/make.conf. Mantém-no o mais limpo possível, porque quando as actualizações forem precisas vais ter de mudar algumas, e nesse ponto só as deves mudar na pasta /etc/portage/package.use/.

Basta lembrar de ir de férias alguns dias ou semanas, enquanto o processo de compilação termina, e se tivermos sorte e algo correr mal — o que é espantosamente comum no Gentoo depois de algum tempo sem actualizar... ao fim de um mês vais provavelmente encontrar um problema. Ao fim de um ano.. :)

Because using Links to install Gentoo we cannot see Warnings or Alerts

Last Gentoo Linux Review I describe how I get confused when installing Gentoo from the Minimal ISO. Then I face some issues, which are having Systemd and OpenRC in the same page, while Warnings are not shown as warnings, and therefor some details are not clear enought for me.

Then, I start reading the Full Installation Alpha Version of their documentation and I realize that warnings were there, while the Systemd information too. So at this point, I don't wish to follow Gentoo Handbook, but build my own by taking notes of their Handbook notes. Is the difference between using Firefox or w3m/links/elinks/lynx Terminal Web-Browsers.

For example, I was complaining about Memory Usage at compilation Time, but they have a Warning saying that using MAKEOPTS="-j2" is the safest way to not use all memory that we have in our machine, which can run out of memory if we use a higher number of CPUs, while building something like Rust or GCC, our Machine will crash and forcing shutdown is necessary. "Is a Installation Skill that Kills Installation." :D

Another curiosity is the Sakaki (some Japanese user that share his installation process) dedicated to a possible exclusive Systemd Handbook with a lot of improvements, if we compare it to the Default and Official Gentoo Manual, while the first warning on the Top of the Page, tell us to Not Follow that Guide. Then I ask myself: why that Guide is still there anyway? I don't know, but if I assume that some details are "out of Date", or we update them or we remove the full out of date article to the "Archive" folder. I mean, I would hide it, to not confuse users that use "Links" to read the manual pages available on Gentoo websites.

Is just a noobie perspective, they do whatever they like to. But yeah, they could spend some minutes updating their Documentation or spend some seconds by moving that article to some "archive folder..." mv article archive/ ... Something that any Linux user can do in less than 1 single day.

Can you imagine how much time you will spend on compilations, just to have a "stable" version for a few days? I mean, in a older machine, using MAKEOPTS="-j3" at the end of updating Chromium a new version is already available, taking you another week to compile the new version and updating again after finishing the compilate of the last update. In that aspect is Insane (in the Brain).

So, in this Time consuming perpective, since we will compile our own personal Kernel with the modules and features that we wish to have, maybe a ACCEPT_KEYWORDS="amd64" stable releases is the best choice, since updates are a bit slower. Even then, I would update Gentoo only if is strictly necessary. Is like Slackware, updates are damn slow, can take a year or so, while they still using OpenRC only. So, never update Gentoo and naturally, never add too much keywords to the USE="X" on the /etc/portage/make.conf file. Keep it as clean as possible, since when updates are needed you will need to change some and at that point, you should only change them on /etc/portage/package.use/ folder.

Just remember to go for vacations for some days or weeks, while compilation process gets done, if we have some luck and something wrong happen, which is amazingly common on Gentoo after not updating for some Time.. after 1 month you will probably encounter some problem.. After one year.. :)
