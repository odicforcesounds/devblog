HTTP — From Browser Click To Server

HTTP = request/response text over TCP (usually TLS). Specs: HTTPWG, RFC 9110 semantics, RFC 9112 HTTP/1.1, RFC 9113 HTTP/2, RFC 9114 HTTP/3. MDN: MDN HTTP.

0 — The 11-Step Journey (One Click)

1. URL parse: https://api.example.com:443/notes?page=2 → scheme+host+port+path+query
2. Cache? memory → disk → service-worker? (Cache-Control decides)
3. DNS: resolver → 93.184.216.34 (curl: --resolve to fake; see: dig api.example.com)
4. TCP handshake: SYN → SYN-ACK → ACK (see tcp-packets-dark.html)
5. TLS handshake (https): ClientHello(SNI) → ServerHello+cert → key → Finished (port 443)
6. HTTP request bytes ride TLS records inside TCP segments inside IP inside Ethernet
7. Server: NIC → Nginx (reverse proxy) → Node/Express route → DB → JSON
8. HTTP response returns same tunnel: status + headers + body
9. Browser: parse HTML/CSS/JS, fetch sub-resources ( HTTP/2 multiplex / HTTP/3 QUIC-UDP )
10. Render, run JS (fetch/XHR), store cookies/cache per headers
11. Keep-alive reuses TCP; close via FIN or idle timeout
Watch it: DevTools Network tab + curl -v + tcpdump -i any port 443 (sizes) + Wireshark Follow TLS. Same story, four lenses.

2 — Methods + Status (What They Mean On Wire)

Methods: GET (read, cacheable), HEAD (headers only), POST (create), PUT (replace), PATCH (partial), DELETE (remove), OPTIONS (CORS preflight). Status: 1xx hold on, 2xx win (200 OK, 201 Created, 204 No Content), 3xx go elsewhere (301/302/307/308 + Location), 4xx you messed up (400/401/403/404/429), 5xx server messed up (500/502/504).

curl -sSI https://example.com | head          # status + headers
curl -sS -X POST -H 'Content-Type: application/json' -d '{"a":1}' https://api.example.com/notes -D -

3 — Headers That Matter (Examples You'll Actually Send/See)

HeaderDirectionExample + why
HostReqHost: api.example.com — virtual-host routing. HTTP/1.1 mandatory.
AuthorizationReqBearer eyJ... / Basic dXNlcjpwYXNz. Never log full value.
Cookie / Set-CookieBothCookie: sid=abc → Set-Cookie: sid=abc; HttpOnly; Secure; SameSite=Strict. Session + flags stop XSS/CSRF.
Content-Type / LengthBothapplication/json; charset=utf-8 + 48. Mismatch = truncation bugs.
Accept / Accept-EncodingReqAccept: application/json, Accept-Encoding: gzip, br — negotiate format/size.
Cache-Control / ETag / Last-ModifiedBothmax-age=60, must-revalidate, ETag: "v1" + If-None-Match → 304 saves bytes.
CORS: Origin / ACAO / VaryBothOrigin: https://app.example.com → Access-Control-Allow-Origin: https://app.example.com + Vary: Origin. Wildcard + credentials = fail.
Security: CSP/HSTS/X-Frame/X-Content-Type/ReferrerRespContent-Security-Policy: default-src 'self', Strict-Transport-Security: max-age=31536000, X-Frame-Options: DENY, X-Content-Type-Options: nosniff, Referrer-Policy: no-referrer.

5 — Versions: 1.1 vs 2 vs 3 (One Line Each)

1.1: text, one request per connection (keep-alive pipelining rare). 2: binary multiplex over one TCP (h2, needs ALPN). 3: QUIC over UDP, faster loss recovery. Debug: curl --http1.1/--http2 -v + Alt-Svc header.

Refs: MDN header reference, HTTPWG, RFC 9110.

Type URL → DNS → TCP → TLS → HTTP bytes → proxy → app → DB → bytes back. Headers are the envelope customs stamps.
