DNS — How It Works, How To Configure & Use

DNS = phonebook: names → IPs (+ mail, text, service). Specs: RFC 1035, RFC 8484 DoH, 1.1.1.1 docs. Test bed: your Debian + dig.

0 — How It Works (60-Second Path)

browser → stub resolver (/etc/resolv.conf: nameserver 1.1.1.1)
  → recursive resolver (Cloudflare/Quad9/own Unbound)
    → root "." → TLD "com." → authoritative "example.com."
    ← A 93.184.216.34 (cached by TTL each level)
# watch live:
dig +trace example.com
sudo tcpdump -i any -nn port 53
Authoritative = truth. Recursive = librarian. Stub = you asking. TTL = how long to remember. NXDOMAIN = no such name.

1 — Record Types You'll Actually Use

TypeExample + meaning
A / AAAAapi.example.com. 300 IN A 93.184.216.34 / AAAA IPv6. The core answer.
CNAMEwww → api.example.com. Alias. Never at apex (use ALIAS/ANAME there).
MX / TXT (SPF/DKIM/DMARC)MX 10 mail.example.com. Mail routing. TXT "v=spf1 ..." anti-spoof.
NS / SOADelegation + zone authority (serial, refresh, admin mail).
SRV / CAA / PTRService ports, CA allow-list, reverse IP→name.

2 — Configure: 4 Ways (Pick One)

A. Just use trustworthy resolvers (easiest, 2 min)

# /etc/systemd/resolved.conf (Debian systemd):
[Resolve]
DNS=1.1.1.1#cloudflare-dns.com 9.9.9.9#dns.quad9.net 8.8.8.8
DNSOverTLS=yes
# then: systemctl restart systemd-resolved; resolvectl status; resolvectl query example.com

B. Own recursive (privacy, no upstream logs)

sudo apt install -y unbound
# /etc/unbound/unbound.conf: server: { interface: 127.0.0.1; access-control: 127.0.0.0/8 allow; hide-identity: yes; }
systemctl enable --now unbound
# point stub to 127.0.0.1; test: dig @127.0.0.1 example.com +dnssec

C. Own authoritative for your domain (you are the truth)

sudo apt install -y bind9
# /etc/bind/named.conf.local: zone "example.com" { type primary; file "/etc/bind/db.example.com"; };
# db file: $TTL 300 / @ IN SOA ns1 admin 2024010101 (...) / @ IN A 93.184.216.34 / www IN CNAME @
named-checkconf; named-checkzone example.com /etc/bind/db.example.com; systemctl reload bind9
# registrar → glue NS ns1.example.com → your IP. Verify: dig +trace +dnssec example.com

D. Encrypted DNS: DoT / DoH (ISP can't snoop/modify)

# DoT via stub (above) or Unbound forward-tls to 1.1.1.1:853 / 9.9.9.9:853
# DoH via dnscrypt-proxy (https://github.com/DNSCrypt/dnscrypt-proxy):
sudo apt install -y dnscrypt-proxy
# /etc/dnscrypt-proxy/dnscrypt-proxy.toml: server_names=['cloudflare','quad9-doh']
# Firefox: Settings → DNS over HTTPS → Custom https://cloudflare-dns.com/dns-query
Order of privacy: ISP plain (sees all) < public resolver+DoT/DoH (hides from ISP) < own recursive (hides from resolver, root/TLD still see hashes). DNSSEC adds authenticity, not privacy.

3 — Use & Debug Daily

dig example.com +short; dig AAAA example.com; dig MX example.com; dig TXT example.com
dig @1.1.1.1 example.com +dnssec   # AD flag = validated
host -t A example.com 1.1.1.1; nslookup example.com
resolvectl query example.com; systemd-resolve --statistics
# flush: resolvectl flush-caches  (Chrome: chrome://net-internals/#dns → Clear)
# reverse: dig -x 93.184.216.34 +short

4 — Gotchas That Bite

TTL patience (wait old TTL after change), CNAME at apex forbidden, trailing dot in zone files (mail.example.com. vs relative), registrar glue missing, DNSSEC chain break = bogus, captive portals hijack port 53 (use DoH to escape).

Refs: RFC 1035, Cloudflare DNS, Quad9, dnscrypt-proxy, Unbound, BIND9.

Stub asks, recursive hunts, authoritative answers, cache remembers. Encrypt the hunt, sign the answer.
