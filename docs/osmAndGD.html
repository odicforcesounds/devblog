LEVEL 1 · OSM ZERO

What is OpenStreetMap? The Wikipedia of Maps

Story: your city vanished from commercial maps. The community rebuilds it — you hold the first GPS trace. 🏠 Home

1.1 OSM in 30 seconds

OpenStreetMap (2004, UK) is a free, editable world map built by ~10M volunteers. Data is open (ODbL): anyone can use it, with attribution. Unlike Google Maps, you own the data — perfect for Android indie games (no API key bills).

  • Database, not picture: geometry + tags.
  • 3 primitives only: Node, Way, Relation.
  • Rendered later into tiles you see.

1.2 The 3 atoms — animated below 👇

  • Node = point: lat, lon. A tree, shop, GPS fix.
  • Way = ordered node list. Open = road/river. Closed = building/park area.
  • Relation = group of nodes/ways with roles. Bus route, multipolygon, turn restriction.

Try it: each click drops a Node. Connect 3+ and you've authored a Way.

🎮 INTERACTIVE — CLICK TO MAP (SVG, NO LIBS)

Each click = +2 XP. Real editors: iD (web), JOSM (desktop), Vespucci/StreetComplete (Android).

1.3 Why OSM for games?

  • Free POIs (treasures, gyms, checkpoints) worldwide.
  • Offline: ship .map / .mbtiles, play without network.
  • Real streets = real level geometry (routing, geofences).

1.4 Golden rule

Map what's on the ground. No fictional roads, no copyrighted imports. Your edits go live in minutes and power thousands of apps.

LEVEL 2 · HOW OSM WORKS

Tags, Edits & the Tile Machine

🏠 Home · Geometry is meaningless without meaning. That's tags.

2.1 Tags: key=value

Every object carries tags: highway=primary, amenity=school, natural=tree. Keys group, values specify. No fixed schema — community votes on the wiki.

node: highway=bus_stop
way:  highway=residential + name=Rue 10 + maxspeed=30
area: building=yes + building:levels=3

2.2 Contribution loop

Survey → Edit → Validate → Render → Use. Collect with GPS/StreetComplete → edit in iD/JOSM → changeset uploaded with comment → validators + bots check → renderers (Mapnik) bake tiles in minutes → your Android app reads them.

  • Changeset = one edit session with message.
  • Revert possible; vandalism is caught fast.

LEVEL 3 · OSM ON ANDROID
Put the Free Map in Your Game
🏠 Home · Zero Google Maps bills. Full offline. Total control.

  

    
3.1 Three ways to show OSM
  • osmdroid (MapView) — drop-in, free. map.controller.setZoom(16); map.controller.setCenter(GeoPoint).
  • MapLibre / Tangram — vector, styled with JSON, 60fps.
  • Geo-intent — geo:lat,lon?q=cafe opens any map app. Zero code map!

    
3.2 Android location stack
  • ACCESS_FINE_LOCATION + ACCESS_COARSE_LOCATION in Manifest; request at runtime (Android 6+).
  • FusedLocationProviderClient — battery-smart GPS/Wi-Fi fusion.
  • Foreground service for tracking while playing; geofence with GeofencingClient.
  • Offline: pre-pack .mbtiles in assets/ or download region on Wi-Fi.

4.1 MDA framework
  • Mechanics (rules you code): move, collect, geofence trigger.
  • Dynamics (what emerges): race to POI, territory control.
  • Aesthetics (feelings): discovery, fellowship, challenge. Design backwards from feeling!

    
4.2 Pillars of a good Android game
  • Core loop ≤30s: walk → discover → collect → upgrade.
  • Clear goal + feedback: every tap sparkles (juice).
  • Fair progression: tutorial → easy wins → mastery.
  • Session design: 2-min bus-stop sessions, cloud save.

LEVEL 5 · ANDROID ENGINE ROOM
Lifecycle, Game Loop & 60 FPS
🏠 Home · Ship buttery gameplay on a $120 phone.

  

    
5.1 Respect the lifecycle
onCreate() → load assets
onResume() → start loop/thread
onPause()  → PAUSE game + save!
onDestroy()→ release sensors, GPS
Never run GPS/render in background. Save state in onPause — a call can arrive mid-boss-fight.

    
5.2 Rendering choices
  • Canvas/SurfaceView: simple 2D, easy, enough for map games.
  • OpenGL ES / Vulkan: max perf, more code.
  • Engines (libGDX, Godot, Unity): physics, particles, export to Android fast.
  • Fixed timestep: update(dt); render() via requestAnimationFrame/Choreographer; pool objects, avoid GC spikes.
