Não, isto não é um post sobre prisões

Já leste o meu post sobre o FreeBSD? Com base na última experiência a usar o Gentoo, percebi que o FreeBSD é o que preciso para desenvolver os meus servidores. Só preciso de uma única máquina para alojar todos os serviços necessários em máquinas diferentes e, embora isso gaste mais electricidade, ao usar o FreeBSD posso ter diferentes «servidores dedicados» dentro do servidor principal. É o que as Jails representam.

Os sistemas BSD são espantosos. Podes criar várias jails para muitos propósitos, e o propósito principal aqui é apenas ter um Sistema Operativo dedicado para cada serviço, dando-me a sensação de que é um pouco mais seguro do que ter um Sistema Operativo realmente dedicado num hardware dedicado para cada serviço, ou ainda mais fundo: podes criar uma jail com muitos processos filhos que são outras jails.

Como na prisão, estar em Jail é FreeBSD, mas isso custa-te algum trabalho a manter, como qualquer prisão gasta dinheiro a manter as pessoas que estão lá dentro vivas. Há vários tipos de Jails, mas construir uma ou mais à maneira original exige mais trabalho de configuração e manutenção. Por isso, usar o software Bastille é a recomendação para resolver este problema de forma fácil.

Assim, podes ter por exemplo uma máquina com 1TB de disco, 8GB de RAM e 8 núcleos que seria um servidor dedicado, mas como «tu» queres acrescentar mais serviços de forma independente uns dos outros, podes criar Jails. No OpenBSD podes fazer o mesmo, mas como o OpenBSD é mesmo paranóico com segurança, o desempenho é sacrificado, enquanto ao usar o FreeBSD o desempenho é maior e, por isso, não precisas de sacrificar metade dos recursos do sistema para os usar.

Saber tudo isto faz-me pensar nesta «pequena piada»: A Internet não é a Internet, mas um sistema BSD. Numa conversa com alguns tipos do canal #FreeBSD no servidor IRC irc.libera.chat, aprendi um pouco mais sobre esta abordagem e sinto que preciso de a experimentar. Ao contrário do Docker, as Thick Jails do BSD não dependem do sistema principal. Por isso, se um Hacker dominar o servidor, na verdade só domina a Jail, não o sistema principal. Naturalmente isto pode ser falso, já que a segurança é um problema enorme que pode afectar muitas coisas, mas o conceito de base é esse, o que é bastante agradável.

No, this is not a post about Prisons

Did you already read my post about FreeBSD? Based on the last experience on using Gentoo, I figure out that FreeBSD is what I need to develop my servers. I just need one single Machine to host all necessary services in different machines, while that would cost more electricity, by using FreeBSD I can have different "dedicated servers" inside the main server. Is what Jails stand for.

BSD systems are mind blowing. You can create several jails for many purposes, while the main purpose here is only to have a dedicated Operating System for each service, giving me the sensation that is a little bit more secure than having a real dedicate Operating System in a dedicated Hardware for each Service, or even deeper, you can create a jail with many child processes that are other jails.

Like in prison, to be in Jail is FreeBSD but that cost you some work to maintain it, like any prison will spend money to maintain the people inside the Jail, alive. There are several type of Jails, but building one or more in the original way ask you more work to configure and maintain. Therefor, using Bastille software is the recommendation to deal with this problem in a easy way.

So, you can have for example one machine with 1TB disk space and 8GB of RAM and 8 CPU cores that would be a dedicated server, but since "you" wish to add more services in a independent way from each others, you can create Jails. In OpenBSD you can do the same, but since OpenBSD is really paranoid with security, performance is sacrificed, while using FreeBSD performance is bigger and therefor you don't need to sacrifice half of your OS resources to use them.

Knowing all of this, make me think about this "little joke": The Internet is not the Internet, but a BSD system. In a conversation with some guys from #FreeBSD channel on irc.libera.chat IRC server, I learn a bit more about this approach and I feel I need to try it. Differently from Docker, BSD Thick Jails are not dependent from the main system. So, if an Hacker own the server, in fact the hacker only owns the Jail, not the main system. Naturally this can be false since security is a big big problem that can effect many things, but the base concept is that, which is pretty nice.
