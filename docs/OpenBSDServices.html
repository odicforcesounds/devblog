Chapter 1

HTTPD — the austere web server ★ CHAPTER CLEARED

httpd(8) does one job: serve files fast, chrooted, with almost no knobs. No modules, no .htaccess, no reverse-proxy engine (that is relayd's job). If you want dynamic content you hand it to fastcgi (slowcgi, php-fpm). This chapter drills: processes → sockets/servers → locations → static/fastcgi/security.

LVL 1

1.1 Process model & chroot drill

UNSEALED

When you run rcctl start httpd, one privileged parent reads /etc/httpd.conf, binds port 80/443, then forks prefork server workers (default 3) plus a logger. Workers immediately chroot("/var/www") and drop to user www with tight pledge(). That means a bug in request parsing cannot see /etc at all — document roots like /htdocs/site are really /var/www/htdocs/site. The private key path is the exception: it is loaded before chroot from /etc/ssl/private/.

# /etc/httpd.conf — smallest speaking server
server "www.example.com" {
  listen on * port 80
  root "/htdocs/example"  # = /var/www/htdocs/example on disk
}
# httpd -n  &&  rcctl enable httpd  &&  rcctl start httpd

LVL 2

1.2 Servers, listen & TLS (SNI)

SEALED

Each server "name" is a virtual host. Matching order: listen socket first, then Host header against name/alias globs; unmatched Host falls back to the first server on that socket. listen on * tls port 443 enables TLS; the tls { certificate, key, protocols } block defaults to TLSv1.2+1.3. Try the drill: send three Host headers and watch which server answers.

server "www.example.com" {
  alias "example.com"
  listen on * port 80
  listen on * tls port 443
  tls { certificate "/etc/ssl/example.fullchain.pem"
        key "/etc/ssl/private/example.key" }
  root "/htdocs/example"
  log style combined
}

LVL 3

1.3 Locations: first match wins

SEALED

Inside a server, location blocks rewrite the rules per path. Patterns are shell globs; location match uses patterns with captures. First matching location wins — order matters. A location can set its own root, directory index/no auto index, block, or hand off to fastcgi. found / not found restrict to existing / missing files.

location "/blog/*" { root "/htdocs/blog" }
location "*.php" { fastcgi socket "/run/php-fpm.sock" }
location "/private/*" { block return 403 "forbidden" }
location "/*" { root "/htdocs/example" }
TRAP: /blog/y.php hits /blog/* first and is served as a static file, never reaching fastcgi. Put specific patterns first.

LVL 4

1.4 Dynamic content, auth & logging

SEALED

httpd never runs code itself. fastcgi socket "/run/slowcgi.sock" (note: inside chroot, so host path /var/www/run/…) forwards to slowcgi (CGI wrapper) or php-fpm. Auth is HTTP Basic via an htpasswd file inside the chroot — always behind TLS. Logging: log style combined to /var/www/logs/* or syslog. MIME types come from the types { include "/usr/share/misc/mime.types" } section; unknown → application/octet-stream.

location "*.cgi" { fastcgi socket "/run/slowcgi.sock" }
location "/secure/*" {
  authenticate "Ops" with "/htpasswd"
  root "/htdocs/secure"
}
types { include "/usr/share/misc/mime.types" }
log access "example-access.log"  # → /var/www/logs/

Chapter 2

RELAYD — relay, redirect & load balancer ★ CHAPTER CLEARED

relayd(8) is the front door: it terminates TLS, inspects layer 7, health-checks backends in tables and forwards only to the living. Layer-3 redirect programs pf rdr-to; layer-7 relay proxies the connection. Same animated drill style as Chapter 1.

LVL 1

2.1 Relay vs redirect (L7 vs L3)

UNSEALED

redirect = packet-level NAT via pf (fast, blind). relay = accepts the client connection, applies protocol rules, opens a second connection to the backend (can see HTTP, add headers, do TLS). If you need forward to <app> port 8080 check http "/" code 200, you need a relay.

# L3: pf programs rdr-to (no HTTP inspection)
redirect "web" { listen on egress port 80
  forward to <webhosts> port 80 }
# L7: full proxy (HTTP aware, health-checked)
relay "web" { listen on egress port 80
  protocol "http"  forward to <app> port 8080
  check http "/" code 200 }

2.2 Tables & health checks (failover drill)

SEALED

table <app> { 10.0.0.11, 10.0.0.12 } is the pool. check http "/" code 200 (or check tcp, check script) marks hosts up/down; dead hosts get no traffic until they recover. Scheduling: round-robin by default, plus least-states, random, hash/srchash for stickiness.

table <app> { 10.0.0.11, 10.0.0.12 }
relay "site" {
  listen on egress port 80
  protocol "http"
  forward to <app> port 8080 check http "/" code 200
}

LVL 3

2.3 Protocols: filter, rewrite, TLS acceleration

SEALED

protocol "http" { … } is where L7 brains live: match request header … forward to, block, header append/change/remove, return redirects, TCP + TLS options. Classic pattern: relayd terminates public TLS with one cert, then speaks plain HTTP to backends on a trusted LAN — TLS acceleration.

protocol "http" {
  match request header "Host" value "static.example.com"
    forward to <static>
  match url "/api/*" forward to <api>
  tcp { nodelay, sack, socket buffer 65536 }
  tls { ciphers "HIGH:!aNULL" }
}
relay "tls-accel" {
  listen on egress tls port 443
  tls { certificate "/etc/ssl/fullchain.pem"
        key "/etc/ssl/private/key.pem" }
  protocol "http"  forward to <app> port 8080 check tcp
}

2.4 relayd + pf + httpd stack

SEALED

Logs via syslog; relayctl show summary/hosts inspects state.

# relayd.conf: front on egress, backs on 10.0.0.0/24

Chapter 3

SMTPD — OpenSMTPD mail ★ CHAPTER CLEARED

smtpd(8) is a privilege-separated fleet (control, lookup, queue, scheduler, dispatcher, pony/exec, filters) driven by one readable file: smtpd.conf = tables + actions + listeners + rules. Same drill rhythm: envelope → rules → queue → delivery.

LVL 1

3.1 Processes & the envelope

UNSEALED

SMTP talks in an envelope (MAIL FROM / RCPT TO) separate from the message headers. smtpd splits duties so no single process is both network-facing and queue-owning: pony speaks SMTP, lookup resolves tables/aliases, queue owns disk, scheduler plans retries, dispatcher/mda/mta deliver. Crash one, the mail survives.

#最小 shape of smtpd.conf: tables → actions → listen → rules
table aliases file:/etc/mail/aliases
action "local" mbox alias <aliases>
listen on lo0
match for local action "local"

LVL 2

3.2 Listeners, rules & actions

SEALED

listen on egress port 25 tls-require (MX), port 587 tls-require auth (submission), port 465 smtps (implicit TLS). Rules are first-match-wins: match [from …] [for …] [auth …] action "…". Actions: mbox (local spool), maildir, relay (send onward), reject. Order rules specific → general.

action "local" mbox alias <aliases>
action "out" relay
listen on egress port 25 tls-require
listen on egress port 587 tls-require auth
match for local action "local"
match auth from any for any action "out"
match from any for any action "reject"  # no open relay!
OPEN RELAY TEST: unauthenticated mail from anywhere for anywhere must hit reject. If it relays, you are the spam cannon.

LVL 3

3.3 Tables, aliases & virtual domains

SEALED

tables map keys→values: file:/etc/mail/aliases, file:/etc/mail/virtuals, file:/etc/mail/secrets, or db (built with makemap). Aliases expand ops: alice, bob; virtuals map sales@example.com → alice@example.com. newaliases rebuilds the db after edits.

# /etc/mail/aliases
ops: alice, bob
# /etc/mail/virtuals
sales@example.com  alice@example.com
@example.com       catchall@example.com
# smtpd.conf
table aliases file:/etc/mail/aliases
table virtuals file:/etc/mail/virtuals
action "local" mbox alias <aliases> virtual <virtuals>

LVL 4

3.4 Queue, filters, TLS & anti-spam posture

SEALED

Accepted mail is fsync'd to /var/spool/smtpd, then the scheduler retries with backoff (smtpctl show queue, smtpctl remove …). filters (rspamd, spamd via filter-rspamd, proc-exec) can reject/tag before queueing. Harden: tls-require on listeners, valid rDNS + SPF + DKIM (via rspamd/dkim) + DMARC, and spamd greylisting in pf for port 25.

filter "rspamd" proc-exec "/usr/local/bin/filter-rspamd"
listen on egress port 25 tls-require filter "rspamd"
action "out" relay
# smtpctl show queue | smtpctl log briefing

Chapter 4

VMM / VMD — virtual machines ★ CHAPTER CLEARED

One hypervisor (vmm(4) in the kernel, /dev/vmm), one daemon (vmd(8)), one tool (vmctl(8)), one file (/etc/vm.conf). Guests need hardware VMX/EPT or SVM/RVI, serial console, and virtio drivers. No graphics, no passthrough, no live migration — by design, small and auditable.

LVL 1

4.1 vmm · vmd · vmctl: who does what

UNSEALED

vmm runs in the kernel using CPU virtualization; a guest VM exit returns to userspace. vmd owns VM processes, emulates virtio devices in split helper processes (pledged/unveiled), drives VCPUs through /dev/vmm. vmctl talks to vmd's socket: create, start -c, console, stop, pause, status. Firmware /etc/firmware/vmm-bios comes from fw_update.

# dmesg | egrep '(VMX/EPT|SVM/RVI)'  — must match, else no vmm
doas fw_update
doas rcctl enable vmd; doas rcctl start vmd
doas vmctl create -s 40G /var/vm/guest.qcow2
doas vmctl start -c -L -r install.iso -d guest.qcow2 guest
# ~~. or ~. to escape console

LVL 2

4.2 CPU, memory, disks (raw vs qcow2)

SEALED

memory 2G (rounded to MB, capped by vmd's datasize), cpus 1 (safe; SMP unsupported). disk "/var/vm/g.qcow2": raw = flat preallocated, qcow2 = sparse + backing files (vmctl create -b base.qcow2 child.qcow2 for golden-image clones). Backing files are not snapshots — shut down cleanly before host-side copies.

vm "guest" {
  memory 2G
  cpus 1
  disk "/var/vm/guest.qcow2"
  cdrom "/var/vm/install.iso"  # vioscsi CD-ROM
}

LVL 3

4.3 Networking: tap, local, switches (veb/bridge)

SEALED

Guest sees vio(4); host sees a tap(4). local interface auto-numbers from 100.64.0.0/10 with DHCP — but no Internet until you add NAT + forwarding. A switch "lab" { interface veb0 } bridges taps to a veb/bridge; put host IP on a vport. Ethernet bridging works; Wi-Fi bridging does not.

switch "lab" { interface veb0 }
vm "guest" {
  memory 2G
  disk "/var/vm/guest.qcow2"
  interface { switch "lab" }
  owner vmadmin
}
# pf: match out on egress from vport0:network to any nat-to (egress)

LVL 4

4.4 Virtio, isolation & ops

SEALED

Guests use paravirtual virtio: vio (net), block storage, vioscsi (CD-ROM), vmmci (host shutdown/reboot requests), console, entropy. vmd splits device emulation into helper processes under pledge/unveil, assigns owner per VM for socket access, supports pause/resume and memory dump/restore — but no live migration, no passthrough, no graphics.

vmctl ─unix socket─▶ vmd ─ioctl /dev/vmm─▶ vmm(4) ─VMX/SVM─▶ guest │ ├── vio-net helper ── tap ── veb/bridge │ ├── blk helper ── qcow2/raw │ └── vioscsi ── install.iso └── vmmci: host "vmctl stop" == graceful guest shutdown
doas vmctl status
doas vmctl console guest     # serial; exit with ~.
doas vmctl pause guest; doas vmctl resume guest
doas vmctl stop guest        # via vmmci if guest supports it
doas vmd -n                  # check vm.conf like httpd -n
