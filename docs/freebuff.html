01 — Foundations

What Freebuff actually is

Freebuff is a coding agent, not an autocomplete box. You describe an outcome in plain language; a coordinator maps your repository, plans, edits files, runs commands, checks its own work and reports back. It runs in your terminal, on your desktop, in a browser, on a hosted sandbox attached to GitHub, and in a plain chat window. The same agent runtime sits underneath all five, which is why this guide can teach the system once and then explain the surfaces.

≠

Not a single model

A coordinator routes each turn to one of nine narrow subagents. A cheap, fast model finds files; a reasoning model plans; a reviewer reads the diff; a shell agent runs the tests. You pick the main model, the system picks the right tool for each step.

$0

Ads, not a paywall

The free tier is funded by text ads. There is no card, no API key and no credit meter to watch. Paid plans add daily hours, a monthly bonus and access to every model — they do not unlock the product itself.

⏱

Billed in hours

Usage is measured in hours, not tokens. One session lasts one hour and contains unlimited messages. A 3× model consumes three hours of balance for that hour of work. Daily hours reset at local midnight and never roll over.

02 — Five doors, one engine

Every Freebuff product, in detail

Most people meet Freebuff through one surface and never realise the others exist. The agent runtime is shared, but each product optimises for a different moment: a repo on your laptop, four tasks at once, a repository you do not have cloned, a brand-new app, or a question with no code attached. Pick the door that matches the moment.

Native app · macOS · Windows · Linux

Freebuff Desktop

The control room. Desktop runs agents locally against your real project and lets several of them work at the same time, each in its own tab. When two agents would otherwise fight over the same files, Desktop isolates them in separate workspaces instead of letting them overwrite each other. You can also keep a locally installed Claude Code or Codex agent available inside Desktop using your own provider account — those connected models sit outside Freebuff's included catalog and outside its hourly wallet.

  • SignatureParallel conversations in tabs, with concurrent agents isolated in separate workspaces or Git worktrees so two tasks cannot trample one branch.
  • Best forA full working day of changes: one tab on the feature, one on the flaky test, one on the migration, one reviewer you can ask for a second opinion.
  • AlsoVisual diffs, per-tab context, and the same subagent cast the CLI uses. Local commands run with the permissions of your user account, so approval prompts matter.
  • AccessFree and paid accounts. Download, sign in, open a folder. No API key.

03 — The cast

How one prompt becomes a reviewed change

Freebuff does not send your whole request through one giant prompt to one giant model. A coordinator reads the turn, decides which narrow specialists to spawn, gives each one only the context and permissions it needs, and stitches the results together. That is why the same product can find a file cheaply, reason expensively, run a shell command under supervision and review the diff before you ever see it.

STEP 01

Intent

You describe an outcome. The coordinator classifies the task: explore, edit, debug, research, or build.

STEP 02

Context

project-scout supplies the repo map; file-picker ranks the handful of files that actually matter.

STEP 03

Plan

For hard turns, thinker-with-files-gemini reads the relevant files and reasons on Gemini Pro before any edit.

STEP 04

Execute

The agent edits files and asks shell-runner for installs, builds and test commands inside a permission boundary.

STEP 05

Verify

test-runner runs only the relevant suite; browser-use drives Chromium when rendered behaviour matters.

STEP 06

Review

code-reviewer reads the diff by severity — regressions, missing tests, security smells — and sends fixes back.

STEP 07

Deliver

git-curator stages, writes a commit message in your repo's style, and opens a PR with /pr.

STEP 08

Report

You get the change, the commands that ran, the test output and any open risk — not just “done”.

The nine subagents

Who does what, and when they run

Each has narrow scope, narrow context and narrow trust. You can call any of them by hand with /agent <name>.

file-picker01

Runs a fast Flash Lite model against a local code map to find the files that matter for the current task. Returns ranked paths plus a one-line justification for each. Almost every other subagent depends on it.

RunsAt the start of almost every turn · Gemini 3.1 Flash Lite

code-reviewer02

Reads diffs after an edit and reports issues by severity. Catches obvious regressions, missing tests and security smells. Its findings go back into the loop, not just into a report you have to act on manually.

RunsAutomatically after any multi-file edit · or /review

browser-use03

Drives a real Chromium instance to verify the app you just edited still works. Logs in, navigates, asserts on the rendered DOM, takes screenshots. Used heavily on full-stack tasks generated in the App Builder.

RunsWhen behaviour in a browser is the acceptance test

thinker-with-files-gemini04

When a turn needs deep reasoning, the coordinator hands off. It reads the files it needs and thinks the problem through on Gemini Pro — included inside Freebuff rather than billed as a separate upgrade.

RunsOn architecture, tricky bugs and cross-file reasoning

researcher05

Does web research with citations. Useful when the task touches an unfamiliar library, a changed API or a version-specific behaviour. Returns a short brief with linked sources so you can check the claim.

RunsOn docs, releases and “how does this service work” turns

test-runner06

Detects the project's test framework — vitest, jest, pytest, go test, cargo test — and runs only the relevant tests instead of the whole suite. Streams failures back to the coordinator for repair.

RunsAfter edits that can break behaviour

git-curator07

Stages, commits and writes commit messages that match the repository's historical style. Opens pull requests with /pr. Refuses to push to main unless you explicitly ask it to.

RunsWhen you approve committing or opening a PR

shell-runner08

Executes shell commands inside a permission boundary. Destructive commands always require approval. Long-running processes are backgrounded with output streamed to a terminal file the main agent can read.

RunsFor installs, builds, servers, migrations and tests

project-scout09

Added in 2026. Indexes the repository on first run and keeps the index warm, tracking recent edits, build outputs, lint errors and stack metadata so the coordinator has fast structural understanding without re-reading the whole tree.

RunsFirst run, then continuously in the background

⌘

Call the cast yourself

Force a specialist with /agent file-picker, /review or /pr. If a subagent is noisy for a particular repo, disable it with --no-subagent <name> at startup or in .freebuffrc.

!

Trust boundaries are real

The reviewer does not get browser logs; the browser does not get shell history. The shell agent can refuse what the coordinator cannot. Destructive commands need your approval, and git will not push to main unasked.

◎

Cost-aware by design

File discovery runs on a cheap, fast model. Expensive reasoning is reserved for turns that need it. That division is the reason an hour of Freebuff can cover a surprising amount of work.

Freebuff offers yearly billing and a pay-once option for crypto and local payment methods. The plans page does not publish those prices — choose the term at checkout to see them.

Monthly cancellation ends the plan and perks immediately, with no proration or refund. Yearly cancellation stops the next renewal and keeps access for the paid year, without an automatic refund. Pay once never renews.

Model costs and allowances can change during beta. A price change will not affect a running session, and Freebuff says every plan will keep including more in model usage than its price. Promotional prices are temporary.

07 — The fine print, spelled out

Limits, wallet mechanics and what happens to your data

Most reviews stop at “free tier, some limits”. That is not useful when you are deciding whether to run a four-hour migration on a Tuesday night. Here is the actual machinery: how hours are spent, when they refill, what fair use can do to a session, how regional access differs, and which data is and is not handed to advertisers.

A session is one hour, with unlimited messages

You are not rationed per prompt. Start a session, send fifty messages in the hour, and the session still costs its hour. The clock, not the message count, is the unit — which rewards batching a coherent piece of work into one sitting.

Models consume hours at a multiplier

An hour on MiMo v2.6 Flash Slow uses one hour of balance. An hour on a 3× model uses three. The multiplier is shown in the picker before you start, so the cost of a session is knowable in advance.

Daily hours reset at local midnight and never roll over

Unused daily hours are gone at the end of the day. There is no banking strategy: if you have a heavy task, do it today rather than saving capacity for tomorrow.

The monthly bonus is overflow, not a second daily pool

Paid plans add 60, 100 or 160 hours per month on top of the daily refill. It covers extra usage when a day runs long. An unused bonus is replaced by the next bonus — including when you upgrade — so it does not accumulate indefinitely.

Fair use can pause a session even with balance left

Allowances are not a guarantee of infinite throughput. Freebuff applies fair-use limits; a session may pause or stop even when hours remain. Capacity, not just payment, is part of the product.

Access depends on region and VPN status

Freebuff is available in every country. Supported regions get full access; other regions and VPN or proxy users get limited access to GLM 5.3 Flash, DeepSeek V4.1 Flash, MiMo v2.6 Flash Fast and both Solar models. The free limited-access allowance is 5 hours a day, or 4 on a VPN or proxy, spent first on every model, GLM included. Earned hours go into your wallet and are used after it.

Balances are denominated in hours since 15 October 2026

Older material talks about credits. The current wallet reads in hours, and 1 hour = 5 Freebucks. Referrals and bounties earn extra sessions on top of the free daily allowance.

Model availability is a matrix, not a promise

Availability depends on your access tier, the product you are using, your region and current capacity. Promotional entries can disappear. Models may serve from a quantized Q8_0 build, which can differ subtly from the full-precision version.

Cancellation is not prorated

Monthly: the plan and perks end immediately, with no refund or credit for the unused part of the month. Yearly: the next renewal stops, access continues through the paid year, and there is no automatic refund. Pay once simply never renews.

Data-use notices are per model and per feature

AI training on your submissions happens only when a model or feature says data may be used for training. In that case Freebuff or the provider may keep submissions to develop, train, test, evaluate, fine-tune and improve models, and Freebuff may share or sell them to third parties. Separately, Freebuff may use your data to train the models that choose and measure ads.

What advertisers do and do not get

Freebuff's free access is supported by text ads. The company says it may analyse messages, agent traces, files and usage to personalise ads and train ad models. It also states that separately uploaded files, project files and connected repositories are not given to advertising providers.

For Cloud, restricted partners may evaluate repositories you connect, but cannot otherwise use, broadly share or train on them. Read the current Privacy Policy before connecting a private repo you do not own.

⌂

Files outside your project

Freebuff says it does not read files outside your project, with narrow exceptions: files an agent reads in the conversation, files you share, and settings such as agent instructions and skills. That is a meaningful boundary for anyone with client work or secrets sitting in a home directory.

!

Public by default means public

Hosted preview URLs are reachable by anyone who has the link, and preview environments can be public. Do not put production credentials, customer data or private keys into a preview app, and remember that deploying new code does not republish an environment you deliberately took offline.

08 — The verdict

What Freebuff is genuinely good at — and where it stops

A guide that only lists strengths is an advertisement. The useful question is not “is it good?” but “good at which part of my week, and at what cost?” Here is the honest split.

Unusually strong
Real trade-offs
  1. Breadth for the priceFive surfaces, twelve picker models, nine subagents and a free tier with no card. The entry price is genuinely zero, not a seven-day trial.
  2. Orchestration, not one mega-promptCheap models find files, expensive models reason, a reviewer reads diffs, a shell agent is permissioned. Work is routed instead of crammed into one context.
  3. Verification is part of the loopIt runs the relevant tests, can drive Chromium, and reviews its own diff. That is a materially better loop than “generate and hope”.
  4. It can ship, not just editApp Builder plus hosted auth, database, storage and publish means the output can be a running product rather than a patch.
  5. Context options that matter524K and 1M windows, PDF/audio/video input on Gemini 3.8 Flash, image input on several models. Big artifacts stop being a summarisation problem.
  6. Real parallelism locallyDesktop's isolated worktrees let several agents work at once without the usual branch collisions.
  7. Research with sourcesThe researcher returns linked citations, which is the difference between a plausible answer and a checkable one.
  8. One wallet everywherePlan in Chat, implement in the CLI, verify in Cloud, finish in Web — no separate subscription per surface.

  2. Availability is conditionalModel access varies by tier, product, region and capacity. Promotional entries such as Gemini 4 Argon and GPT-6.1 Sol are temporary and region-gated.
  3. The free tier is ad-supportedText ads fund it, and usage data may train ad models. Uploaded files, project files and connected repos are excluded from ad providers, but this model is not for everyone.

09 — Your first ten minutes

Set up on the surface you actually use

You do not need to install anything to try the idea. Pick one door, do one real task, and judge the loop. The CLI is the fastest way to see the whole agent; Cloud is the fastest way to see it work on code you did not write.

Terminal in a project you own

Requires Node and npm. Run it inside the repository you already work in, so the agent has a real test suite to verify against.

npm install -g freebuff
cd ~/my-project && freebuff

Desktop, for parallel work

Download the macOS, Windows or Linux build, sign in, and open a folder. Start a second tab only when you actually have a second independent task.

freebuff.com → Download

Cloud, for a GitHub repository

Connect a public or private repo, let the sandbox boot, and use the preview URL. Best first task: fix a failing test you did not write.

freebuff.com/cloud

A first prompt that works better than “build me an app”

Name the outcome, the constraint and the proof. The agent can discover files and run commands; it cannot discover what “done” means to you.

The auth test fails about one run in five. Find out why, fix the cause, and prove it by running the auth suite 20 times. Do not mock the session cookie to make it pass.
  • Outcome — a deterministic test, not a silenced one.
  • Constraint — no mocking away the failure.
  • Proof — the suite repeated twenty times.

Habits that pay for themselves

Batch the session

Since a session is an hour with unlimited messages, group related work instead of opening ten short sessions.

Use unmetered models first

Save the 15× and flagship models for the hard reasoning, not for renames and test fixtures.

Read the diff

Review is a subagent, not a substitute for your judgement — especially on auth, payments and data migrations.

Give it a green baseline

An agent verifies much better when the suite already passes and the repo has instructions in AGENTS.md.
