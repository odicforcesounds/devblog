Âmbito deste manual

Este arquivo tem sete páginas que são jogos: um portão com três portas, um labirinto de conhecimento, uma caminhada xamânica, um jogo de palavras e três variações sobre o mesmo tema. Todas foram escritas em HTML e JavaScript sem bibliotecas, e todas reinventaram a mesma peça. Este documento é a peça, escrita uma vez.

Não é um tutorial de framework. É o manual de autor do padrão que já existe no arquivo: um grafo de nós, cada nó com um texto, uma fonte e duas a quatro saídas, um fio que registra o caminho e um botão para voltar. Chama-se-lhe jogo errante porque não tem pontuação, nem nível, nem derrota — só escolha.

Regra zero

Se o jogo precisa de explicar as regras antes de começar, as regras estão mal desenhadas. Em todas as peças deste arquivo, a primeira coisa que o leitor vê é uma porta — não um regulamento.

▸

Um nó, campo a campo

O formato usado em The Turning e na sua gémea A Viragem cabe numa linha de JavaScript. Sete campos, e nenhum deles é decorativo.

O objecto de um nó
CampoTipoO que éExemplo
wstringO mundo: «glifo · lugar». A parte antes do ponto médio é o glifo; a parte depois é onde estás.門 · O portão
gcharO glifo grande desenhado no painel. Um só caractere.門
tstringO título do nó — a frase que o leitor lê como cabeçalho.Um portão sem letreiro
xstringO texto. Três a seis frases. Se precisar de mais, o nó está a fazer o trabalho de dois.Estás onde os três livros começam…
sstringO ficheiro-fonte deste nó. Obrigatório: é o que impede o jogo de ser ficção sem lastro.daoPoemBook.html
nstringO título legível dessa fonte, para o link «de …».O Livro Sexy — Poemas do 道
carrayAs saídas: pares [etiqueta, destino]. O destino especial @random escolhe outro nó ao acaso.[["佛 · Sentar", "b1"]]

O campo s é a decisão de desenho mais importante de todas: cada nó aponta para um documento real do arquivo. O jogo não é um poema solto — é um índice que se percorre.

O motor mínimo

Cerca de quarenta linhas, nenhuma dependência, um fio que se lembra do caminho e um botão para voltar. Este é o esqueleto que os dois jogos gémeos usam. 

var NODES = { /* … */ };
var current = "start";
var thread = [];

function go(id, remember) {
  if (id === "@random") {
    var keys = Object.keys(NODES).filter(function (k) { return k !== current; });
    id = keys[Math.floor(Math.random() * keys.length)];
  }
  if (!NODES[id]) { return; }                 // destino inválido: não avança
  if (remember !== false) { thread.push(current); }
  current = id;
  history.replaceState(null, "", "#" + id);   // estado no URL
  render();
}

function back() {
  if (!thread.length) { return; }
  current = thread.pop();
  history.replaceState(null, "", "#" + current);
  render();
}

function render() {
  var node = NODES[current];
  glyph.textContent = node.g;
  world.textContent = node.w;
  title.textContent = node.t;
  text.textContent  = node.x;

  source.textContent = "";
  var a = document.createElement("a");
  a.href = "./" + node.s;
  a.textContent = node.n + " · " + node.s;
  source.appendChild(document.createTextNode("de "));
  source.appendChild(a);

  choices.textContent = "";
  node.c.forEach(function (pair) {
    var b = document.createElement("button");
    b.type = "button";
    b.textContent = pair[0];
    b.addEventListener("click", function () { go(pair[1]); });
    choices.appendChild(b);
  });
  backBtn.disabled = thread.length === 0;
}

go((location.hash || "#start").slice(1), false);

Três detalhes que parecem pequenos e não são: o destino é validado antes de avançar; o estado vai para o URL, para que um link partilhe o nó e não o início; e o botão de voltar desactiva-se quando o fio está vazio, em vez de desaparecer.

As regras do grafo

Um grafo de trinta e dois nós tem trinta e duas oportunidades de estar errado. Estas cinco regras eliminam quase todos os erros antes de o leitor os encontrar.

  • Sem becos. Todos os nós têm pelo menos duas saídas, excepto um nó final declarado.
  • Sem órbitas. Nenhum nó deve ser alcançável apenas por um caminho de comprimento máximo — isso transforma o jogo num corredor.
  • Sem destinos mortos. Cada alvo em c tem de existir em NODES.
  • Sem ciclos de um passo. Um nó não aponta para si próprio; ida-e-volta imediata só com o botão de voltar.
  • Fonte obrigatória. Todos os nós citam um ficheiro que existe em docs/.

As cinco regras cabem num verificador de vinte linhas, que se corre antes de publicar. Foi assim que se encontrou o erro que deixava o painel vazio: o grafo estava bem, o que faltava era o script chegar ao browser.

O erro que se repete

Em três ocasiões o jogo «não funcionava» e o código estava correcto: o script inline era reescrito pelo Rocket Loader da Cloudflare e a CSP não permitia carregar o substituto. Antes de reescrever o motor, verifica o que o browser recebeu. O caso está documentado em O Arquivo como Sistema.

A escolha do molde é a decisão mais cara de todas: um jogo de grafo com trinta e dois nós custa trinta e dois textos, um por nó; um jogo de tempo real custa uma animação e quase nenhum texto. Escolhe pelo que o leitor deve fazer, não pelo que é mais divertido de programar.

Ritmo: texto, respiração, movimento

Um jogo errante vive de uma tensão: o leitor quer chegar, e o desenho quer que ele pare. Três regras de ritmo resolvem-na.

  • Um nó, uma ideia. Se um nó tem duas teses, são dois nós ligados.
  • A saída mais longa é a certa. Escrever as etiquetas antes do destino força a que cada escolha seja uma frase com vontade própria.
  • O escuro é um lugar, não um tema. Em ambos os jogos, o terceiro mundo é o que não tem letreiro — e é o que dá sentido aos outros dois.

Na tradução, o ritmo é o primeiro a perder-se: um nó de quatro frases em inglês vira seis em português e o painel deixa de respirar. A regra prática é manter o número de frases e cortar adjectivos, não acrescentar orações.

◍

Acessibilidade e teclado

Um jogo de botões é, por sorte, quase acessível de origem. Quatro linhas de cuidado mantêm-no assim.

O mínimo exigível
ElementoRegra
Escolhas<button type="button"> — nunca <div onclick>. Botões recebem foco e Enter de graça.
AnúncioO painel que muda leva aria-live="polite", para que o leitor de ecrã saiba que o nó mudou.
FocoDepois de avançar, o foco vai para o título do nó novo — não para o topo da página.
Movimento@media (prefers-reduced-motion: reduce) desliga as transições do painel e do progresso.
⌁

Estado sem servidor

Não há base de dados, nem conta, nem cookies. O estado do jogo cabe em três sítios, e cada um serve uma coisa diferente.

O URL

#nó guarda onde estás. Partilhar o link partilha o lugar, não o caminho. É o único estado que sobrevive a um marcador.

A memória do separador

sessionStorage guarda o fio completo, para que um refresh não apague a caminhada. Fecha o separador e desaparece — o que é o comportamento correcto.

O histórico do browser

history.replaceState evita que o botão «voltar» do browser e o botão «voltar» do jogo entrem em conflito.

O que não guardar

Nada que identifique o leitor. Não há analytics no jogo, e não deve haver: o percurso é privado por desenho.

Bilingues: dois ficheiros, um grafo

The Turning e A Viragem são o único par do arquivo que partilha os identificadores dos nós, um a um. Isso não é um detalhe de arrumação: é o que permite comparar as duas versões e o que permite testar uma com o verificador da outra.

Regras do par bilingue
RegraPorquê
Os id dos nós são iguais nos dois ficheirosUm link #t1 funciona nas duas línguas
O número de nós é igualQualquer nó acrescentado numa língua é uma dívida na outra
As fontes (s, n) mudam de línguaO jogo inglês aponta para os ensaios ingleses; o português para os portugueses
O tom pode divergir, a estrutura nãoTraduzir não é copiar palavras; é manter o ritmo

Só dois pares de todo o arquivo cumprem esta disciplina. Os restantes traduzem-se reestruturando, o que é legítimo — mas deixa de permitir a comparação. Um registo de pares resolveria isso sem tocar nas páginas antigas.

✓

Checklist de autor

Nove verificações, na ordem em que falham. Se as nove passarem, o jogo abre em qualquer browser sem uma única dependência externa.

  1. O grafo tem um nó start e todos os outros são alcançáveis a partir dele.
  2. Nenhum destino em c aponta para um nó inexistente.
  3. Todos os nós têm s e n, e o ficheiro citado existe.
  4. Nenhum nó tem mais de quatro saídas — mais do que isso é um menu, não uma escolha.
  5. O botão de voltar desactiva no primeiro nó.
  6. O URL guarda o nó actual e um refresh mantém o lugar.
  7. O painel tem aria-live e o foco segue o título.
  8. As transições desligam com prefers-reduced-motion.
  9. A CSP inclui 'self' e o <script> tem data-cfasync="false".
Um jogo sem pontos não pede nada ao leitor. É por isso que ele fica.
