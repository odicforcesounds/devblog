Não existe isso de «qual é a melhor», já que tudo depende de outra coisa que está longe de nós. A melhor é a que te assenta melhor, e isso depende de como organizas os dados e de como vês a lógica nas fórmulas disponíveis que foram desenvolvidas para gerir o que é falso sendo não-falso. Quer dizer, a Virtualização é uma emulação e todas as emulações não são reais como as máquinas físicas são. Enfim, a emulação pode ser fantástica, se não quiseres investir em vários hardwares para criar máquinas dedicadas a algumas soluções específicas de que possas precisar. Por exemplo, nesta minha especificação em particular, precisaria de pelo menos 4 máquinas dedicadas a falar umas com as outras, estando em classes de rede diferentes. Defini-las em classes de IP diferentes é uma opção, e pode ser útil para grandes empresas que precisam de ter «computadores» novos para testar ou desenvolver novas aplicações. Não sou uma empresa e não preciso de testar de forma recursiva todos os detalhes do serviço que quero dar aos utilizadores, mas gosto de pensar nessa possibilidade, que é falsa, e emular essa possibilidade como realidade. Então, como os sistemas BSD usam Jails e os sistemas OpenBSD usam VMs, são mais ou menos iguais no objectivo principal, e vou mergulhar no que torna cada um diferente do outro.

Além do que podemos fazer com estas emulações, no FreeBSD a usar Jails, sabemos que estas máquinas vão usar FreeBSD também. Partilham o mesmo kernel e, com isso em mente, todas as jails usam FreeBSD. Por outro lado, temos o OpenBSD, que usa VMs. Não testei nem explorei muito isto, mas parece que posso criar um isolamento total, incluindo o Sistema Operativo e o Kernel. Com VMs no OpenBSD, parece que é KVM ou QEMU, onde podemos instalar um Sistema Operativo dedicado com todos os detalhes técnicos de que possamos precisar. A partilha de recursos está em quanta memória/cpu/disco usamos para cada virtual-host, que cada um pode gerir com as suas próprias limitações.

O Docker é outra forma de isolar aplicações, mas o Docker também tem problemas de segurança que podem interferir com o host principal, como os ThinJails fazem no FreeBSD.

O processo de criar Jails exige as nossas mãos para produzir todos os detalhes, e com as VMs é igual. Precisamos de especificar todos os parâmetros que vamos usar e, com esses, arrancamos os nossos virtual-hosts. O QEMU e o KVM funcionam como VMs, já que precisamos de criar um sistema de ficheiros para cada máquina virtual. Não é o mesmo para a jail do FreeBSD? Mesmo que seja recomendado criar uma partição zpool para gerir as nossas jails, não sei se criar essa «partição em ZFS» é mesmo necessário, mas admito que o ZFS mudou a forma como vejo as partições de ficheiros, o que é de certa forma confuso para mim, se não entender que o propósito é criar snapshots do conteúdo, para ser possível recuperar ou fazer backups, como o BTRFS é usado em algumas distros Linux como o OpenSuse e outras.

Vou testar todas estas diferenças usando a mesma estrutura de rede, para me ser possível entender as diferenças entre Jails e VMs em desempenho e consumo de recursos. Como podemos especificar quanta memória cada máquina pode usar e quantas CPUs cada máquina pode usar, talvez não haja uma diferença óbvia, mas esse é o meu objectivo para os próximos dias.

Diverte-te a testar a realidade, já que a realidade se diverte a testar-te.

There is no such thing as "which is the best", since all depend on something else that is far away from the self. The best is what sweet you better, while that depend on how you organize data and how you see logic in the avaiable formulas that were developed to manage what is fake, while being non-fake. I mean, Virtualization is an emulation and all emulation are not real, as real, physic machines are. Anyway, emulation can be awesome, if you don't wish to invest in several hardware, to create dedicated machines for some specific solutions that you may need. For example, in this particular specification of mine, I would need at least 4 dedicated machines to talk with each others, while being in different network classes. To define them into different IP classes is an option, and this can be useful for big companies, that need to have new "computers" to test or develop new applications. I am not a company and I don't need to test in a recursive way all the details of the service I wish to give to users, but I like to think about that possibility, that is false, and emulate that possibility as reality. So, since BSD systems use Jails and OpenBSD systems use VMs, they are more or less the same in the main objective, and I will dive into what makes each, different from the other.

Beside what we can do with this emulations, in FreeBSD using Jails, we know that this machines will use FreeBSD too. They share the same kernel and with that in mind, all jails will use FreeBSD. In another hand, we have OpenBSD, which use VMs. I didn't test and explore much about this, but it looks like I can create a full isolation, including Operation System and Kernel. With VMs in OpenBSD, It looks like KVMs or QEMU, which we can install a dedicated Operating System with all technical details we may need. Resource sharing is in how much memory/cpu/disk, we will use for each specific virtual-host, that each can manage with their own limitations.

Docker is another way to isolate applications, while Docker have some security issues too, which can interfere with the main host, like ThinJails do in FreeBSD.

The process of creating Jails needs our hands to produce all details, while VMs is the same. We need to specify all parameters we will use, and with those, we start our virtual-hosts. QEMU and KVM, work like VMs, since we need to create a filesystem for each virtual-machine. Not the same for FreeBSD jail? Evem if is recommended that we create a zpool partition to manage our jails, I don't know if the creating of that "partition in ZFS" is really needed, but I admit that ZFS change how I see FileSystem-partitions, which is somehow confusing to me, if I don't understand that it's propose is to create snapshots of content, to be possible to recover or backup, like the BTRFS is used for in some Linux distros like OpenSuse and others.

I am going to test all this differences using the same network structure, to be possible for me, to understand the differences between Jails and VMs, in performance and resources consuming. Since we can specify how much memory each machine can use and how many CPUs each machine can use, maybe there is no obvious difference, but that is my goal for the next days.

Have fun testing reality, since reality have fun testing you.
