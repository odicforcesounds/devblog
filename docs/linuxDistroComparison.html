Linux Distributions, Compared

Every Linux distribution ships the same kernel and runs the same applications, and yet the experience of using Debian, Fedora, Arch and NixOS is completely different. The differences are not in the programs: they are in who decides what gets installed, when the system changes, and what happens when it breaks. This is a reference to what each family actually does, what it is for, and how the distros inside a family differ from each other.

Before the catalogue, one definition worth carrying: a distribution is kernel + userland + package manager + release policy + installer + support model. The desktop environment is a layer on top (GNOME, KDE Plasma and Xfce are available almost everywhere), and the C library and init system are quietly decisive for compatibility. If you remember the four questions — fixed or rolling, who packages, what breaks, who supports — most of the distro debate answers itself. For a broader tour of reviews and experiments on this blog, see Some Distros that look different, Hard to maintain, Almighty Linux Short Review and Overkill & HardenWing.

The two axes that explain everything

Release model. A fixed distribution freezes a set of package versions, tests them together, and ships a release you can keep for years. A rolling distribution updates continuously: you install once and receive new versions as they are packaged. Fixed means predictable and slow to change; rolling means current and occasionally surprising. There is no third option that escapes this trade-off — every "curated rolling" distro is just rolling with an extra delay.

Package policy. The second axis is who decides what enters the system and how. Binary package managers (APT, DNF, pacman, zypper, xbps, apk) install pre-built packages. Source-based systems (Portage) compile locally and let you choose options per package. Declarative systems (Nix) build the whole system from a description and keep every previous generation on disk. A distribution is, more than anything else, a policy about change.

Two technical layers matter downstream: libc (glibc almost everywhere, musl on Alpine and optional on Void/Gentoo) and init (systemd almost everywhere, OpenRC on Alpine and Gentoo by default, runit on Void, sysvinit-style scripts on Devuan and Slackware). Most incompatibilities people blame on "the distro" are really glibc/musl or systemd assumptions.

Debian and its children

The Debian family is the largest ecosystem in Linux, and its defining property is patience. Debian's stable branch freezes for roughly two years, receives security support for about three, and can be extended further by the LTS team. Packages are built against a single policy document, the social contract keeps the system free, and the result is the distro people install on servers they intend to forget about. Ubuntu, Mint, Kali, MX and dozens of others are variations on this base.

Debian

The reference implementation of stable Linux. Three branches — stable, testing, unstable (sid) — with APT on top. Conservative versions, excellent documentation, no corporate owner, and a community that argues about governance for sport.

APT · fixed · systemd · glibc

Ubuntu

Debian-based, six-month releases and a two-year LTS cadence with five years of standard support (extendable commercially). Adds Snaps, PPAs and its own tooling. The default choice for cloud images and third-party software instructions.

APT + Snap · fixed · systemd · glibc

Linux Mint

Ubuntu LTS base (or Debian, in LMDE) with Cinnamon, MATE or Xfce. Removes Snaps by default, ships a cautious update manager and tools that assume the user should not have to read a wiki to install a printer.

APT · fixed · systemd · glibc

Pop!_OS

System76's Ubuntu LTS derivative, built for their hardware and for people who want a polished desktop without configuration. Adds a recovery partition and its own COSMIC desktop work.

APT · fixed · systemd · glibc

Kali Linux

Debian-based rolling release with hundreds of security tools. It is a toolkit, not a daily driver: the default configuration is deliberately permissive for testing, and using it as a main system trades stability for tool availability.

APT · rolling · systemd · glibc

MX Linux

Debian stable with Xfce, its own MX Tools and systemd optional by default. A pragmatic desktop for older hardware and for users who want Debian without assembling the pieces.

APT · fixed · sysvinit/systemd · glibc

Debian's children differ mostly in defaults and support politics: Ubuntu brings commercial support and newer software; Mint removes Snaps and targets desktop users; Kali inverts the security defaults; MX preserves Debian's stability with a friendlier toolset. The package manager is identical, which is why skills transfer. For the Debian view on this blog, see Debian Forever, Debian, simple and fast, an introduction to APT, and the Debian technical manual for the boot-to-security walkthrough.

The Red Hat family

Red Hat's world is defined by enterprise support and by SELinux. Fedora is the fast-moving community project where the technology is developed; RHEL is the slow, certified, subscription product; Rocky and Alma rebuild RHEL without the subscription; CentOS Stream sits upstream of RHEL as its rolling preview. All use RPM packaging with DNF and default to SELinux enforcing — the single biggest practical difference from the Debian family after corporate support. Both halves of that stack have a manual on this blog: the RHEL technical manual walks the administration track from install to automation, and SELinux, zero to hero goes through contexts, type enforcement and the policy tools.

Fedora

Six-month releases with about thirteen months of support each. New kernels, new GNOME, new Wayland — first. SELinux enforcing, DNF5, and atomic variants (Silverblue) that treat the OS as an image.

DNF · fixed · systemd · SELinux

RHEL

The commercial distribution: ten-year life cycles, certifications, vendor support and predictable backports. You pay for the support contract, not for the software bits.

DNF · fixed · systemd · SELinux

Rocky Linux

A community, bug-for-bug rebuild of RHEL, created after CentOS pivoted to Stream. Same ABI, same packages, no subscription.

DNF · fixed · systemd · SELinux

AlmaLinux

The other RHEL rebuild, backed by CloudLinux. Functionally interchangeable with Rocky for most workloads; the choice usually comes down to governance and funding.

DNF · fixed · systemd · SELinux

CentOS Stream

Rolling preview of the next RHEL minor release. Good for testing and CI against what RHEL will become; not a drop-in replacement for the old stable CentOS people remember.

DNF · rolling · systemd · SELinux

openSUSE and SUSE

openSUSE is the community arm of SUSE, and its distinguishing features are YaST (a system administration tool that predates most of the competition), the zypper package manager, and Btrfs snapshots wired into the bootloader. Leap is the fixed, enterprise-aligned release; Tumbleweed is a rolling distribution with automated testing before each snapshot. When an upgrade goes wrong, the rollback is a boot menu entry — the most underrated safety net in the Linux world.

openSUSE Leap

Fixed releases built from SUSE Linux Enterprise sources. Excellent for workstations and small servers where you want stability plus YaST's centralised configuration.

zypper · fixed · systemd · glibc

openSUSE Tumbleweed

Rolling, but with openQA testing every snapshot and automatic Btrfs snapshots. The most conservative way to run a rolling distribution.

zypper · rolling · systemd · glibc

Arch and its derivatives

Arch is a philosophy as much as a distribution: minimal base install, no defaults you did not choose, rolling packages, and the Arch Wiki — arguably the best Linux documentation ever written, useful even on other distros. pacman is fast and simple; the AUR supplies user-maintained build scripts for almost everything else. The cost is that you assemble the system and you own the breakage. Manjaro and EndeavourOS package the same base with different amounts of hand-holding.

Arch Linux

Rolling, minimal, and explicit: you install what you need, read the wiki, and learn how the system fits together. archinstall now provides a guided installer without changing the philosophy.

pacman · rolling · systemd · glibc

Manjaro

Arch packages held back for extra testing, plus its own tools for kernels, drivers and updates. A friendlier on-ramp that occasionally creates its own compatibility puzzles.

pacman + pamac · rolling · systemd · glibc

EndeavourOS

An Arch installer and a sensible default setup with a small theme layer. Nearly vanilla Arch, without the manual partitioning ritual.

pacman · rolling · systemd · glibc

The independents

These distributions do not share a base with the families above, and that is the point: each one is an argument about how a system should be built. Gentoo argues for compilation and choice; NixOS argues for reproducibility and rollback; Slackware argues for simplicity and tradition; Void argues for minimalism without systemd; Alpine argues for small and secure, which is why it runs inside so many containers. Below all of them sits Linux From Scratch, which is not a distribution at all but the recipe distributions are made from: it builds the toolchain, the C library and the kernel by hand, and it is the fastest way to see what every entry in the table below is actually hiding.

Gentoo

Source-based: Portage compiles packages with the options you select in USE flags. Maximum control and optimisation, paid for in compile time and maintenance attention. OpenRC by default, systemd optional, musl supported.

Portage · rolling · OpenRC · glibc/musl

NixOS

The entire system is a declarative configuration. Upgrades are atomic, every generation stays bootable, and rolling back is selecting an older entry. The learning curve is the price of never having a half-upgraded machine.

Nix · rolling · systemd · glibc

Slackware

The oldest maintained distribution, still shipping a clean, traditional system with BSD-style init scripts and no dependency resolution. You learn what every package does because you install every package.

slackpkg · fixed · sysvinit · glibc

Void Linux

Rolling, lightweight, with runit instead of systemd and the xbps package manager. A clean middle ground between Arch's freshness and a minimal init.

xbps · rolling · runit · glibc/musl

Alpine Linux

musl libc, BusyBox userland, OpenRC, and a whole system measured in megabytes. The default base image for containers; usable as a desktop, unusual as one.

apk · fixed/edge · OpenRC · musl

The differences that actually bite

Upgrades

A fixed distribution upgrades in steps: do-release-upgrade, dnf system-upgrade, or a new ISO and a migration plan. A rolling distribution upgrades continuously, which means a broken update can arrive on a Tuesday. Arch and NixOS both make rollback practical — snapshots or generations — and that safety net changes the risk calculus more than the version numbers do.

Security models

Fedora, RHEL and friends default to SELinux enforcing (the SELinux manual covers what that means in practice). Debian and Ubuntu default to AppArmor, enabled for common services. Alpine and Gentoo are minimal by default and leave the hardening to you. This matters far more than the wallpaper: two systems with the same applications can have completely different mandatory access controls.

Stability versus freshness

Debian stable and RHEL will not give you the newest compiler, and that is a feature: the system is tested as a whole. Arch and Tumbleweed will give you the newest everything, with the understanding that you are part of the testing. Fedora sits in the middle: new technology, predictable short lifecycles. The honest question is not "which is better" but "how much change can my workflow absorb this month".

The same runtime, packaged differently

Python ships on nearly every distribution, and it is the clearest case of packaging policy reaching the user. Debian and Ubuntu mark the system interpreter as externally managed (PEP 668), so pip install refuses to touch it and points you at a virtual environment; Fedora tracks recent versions closely and expects the same discipline; Arch is normally on the newest release; Alpine builds against musl, where many binary wheels do not exist and packages get compiled locally. None of this is a Python problem — it is the distribution's policy surfacing in your terminal. For the long version, from installing Python without wrecking the system to running it in production, see the Python 3 field manual.

Licensing, governance and money

Debian is a community project with a constitution. Ubuntu, RHEL and SUSE have commercial parents whose interests sometimes diverge from users' (Snaps, subscriptions, licensing changes). Rocky and Alma exist precisely because a licensing decision changed a community's plans. Choose a distro with a governance model you are willing to live with, because that model decides what happens in a decade.

musl versus glibc

Alpine's small size comes from musl, and musl is not binary-compatible with glibc. Some pre-built software — including some proprietary tools and language runtimes — simply will not run. This is fine for containers and Go binaries; it is a daily annoyance on a desktop. Void and Gentoo expose the choice explicitly, which is the honest way to present it.

One honest caveat to finish: the distro matters less than the internet believes. The same Firefox, the same Python, the same Flatpak applications and the same containers run everywhere. What changes is package policy, support horizon, defaults and the community you will ask for help. Pick the policy you can live with, learn its package manager properly, and stop distro-hopping when the system starts working. That is usually the moment the operating system becomes boring — and boring is the goal.
