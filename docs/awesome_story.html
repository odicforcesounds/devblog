The Awesome Story

Awesome is not an adjective here. It is a habit: somebody learns something the hard way, writes it down as a list, and leaves the door open for whoever comes next. What follows is one walk through that habit — the terminal, the languages, the machines, the data, the watch, the makers, the school, and the part of life that starts when the laptop lid closes. Every story about computers begins in a rectangle of text with no patience and no pity. The first door is an editor old enough to have opinions: Emacs, which stopped being an editor decades ago and became a way of living inside a keyboard. Beside it sits the shell itself, where Bash turns a sentence into work, and a shelf of terminal applications that each do one small thing well, without asking for a window. Then the terminal starts talking back. There are console services you reach with a single curl — weather, news, a clock, a joke — and the day you stop opening a browser to read the forecast is the day you understand why people stay down here. Nobody memorises all of it: we keep cheat sheets, then a larger and more honest collection of them, and finally a book of secrets passed from engineer to engineer like a family recipe. From the shell you fall into the languages, and the first one is always the oldest: C and C++, where memory is not a metaphor and every shortcut eventually sends a bill. Then the newcomers with the same ambition and better manners — Rust, which lets the compiler argue with you until you are right, and Go, which prefers three clear lines to one clever one. And Python, the language people reach for when they want a result before bedtime. Around them, the rest of the family: Java, still running the world's banks from inside a virtual machine; Ruby, written on purpose to make programmers smile; and TypeScript, which put types on JavaScript and calmed an entire industry in the process. Anyone starting today needs the map before the tools, and learn JavaScript properly is that map: books, exercises, and the order in which to read them. Because the browser quietly became an operating system, Node.js carried the language to the server, React and Angular spent a decade arguing about how to draw an interface, Django proved that a framework can be boring in the best possible sense, Flutter put the same code on phones, and Tailwind CSS turned styling into vocabulary instead of invention. None of that survives without judgement. Design patterns give names to the shapes we keep redrawing by accident; microservices explain what happens when one program becomes twenty; scalability is the long, humbling study of what breaks first. And when the same job repeats itself every morning, it stops being a ritual and becomes an action. Code needs somewhere to live. Docker turned a server into a file you can copy; system administration kept the lights on through the years; and self-hosting, with a full guide for the first server, made it possible to own a corner of the internet instead of renting one. Beyond the rack there is serverless, where the machine becomes somebody else's problem; free software, which is less about price than about permission; tunnels that carry a laptop's service out into the world; a Raspberry Pi on a shelf doing quiet work; and the Mac on the desk, for the days when the work is not the operating system. Underneath, the plumbing: database tools for everything that must not be lost, eBPF for seeing what the kernel actually does while nobody is watching, IPFS for content that addresses itself instead of its host, and HTTP benchmarks for the endless argument about which proxy is really faster. And on top, the seam between systems: the API as a contract, and the developer tools that keep the contract honest from the first mock to the last monitor. Those systems produce data faster than anyone asked them to. To understand how it is kept, there are papers and courses on databases. To get more of it, a crawler and a shelf of web scraping libraries — which is also how you learn what a site does not want you to read. To keep it, web archiving, because a link is not a promise. On the wire it is traffic, and traffic can be read: packet capture tools and network analysis turn a noisy cable into a graph with a shape. Further out, blockchains and coins asked whether trust can be written down, and mostly answered: yes, at a price. Then comes the harder question, which is not storage but cause. Causality algorithms exist for the difference between correlated and responsible; crowd counting trains a model to count people without naming any of them. Everything above can be used well or badly, so someone has to watch. The old name for that job is information security. The way in is learning how hacking works, a pile of resources to read at night, and a course in ethics — because skill without permission is just crime with better tools. The ground floor is the web: web hacking for the attacks, web security for the reasons they work, pentesting for doing it on purpose and on paper, and CTFs for practising against people who also cannot sleep. Reconnaissance is its own craft: Shodan queries for the machines that answer when nobody meant them to, and search engines for hackers that index what the polite ones hide. When something is found it becomes a write-up; the trade has its own tools, Burp extensions for the hands-on part, and on the other side of the argument stand WAFs and API security. Defence is quieter and harder: hardening before the incident, a blue team during it, and threat detection in the logs afterwards. Then the long memory: forensics, reverse engineering, malware analysis, and a collection of JavaScript malware as evidence that the browser is a crime scene too. Some attackers go deeper than the application: Linux rootkits, remote access trojans, and the kernel exploits that turn one bug into a kingdom. Others go sideways, into cellular networks, Android, and the computer that drives the car. At the mathematical bottom sit cryptography and zero-knowledge proofs. At the human top sits privacy, which is mostly the discipline of not giving away what was never asked for. And because this craft is learned by talking, there are recorded talks and red teams paid to be the honest enemy. Then, in the last few years, the machines started writing. Serving a large model became its own discipline — LLMOps — and the thing built on top of it is the agent: software given a goal instead of an instruction. Most of it is still plumbing, which is why so many people start with a workflow builder and a folder of n8n templates rather than with a training run. Someone still has to make the thing look as if it were made on purpose. CSS is the vocabulary; design systems are the grammar; design tools are the workshop; and style guidelines are what stops five people from inventing five ways to write the same function. Under all of it, the spellbook of modern web development — the map that shows which of the thousand tools you actually need. And two small acts of decency: web apps that work without an account, and a privacy policy written in a language a person can read. None of this is learned alone. There are university courses online and free, and for the security path a whole free curriculum plus the labs where knowledge stops being theory. For the first step there is a list of projects that label issues for beginners — the single most useful page on the internet for anyone who has just finished a tutorial. Then come the interview questions that await, the ideas for what to build next, and an A to Z of resources for students. Work itself has changed shape: remote jobs, people coding live, channels worth the bandwidth, and newsletters for the weeks when reading code is easier than reading blog posts. And for the days when code is not enough, creative coding, where the output is not a feature but a picture. The lid closes. There are films about hackers (almost none of them true), music software for people who hear in patterns, and sushi, which is a technology of its own. There is money that should outlive the month, and — the part the industry keeps forgetting — mental health, which is not a productivity feature. There are free applications that ask for nothing, games whose source you can read, and a list of Android apps chosen for freedom rather than for advertisements. That is the whole walk: a person, a terminal, a language, a machine, a network, a watch, a model, a design, a school, and a life. The lists are the footprints of everyone who went first, and Awesome is only the name we gave to leaving them behind for the next person. All of them, sorted by subject with one line each: the Awesome Index.
