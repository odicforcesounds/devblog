Os programadores do OpenBSD são programadores, não hackers

Com base neste artigo, onde digo que os programadores do OpenBSD são Hackers, há algo que provavelmente não é totalmente verdade, já que são programadores preocupados com segurança, não hackers preocupados em explorar a segurança. Talvez os programadores do OpenBSD que leram o artigo não tenham gostado de ler a minha opinião; como sou um NOOB, eles podiam entender que noobs como eu estão por todo o planeta a dizer algo «estúpido», que pelo menos para eles não é verdade.

Na minha experiência de Noob, os Hackers são pessoas Criativas que conseguem ser criativas em vários assuntos. Da Tecnologia à Mecânica, Electrónica, Física, Arte e muitos outros assuntos que existem neste mundo feito por humanos. Mas, de facto, os programadores do OpenBSD tentam definir os princípios do seu estilo de programação dizendo: «Corrige o Bug antes de os Hackers o encontrarem». Por isso não gostam de se ver como «hackers», talvez porque associam o termo «Hacker» a actividades Maliciosas e, por isso, usar o termo para falar de quão Fantástico o OpenBSD é ao nível do Sistema Operativo e da Pilha de Rede é algo que este grupo não gosta de ler de ninguém (não só nos meus artigos).

Na conferência e nos cursos DEF CON, o conhecimento defensivo faz parte do que é hacking, tal como as abordagens Ofensivas. Os últimos ficheiros da DEFCON de 2025 já estão online para descarregar e explorar, e muitos outros Recursos que qualquer pessoa pode explorar, enquanto as inscrições para os eventos do próximo ano já estão abertas, para Singapura.

Enfim, a comunidade OpenBSD podia gostar de ser visada por outros grupos que focam a intenção em explorar o código dos outros, criando juntos um ciclo saudável, onde uns se focam no código defensivo e os outros tentam explorar o código que aplica as recomendações para ser seguro, como o OBSD faz. Pessoalmente comecei a usar o OpenBSD como o meu Router principal, pondo o OBSD em Bridge Mode e aí controlo todo o tráfego que entra ou sai. Gosto mesmo deste sistema que aplica todas as funcionalidades de segurança por Omissão, o que é perfeito para quem deseja usar um Sistema Operativo Seguro sem saber demasiado sobre os detalhes técnicos necessários para criar um sistema seguro. Se quiseres usar o OpenBSD como desktop, podes querer mudar as configurações predefinidas, mas isso leva-te a definir o sistema numa direcção totalmente diferente: quanto é que não precisas de todas as funcionalidades de segurança implementadas por omissão, ao removê-las ou alterá-las.

OpenBSD developers are developers, not hackers

Based on this article, where I say that OpenBSD developers are Hackers, is something that probably is not totally true, since they are developers concerned about security, not hackers concerned on exploiting security. Maybe OpenBSD developers who read the article didn't like to read my opinion, while I am a NOOB, they could understand that noobs like me, are all over the planet, saying something "stupid", that at least for them, is not true.

In my Noob experience, Hackers are Creative persons that can be creative in several subjects. From Technology to Mechanics, Electronic, Physics, Art and many other subjects that exist in this world made by humans. But in fact, OpenBSD developers try to define their coding style principles saying: "Fix the Bug before Hackers can find them". So, they don't like to see themselfs as "hackers", maybe because they associate the Term "Hacker" to Malicious Activities, and therefor, using the term to talk about how Awesome OpenBSD is at OS and Network Stack levels, is something that this groups don't like to read from anyone (not only on my articles).

On the DEF CON conference and courses, defensive knowledge is part of what hacking is, like the Offensive approach's are. The last DEFCON files from 2025 are already online to download and explore, and many other Resources that anyone can explore, while the registration for the next year events are already open, for Singapore.

Anyway, OpenBSD comunity could like to be targeted, from other groups that focus their intention to exploit others code, creating together a healthy cycle, where ones focus on the defensive code and the others, trying to exploit the code that apply of the recommendations to be secure, like OBSD does. Personally, I start using OpenBSD as my Main Router, putting OBSD in Bridge Mode and there I control all traffic that goes in or out. I really like this OS that apply all the security features by Default, which is perfect for those who wish to use a Secure Operating System, without knowing too much about the technical details that are needed to create a secure system. If you wish to use OpenBSD as a desktop, you may wish to change the default configurations, but this will take you to define the OS in a totally different direction. How much you don't need all security features that are implemented by default, by removing or changing them.
