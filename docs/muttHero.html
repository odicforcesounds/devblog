01From nothing

mutt is a terminal email client with a slogan older than the dot-com bubble and still true: “All mail clients suck. This one just sucks less.” It was written in 1995 by Michael Elkins, forked decades later into neomutt, and remains the email program people reach for when they finally want to triage their inbox faster than a pointer can move.

  • It is keyboard-native. Every action is a key; every key is a line in your config. Nothing hidden behind a hamburger.
  • It reads anything. Local mbox, local Maildir, remote IMAP; mutt does not care, which is why it works with any provider's storage.
  • It sends through anything. A local mail server, its own SMTP client, or your provider's submission port — same interface, three backends.
  • It is composable with the rest of the terminal: mutt + w3m for HTML, notmuch for corpus-scale search, your real editor for composing.
$ doas pkg_add mutt       # BSD-style package naming
# Debian/Ubuntu-style: apt install mutt  (neomutt is the fork with extra patches)
Note: vanilla mutt and neomutt share the config language; this page exists in both worlds and every line below opens in both. Where a feature is fork-only, the page says so — and those are extras, not the road.

02First mail, first keys

Start mutt against something real. If you have mail lying in a local Maildir already:

$ mutt -f ~/Mail/INBOX   # open a specific mailbox
$ mutt -y               # open the mailbox browser (see section 04)

And the first keyboard vocabulary — small, and it never changes:

KeyMoves
j / k (and arrows)Down / up through messages or entries.
<Enter>Open the message (pager view).
qClose current view (pager → index; index → quit).
cChange mailbox (see = and ? expansion below).
d / uMark deleted / undelete (a D in the index; real purge at exit).
sSave message to a mailbox (copy+delete in one move).
r / g / LReply / group (all) reply / list reply.
vView attachments of the message.
?Show the whole key map in this context. Use it; it is a manual living inside the program.
Note: in mailbox-name prompts, = expands to your folder value (=Sent is ~/Mail/Sent) and ! is your spoolfile. That shorthand is why config lines below look so short.

03The configuration files

mutt reads, in order:

  1. /etc/Muttrc (or /etc/muttrc) — the system-wide base; you rarely touch it.
  2. ~/.muttrc (or ~/.config/mutt/muttrc) — everything of yours lives here.
  3. Any other file you source from those two — and that is where multi-account life (section 05) comes from.

The nothing-to-something core, six lines, no account yet:

# ~/.muttrc — the spine
set mbox_type  = Maildir          # maildir > mbox: one file per message
set folder     = ~/Mail           # the root all =names expand into
set spoolfile  = =INBOX           # the default mailbox mutt opens
set record     = =Sent            # copies of what you send
set postponed  = =Drafts          # where postponed drafts live

And create the Maildir directories on disk (a shell line, not a mutt line):

$ mkdir -p ~/Mail/INBOX ~/Mail/Sent ~/Mail/Drafts ~/Mail/Archive
Note: to check your own bindings at any time: ? in the compose screen shows that context's key map, and :set ?postponed echoes the value of a variable. Between those two answers, no config question stays unanswered while mutt is open.
Warn: do not copy a stranger's 900-line muttrc before you have your own six lines working. Borrowed configs are how people end up mutt users with no idea why mail moves. Grow yours sideways (sections 04–09), one block at a time.

04One box, many mailboxes

The multi-email box starts with a declaration: which mailboxes exist and which show in the browser. Then every folder gets its own behaviour:

# ~/.muttrc — declare the landscape
mailboxes =INBOX =Sent =Drafts =Archive
mailboxes =lists/mutt                     # lists live in a subtree, declared like the rest

# behaviour per folder
folder-hook .          "set sort=threads"         # everywhere: threads
folder-hook =lists.*   "set sort=date-received"   # lists: pure chronology

Note the honest limit: mutt does not create folders for you on disk; the mkdir from section 03 done once is why =INBOX resolves.

The browser

  • mutt -y opens a list of every mailboxes line with unread counts.
  • Move with j/k, open with Enter; same keys as everywhere.
  • New folders? Add one mailboxes line; the browser follows.
Note: Maildir folders are directories of files, so you can point any plaintext tool at them while mutt has them open. That property is the quiet superpower of the storage format (and the reason mbox gets dropped by everyone who survives a crash once).

05Many accounts, one muttrc

The multi-account pattern is one account-hook (fires when the account is selected) plus per-account files laid out like documents, sourced by the spine:

# ~/.muttrc — the hub
account-hook $fastmail  "source ~/.mutt/fastmail.conf"
account-hook $workmail  "source ~/.mutt/work.conf"

folder-hook  fastmail.com.*  "source ~/.mutt/fastmail.hooks"
folder-hook  work.example.com.*  "source ~/.mutt/work.hooks"
mailboxes ! "imaps://imap.fastmail.com/INBOX" "imaps://imap.work.example.com/INBOX"

Each account file carries its own identity, server pair and signature, and declares its own set lines — a mini-section-03, plus the network pair of sections 06–07:

# ~/.mutt/fastmail.conf — account template
set from       = "you@fastmail.com"
set realname   = "Your Name"
set imap_user  = "you@fastmail.com"
set imap_pass  = ""                        empty = prompt; see the gpg line below
set folder     = "imaps://imap.fastmail.com/"
set smtp_url   = "smtps://you@fastmail.com@mail.messagingengine.com"
set signature  = "~/.mutt/signature.fm"

# secrets, decrypted at machine startup — never committed anywhere
source "gpg -q --for-your-eyes-only --no-tty -d ~/.mutt/fastmail.gpg |"
Warn: account-hook fires on operations (opening a folder, sending), not at startup. If both accounts share secrets in plain set lines, the last file sourced wins at the worst moment. The fix is discipline: per-account files, sourced by hook, never by the spine directly.
Where do passwords belong?
Not in the file you keep in git. Either way, one thing stays out of the muttrc you keep in git: the password. The classic is a gpg-decrypt-in-flight source "gpg -d ~/.mutt/secrets.gpg |" line that sets imap_pass and smtp_pass at startup; otherwise mutt will simply prompt you, per account, per session..

06IMAP: reading from a distance

Point folder at an imap(s):// URL and mutt becomes an IMAP client: the mailbox browser lists folders straight off the server, and = names still expand against it.

# ~/.muttrc — IMAP core
set imap_user     = "you@example.com"
set imap_pass     = ""                      # empty = prompt; or sourced from gpg
set folder        = "imaps://imap.example.com/"
mailboxes         =INBOX "imaps://imap.example.com/OtherFolder"

The server-politeness knobs, safe as written:

set imap_check_subscribed = yes     # trust the server's folder list
set mail_check      = 60            # imap poll interval, seconds
set imap_peek       = yes           # do NOT auto-mark as read on list
set imap_keepalive  = 300           # keep NAT/freewalls open during long reads
Note: first connect to a new server prints a certificate prompt — read it (fingerprints are the whole point of TLS), accept once, and it is cached. If your provider's certificate chain is normal, this is a once-per-machine moment.

07SMTP: sending without fear

mutt can hand finished mail to your provider directly, skipping any local MTA:

# ~/.muttrc — direct submission
set smtp_url        = "smtps://you@example.com@mail.example.com:465"
set smtp_pass       = ""                        # prompt or gpg, like imap_pass
set from            = "You <you@example.com>"
unset write_bcc                       # do not leak Bcc to the wire; server handles it
  • smtps:// = implicit TLS on port 465. smtp://...:587 = STARTTLS on the submission port. Prefer smtps when a provider offers both; both are fine.
  • If smtp_url is unset, mutt falls back to the local sendmail -compatible binary — and that is the second, classic route:
# ~/.muttrc — delegate delivery to msmtp (config lives in ~/.msmtprc)
set sendmail = "/usr/bin/msmtp"
Note: pick one route per account and leave the other unset. When both are configured, debugging "why did this mail take the weird path" becomes a zebra hunt. The direct smtp_url route is the one this page recommends for laptops; the sendmail route belongs on the server that already has an MTA.

08Providers, Gmail included

Provider recipes are thin layers over what sections 06–07 already taught. Three common ones:

ProviderIMAP folderSMTPKVR (ligatório read)
Gmail imaps://imap.gmail.com/INBOX smtps://smtp.gmail.com:465 Gmail wraps IMAP in labels; special folders are literally [Gmail]/-prefixed.
Fastmail imaps://imap.fastmail.com/ smtps://mail.messagingengine.com Plain IMAP service; server-side Sent tracked by your record.
Any ISP / work server imaps://imap.example.com/INBOX smtps://mail.example.com Same three lines; differences are only the values and the names server-side.

Gmail, the whole truth

# ~/.mutt/gmail.conf
set from              = "you@gmail.com"
set imap_user         = "you@gmail.com"
set folder            = "imaps://imap.gmail.com/"
set spoolfile         = "imaps://imap.gmail.com/INBOX"
set record             = "imaps://imap.gmail.com/[Gmail]/Sent Mail"
set trash              = "imaps://imap.gmail.com/[Gmail]/Trash"
set smtp_url           = "smtps://you@gmail.com@smtp.gmail.com:465"
set imap_check_subscribed  = yes
set imap_list_subscribed   = yes

And the three truths of the label reality (because Gmail is IMAP-wrapped, not native IMAP):

  • Labels are not folders. A message lives in [Gmail]/All Mail and may also appear under any label. mutt browses labels as if they were folders, but deleting manipulates labels, not atoms.
  • Delete means archive or trash — your choice. With trash set above, plain d respects the Trash. For real archive behaviour add a macro that saves to [Gmail]/Archive instead. Decide once; both are one line.
  • Sent lives server-side. Gmail's web UI auto-files every send; point your record at [Gmail]/Sent Mail and both worlds will agree by pointing at the same place.

Authentication is its own paragraph, because Gmail is the most common wall: normal password login requires an app password when 2FA is enabled (it should be). The app password is generated in the provider's security settings and behaves like a normal password string, which makes it a perfect fit for the gpg-sourced file from section 05.

Warn: do not keep 2FA-disabled mail accounts "just for mutt" no matter how convenient; the app password path is the supported one. Also note that a bare mutt without IMAP+SMTP support compiled in (check mutt -v) cannot talk to any provider here — your package choice matters.
Warn: do not ever keep 2FA-disabled Gmail accounts "just for mutt". The app password path is the supported one; a 2FA-less account is a weaker target, and your inbox is the key to every other account you own.

09Colors like a command line deserves

mutt colors objects, not widgets: bundles such as normal, hdrdefault, quoted, signature, indicator, index. Syntax: color OBJECT foreground background [pattern], with default meaning "terminal's own".

# ~/.muttrc — a complete, calm, dark start
color normal          white    default
color hdrdefault      cyan     default
color quoted          green    default
color quoted1         brightgreen  default
color signature       blue     default
color attachment      yellow   default
color search          black    brightyellow
color indicator       black    brightgreen
color status          white    blue
color tilde           brightwhite default
color tree            magenta  default
color error           red      default
color message         white    green
color markers         red      default

All of those, as they would land on your dark terminal (CSS speaking for the terminal palette):

normal hdrdefault quoted signature attachment indicator status error

And the two object+pattern powers that separate a scheme from decoration:

# unread messages scream softly
color index  brightwhite  default  "~N"
# your own outgoing mail, dimmed
color index  blue        default  "~P!~F"
Note: 256-color identifiers also work (color normal color252 default); default keeps the terminal's own. Test choices by eye, live, with :color ... typed straight into the pager — no reload ritual required: it is what resource files wish they were.

10Patterns: the search superpower

l (limit) collapses the index to a sub-world;Everything else — color, hook, save, archive — reuses the same small grammar:

PatternMeansExample limit
~Nnew/unreadl ~N → only what waits for you
~f user@hostfroml ~f butter@club.tld
~t user@hostto (you included)l ~t me@tld
~s wordssubject containsl ~s "invoice"
~F / ~Dflagged / deletedl ~F
!patternnegation — "does not match"l !~s "cron"
&, |, (...)Boolean and / or / groupingl (~N & ~f boss@work.tld)

Where it earns with interest:

  • color index ... pattern — the colors in section 09 are pattern-driven.
  • T (tag-pattern) + ; (apply next command to tagged) turns inbox-zero into arithmetic, not patience: one pattern, everything matching, one key, ruined in bulk or filed in bulk.
  • The same notation is mutt's single search language; there is no second one to learn for hooks, colors, limits and tags — which is rare and lovely.
Note: the full grammar lives in muttrc(5), under "Patterns". Keep that man page handy; it is the accidental second manual for the whole program.

11Keys and macros worth stealing

mutt has bind (one key, one named function) and macro (one key, a symphony of virtual keypresses). The handful worth more than their line-count:

# ~/.muttrc — quality of life (mutt 1.11+ has the sidebar built in)
set sidebar_visible     = yes
set sidebar_width       = 24

# b toggles the sidebar in both index and pager
macro index,pager b "<enter-command>set sidebar_visible=!sidebar_visible<enter>"

# Tab jumps to the next mailbox with unseen mail
bind index \Ct          <sidebar-next>

# one key to archive: save to =Archive, mark deleted in place
macro index,pager a "<save-message>=Archive<enter><delete-message>"

# G runs fetchmail-style helpers, if you have one; delete the line if you do not
macro index G "<shell-escape>fetchmail</shell-escape><refresh>"
Note: the purpose of the macros above is to teach the shape: macro context keys "actions", actions as if typed in the interface wrapped in <...> function names. Start by simulating your last three manual actions; that is the macro list you actually need, custom-made by your own hands.
Warn: two macro-writers' hazards: what genuinely bites is shadowing a default key you use without remembering (bind b away and mutt will never warn), and a macro that fires the wrong context because you forgot the index,pager prefix. When odd behaviour appears, suspect your binds before the program's soul.

12Hero vocabulary

The command-line flags and one-liners that finish the road:

SpellWhat it does
mutt -yMailbox browser — the launcher for your whole declared world.
mutt -f =Archive/2026/octOpen one specific mailbox straight away.
mutt -F ~/.mutt/minimalAlternate config entirely — the clean-room test for debugging your own muttrc.
mutt -nSkip the system-wide config; isolate user settings only.
mutt -RRead-only open; inspect an archive with zero risk of touching it.
mutt -pResume the postponed draft (or bind your own key).
mutt -s "subject" -a f1.pdf -- dest@hostSend from the shell; the classic receipts-and-scripts companion.
mutt -H draft.txtSend a pre-written draft file — cron and templating fuel.
mutt -e "set editor=vi"One-shot config override, like -xrm in xterm.
mutt -vVersion + features, incl. IMAP/SMTP support; check before cursing a missing compile.
Note: the man pages that finish a hero: mutt(1) (flags), muttrc(5) (every variable and every pattern), and the project's own manual page online if you want the full tutorial voice. Between these sections and those, you are set.
Note: and the meta-skill this whole page built: mutt rewards dictating the exact two lines that fix today's annoyance, then stopping. Hoarding muttrc folklore is the fastest route to forgetting why anything works.
