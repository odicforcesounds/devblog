Implicações do nome lógico: a fonte é a resposta

Conhecidas popularmente como TUIs, [Terminal User Interface], as aplicações podem ter várias opções num estilo de menu, que simplifica o que é complexo.

Gosto mesmo de SUI [Shell User Interface]:
Um Terminal é uma interface gráfica para aceder à Shell. Portanto, o nome das TUI está **Errado**.

Para instalar qualquer sistema Linux/BSD tens sempre alguma SUI [Shell User Interface] a guiar-te e a simplificar o teu trabalho, pedindo as opções necessárias que precisas de configurar. Uma SUI semelhante é a do make menuconfig ao compilar o Kernel Linux.

Mesmo que as Interfaces de Utilizador acima usem uma biblioteca chamada Dialog, as SUI são a melhor escolha para uso mínimo. Por isso tive esta ideia: em vez de usar WUI [Web User Interface] para gerir Sistemas, as Gerações Futuras deviam usar SUI para configurar o servidor num estilo elegante.

Não sei nada de programação, mas na minha ignorância diria que os programadores só precisam de acrescentar uma opção gráfica a cada opção que qualquer serviço a correr naquela máquina possa ter. Mesmo que penses que, com esta abordagem, os utilizadores não vão ler a man page, na verdade simplifica o tempo de trabalho deles, porque só precisam de seleccionar [x] as opções correctas para eles e escolher a opção [ar](Apply & Restart) Service.

Com SUI, as ligações são protegidas apenas por SSH.

Logic Name Implications: The Source is the Answer

Popular known as TUIs , [Terminal User Interface], applications can have several options in a menu style, which simplify what is complex.

I really like SUIs [Shell Users Interfaces]:
A Terminal is a Graphical interface to access the Shell. So, the name of TUIs is **Wrong**.

To install any Linux/BSD system, you always have some SUI [Shell User Interface] to guide you and simplify your work, asking the necessary options that you need to configure. A similar SUI is from make menuconfig when compiling the Linux Kernel.

Even if the above User Interfaces use a library called Dialog, SUIs are the best choice for minimal usage. Therefor, I had this idea where, Instead of using WUIs[Web User Interfaces] to manage Systems, Future Generations should use SUIs to configure the server in a fancy style.

I know nothing about coding, but in my ignorance I would say that developers, only need to add a graphical option to each option that any service running on that box, can have as an option. Even if you think that, with this approach users will not read the man page, in fact will simplify their work time, because they just need to select [x] the correct options for them, and select option [ar](Apply & Restart) Service.

With SUIs, connections are secured with SSH only.
