OpenBSD is not an OS.
It is a fortress with a pufferfish.

Born in 1995 from Theo de Raadt's refusal to compromise, OpenBSD made proactive security, correctness and full disclosure its religion. While the rest of technology drowns in buffer overflows, ROP chains, supply-chain backdoors, Meltdown/Spectre and misconfigured firewalls — OpenBSD quietly answered every one of them, years in advance, in the base system, enabled by default.

02

Philosophy: correctness is security

OpenBSD's famous slogan is not marketing — it is the output of a fanatical engineering culture led by Theo de Raadt since the 1995 NetBSD fork.

Simplicity

No knobs you don't need

One pf.conf, one rcctl, one base. Fewer code paths = fewer bugs. OpenBSD will break compatibility to delete a bad API — see strlcpy replacing strcpy everywhere.

Ref: innovations · style(9)

Proactive audit

Fix it before it's a CVE

Since 1996, file-by-file audits of the whole tree, re-audited as new bug classes are learned. Thousands of overflows, races and leaks fixed in 1996–97 alone. Bugs fixed even without a PoC.

Ref: security.html

Full disclosure

No security-through-obscurity

Advisories, errata and fixes published fast and publicly. Admins can assess real risk instead of waiting for a vendor PR statement.

Ref: errata · CERT VU#986425

Free & documented

Man pages are law

Every syscall documented, every change updates the man page. style(9) enforces readable code so review is possible. Ports build as non-root.

Ref: faq1 · ports FAQ

“We overhaul components even at the cost of compatibility, look for the same mistake elsewhere after finding one flaw, and use mitigations to make bugs harder to exploit.” — Theo de Raadt, 2006 interview
03

Timeline: first in the world, again and again

OpenBSD didn't follow hardening trends — it invented them. Use the filter to tour the arsenal.

1996 — The Great Audit begins

File-by-file review of the entire source tree. Thousands of buffer overflows, protocol bugs, info leaks fixed. The foundation of everything. security.html

1999 — OpenSSH born

Clean, separated, audited SSH from OpenBSD. Now the world's SSH. First with privilege separation (2002, 3.2). OpenSSH security

2001 — PF packet filter (3.0)

Readable, stateful, normalizing firewall replacing ipf. SYN proxy, scrub, queues. PF Guide

2003 — W^X + ProPolice (3.3/3.4)

First OS with W^X on multiple arches and ProPolice stack protector system-wide by default. Memory not writable and executable. innovations

2003 — ASLR by default (3.4)

First widely-used OS with ASLR on by default. Later: PIE everywhere (5.3), randomized malloc + library order. innovations

2008–2014 — strlcpy · reallocarray · hardened malloc

Safe string APIs exported to the world; overflow-checked reallocarray(), freezero(), canaries, guard pages, junking. malloc(3)

2014 — LibreSSL fork (5.6)

After Heartbleed, OpenBSD forked OpenSSL, deleted 150k+ lines, modernized. Primary dev in base. libressl.org · 5.6

2015 — pledge(2) (5.9)

One syscall to irreversibly drop power: pledge("stdio rpath", NULL). Hundreds of base programs pledged. pledge(2)

2016 — W^X strict + KARL preview (6.0/6.2)

W^X strictly enforced (wxallowed opt-out); KARL relinks kernel at every boot — new kernel layout each reboot. 6.0 · 6.2

2018 — unveil(2) (6.4) + RETGUARD + Spectre/Meltdown suite

Filesystem sandbox + return-address cookies + retpoline, SMT-off-by-default, L1TF fixes in one release. unveil(2) · 6.4

Today — signify + syspatch + vmm + wireguard

Signed everything, one-command patches, audited hypervisor, modern VPN in base. signify paper

04

Deep dive: the mitigations, explained like an exploit dev

Each feature below is a wall. Alone it slows you; stacked, they break entire exploit methodologies. Click any wall to open its internals, code and sources.

What: a process declares which syscall groups it needs — e.g. stdio rpath wpath cpath inet dns — and the kernel kills it (SIGABRT) if it ever touches anything else. Promises can only shrink, never grow. A compromised httpd parser that pledged stdio rpath cannot exec, open sockets, or ptrace — the exploit dies inside the sandbox it built itself.

/* httpd render path: after parsing config, drop everything */
#include <unistd.h>
if (pledge("stdio rpath", NULL) == -1)
    err(1, "pledge");
/* from here: no exec, no socket, no prot_exec — RCE becomes DoS */

Why secure: moves policy into the program where intent is known; tiny API (one call) so adoption is massive — 500+ base programs pledged. Combines with unveil for least privilege in two dimensions.

Sources: pledge(2) manual · innovations · sshd + privsep

What: grant visibility to only chosen paths with chosen rights (rwxc), then lock: unveil("/var/www","r"); unveil(NULL,NULL). Everything else returns ENOENT — directory traversal, /etc/passwd reads, key theft all fail closed. Perfect pair: pledge limits what calls, unveil limits what files.

/* static file server: see only /var/www, read-only */
unveil("/var/www", "r");
unveil("/var/www/logs", "rwc");
if (pledge("stdio rpath wpath cpath", NULL) == -1)
    err(1, "pledge");
unveil(NULL, NULL);  // lock: no more unveil calls

Sources: unveil(2) · innovations

What: since 3.3, strict by default in 6.0: no page may be WRITE+EXEC. Classic shellcode injection (write bytes → jump) faults. JITs must be explicitly marked and live on wxallowed mounts — visible, auditable exceptions. Forces attackers from easy code-injection to hard code-reuse (ROP), which RETGUARD+ASLR then punish.

Sources: 6.0 release · upgrade60 + wxallowed · innovations

What: first mainstream ASLR by default (3.4); PIE everywhere (5.3); stack, heap, mmap, libs and even mmap gaps randomized per-exec. No fixed system() address to return to — attacker needs an info-leak + bypass per boot, per process. Combined with W^X, the classic ret-to-libc recipe collapses.

Sources: innovations

What: Kernel Address Randomized Link (6.2): at boot, kernel objects are re-linked in random order; /bsd unreadable to users so layout stays secret. Kernel ROP needs a fresh info-leak each reboot — persistence dies. This is boot-time kernel randomization, beyond process ASLR.

Sources: 6.2 release · innovations

What: ProPolice system-wide since 3.3 (world first); RETGUARD replaces classic cookies with per-function random cookies guarding return addresses, plus stack-pivot checks and gadget reduction. Overwrite a return address and the function epilogue aborts before the ret executes.

Sources: innovations · 5.6 notes · 6.4 notes

What: OpenBSD's allocator (by Otto Moerbeek): randomized placement, guard pages on large chunks, canaries, delayed free + protected freed pages, junk fill, aggressive abort on double-free/UAF. Plus safe APIs the world copied: reallocarray() (overflow-checked multiply), recallocarray(), freezero(ptr,len) (zero secrets before free), strlcpy/strlcat.

/* vulnerable: n * sz can wrap → tiny alloc → overflow */
p = malloc(n * sz);               // BAD
p = reallocarray(NULL, n, sz);    // GOOD: aborts on overflow
freezero(secret, secretlen);      // GOOD: scrub then free

Sources: malloc(3) · reallocarray(3) · innovations

What: pioneered in OpenSSH (2002): split daemons into a tiny privileged monitor + big unprivileged worker. Pre-auth network parsing runs as nobody in a chroot; the monitor only answers vetted requests. Later spread to bgpd, dhcpd, pfctl and dozens more. Even root bugs become nobody bugs.

Sources: innovations · sshd(8)

# /etc/pf.conf — default deny, scrub, synproxy
set skip on lo
match in all scrub (no-df random-id max-mss 1440)
block all
pass out quick inet proto { tcp udp icmp } keep state
pass in on egress proto tcp to port 443 \
    flags S/SA synproxy modulate state
pass in on egress proto tcp to port 22 \
    flags S/SA keep state (max-src-conn 5, overload <brute> flush)

Stateful, normalizing (scrub defeats OS-fingerprint + fragmentation tricks), SYN-proxy absorbs spoofed floods, sequence modulation, tables + anchors, ALTQ queues. Default-deny culture, not default-allow.

Sources: PF User's Guide · filtering

What: born in OpenBSD 1999, privilege-separated since 2002. Secure defaults: protocol 2 only, privilege separation + sandboxing on, weak ciphers/MACs pruned aggressively, sshd_config safe out of the box. Its security page lists every vuln transparently — the honesty competitors hide.

Sources: OpenSSH security · sshd(8)

What: 2014 fork after Heartbleed: removed 150k+ lines of compat cruft, aggressive cleanup, modern APIs (libtls), pledge/unveil inside, developed in-tree then ported. Goal: a TLS stack you can actually audit.

Sources: libressl.org · 5.6 release

$ signify -Cp /etc/signify/openbsd-78-base.pub \
    -m SHA256.sig -x SHA256
$ syspatch   # fetch, verify, install base patches
$ pkg_add -u # signed packages (no extra verify step needed)

Every release + patch signed with small, auditable Ed25519 tooling. syspatch closes the “I know, I'll reboot later” gap with binary patches.

Sources: signify paper · syspatch(8) · ports FAQ

What: 6.4 shipped Meltdown PTI, retpoline (Spectre v2), SpectreRSB, L1TF, eager FPU — and disabled Intel SMT/Hyper-Threading by default because shared-core speculative state leaks across threads. Plus getentropy(2)/arc4random(3): never-fail, always-seeded randomness (no Debian-OpenSSL déjà vu).

Sources: 6.4 release · faq10 SMT · getentropy(2)

What breaks attackers

The stack that breaks methodologies

  • W^X + RETGUARD + ASLR: kills write→jump shellcode, then kills the ROP fallback.
  • KARL: kills kernel-exploit persistence across reboots.
  • pledge + unveil + privsep: turns code-exec into a sandbox with no exec, no network, no files.
  • malloc + strl*/reallocarray: shrinks the bug pool itself — fewer overflows to start from.
What doesn't make it invincible

Honest limits (read this)

  • Logic bugs, misconfigurations and enabled services are still on you.
  • pledge/unveil only help if developers use them correctly.
  • Speculative-execution fixes are arch/CPU-dependent.
  • Third-party ports are not fully audited — OpenBSD says so itself.

Ref: security.html · ports FAQ

07

Network & crypto trinity: PF · OpenSSH · LibreSSL

pf(4) · in-kernel

Filtering, NAT, normalization, queues — one grammar

PF scrubs packets (reassembles, normalizes IDs/TTLs) so NIDS-evasion and fingerprinting tricks die at the border; stateful keep state, synproxy for spoofed SYN floods, modulate state for weak ISNs, tables for brute-force jails, anchors for apps (authpf, ftp-proxy), ALTQ for bufferbloat-free shaping. Readable enough to audit — powerful enough to run ISPs.

Full guide: PF User's Guide · filtering · pf(4)

OpenSSH · since 1999

Privilege separation before it was cool

Pre-auth parsing as unprivileged sandboxed child; monitor holds keys. Protocol-cleanups (legacy ciphers removed fast), VerifyHostKeyDNS, DisableForwarding, sandbox pledges per platform. Every vuln published at openssh.org/security — compare that honesty to vendors who silently patch.

LibreSSL · since 2014

Fork, delete, harden, repeat

Forked a month after Heartbleed; removed Windows/Mac cruft, custom memory pools, arc4random everywhere, libtls — TLS in ~10 calls instead of 200 lines of OpenSSL footguns. Developed in OpenBSD base first.

libressl.org · 5.6 release notes

Supply chain & daily ops: stay patched without fear

signify

Ed25519 trust in 500 lines

Ted Unangst's minimalist signer replaced PGP/GPG bloat for releases. One pubkey per release, verifiable offline. paper

syspatch

Binary patches, one word

syspatch fetches, verifies and applies base fixes; pkg_add -u for signed packages; -stable branch for conservatives, -current for the brave. syspatch(8) · advisories

xenocara · ports discipline

X + 16k ports, contained

Xenocara (audited X), ports build as user, update-plist hygiene, explicit wxallowed for the few JITs (node, browsers). What isn't audited is labeled as such. ports FAQ
