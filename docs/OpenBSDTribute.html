OpenBSD is not an OS.
It is a fortress with a pufferfish.

Born in 1995 from Theo de Raadt's refusal to compromise, OpenBSD made proactive security, correctness and full disclosure its religion. While the rest of technology drowns in buffer overflows, ROP chains, supply-chain backdoors, Meltdown/Spectre and misconfigured firewalls — OpenBSD quietly answered every one of them, years in advance, in the base system, enabled by default.

02

Philosophy: correctness is security

OpenBSD's famous slogan is not marketing — it is the output of a fanatical engineering culture led by Theo de Raadt since the 1995 NetBSD fork.

Simplicity

No knobs you don't need

One pf.conf, one rcctl, one base. Fewer code paths = fewer bugs. OpenBSD will break compatibility to delete a bad API — see strlcpy replacing strcpy everywhere.

Ref: innovations · style(9)

Proactive audit

Fix it before it's a CVE

Since 1996, file-by-file audits of the whole tree, re-audited as new bug classes are learned. Thousands of overflows, races and leaks fixed in 1996–97 alone. Bugs fixed even without a PoC.

Ref: security.html

Full disclosure

No security-through-obscurity

Advisories, errata and fixes published fast and publicly. Admins can assess real risk instead of waiting for a vendor PR statement.

Ref: errata · CERT VU#986425

Free & documented

Man pages are law

Every syscall documented, every change updates the man page. style(9) enforces readable code so review is possible. Ports build as non-root.

Ref: faq1 · ports FAQ

“We overhaul components even at the cost of compatibility, look for the same mistake elsewhere after finding one flaw, and use mitigations to make bugs harder to exploit.” — Theo de Raadt, 2006 interview
03

Timeline: first in the world, again and again

OpenBSD didn't follow hardening trends — it invented them. Use the filter to tour the arsenal.

1996 — The Great Audit begins

File-by-file review of the entire source tree. Thousands of buffer overflows, protocol bugs, info leaks fixed. The foundation of everything. security.html

1999 — OpenSSH born

Clean, separated, audited SSH from OpenBSD. Now the world's SSH. First with privilege separation (2002, 3.2). OpenSSH security

2001 — PF packet filter (3.0)

Readable, stateful, normalizing firewall replacing ipf. SYN proxy, scrub, queues. PF Guide

2003 — W^X + ProPolice (3.3/3.4)

First OS with W^X on multiple arches and ProPolice stack protector system-wide by default. Memory not writable and executable. innovations

2003 — ASLR by default (3.4)

First widely-used OS with ASLR on by default. Later: PIE everywhere (5.3), randomized malloc + library order. innovations

2008–2014 — strlcpy · reallocarray · hardened malloc

Safe string APIs exported to the world; overflow-checked reallocarray(), freezero(), canaries, guard pages, junking. malloc(3)

2014 — LibreSSL fork (5.6)

After Heartbleed, OpenBSD forked OpenSSL, deleted 150k+ lines, modernized. Primary dev in base. libressl.org · 5.6

2015 — pledge(2) (5.9)

One syscall to irreversibly drop power: pledge("stdio rpath", NULL). Hundreds of base programs pledged. pledge(2)

2016 — W^X strict + KARL preview (6.0/6.2)

W^X strictly enforced (wxallowed opt-out); KARL relinks kernel at every boot — new kernel layout each reboot. 6.0 · 6.2

2018 — unveil(2) (6.4) + RETGUARD + Spectre/Meltdown suite

Filesystem sandbox + return-address cookies + retpoline, SMT-off-by-default, L1TF fixes in one release. unveil(2) · 6.4

Today — signify + syspatch + vmm + wireguard

Signed everything, one-command patches, audited hypervisor, modern VPN in base. signify paper

04

Deep dive: the mitigations, explained like an exploit dev

Each feature below is a wall. Alone it slows you; stacked, they break entire exploit methodologies. Click any wall to open its internals, code and sources.

What: a process declares which syscall groups it needs — e.g. stdio rpath wpath cpath inet dns — and the kernel kills it (SIGABRT) if it ever touches anything else. Promises can only shrink, never grow. A compromised httpd parser that pledged stdio rpath cannot exec, open sockets, or ptrace — the exploit dies inside the sandbox it built itself.

/* httpd render path: after parsing config, drop everything */
#include <unistd.h>
if (pledge("stdio rpath", NULL) == -1)
    err(1, "pledge");
/* from here: no exec, no socket, no prot_exec — RCE becomes DoS */

Why secure: moves policy into the program where intent is known; tiny API (one call) so adoption is massive — 500+ base programs pledged. Combines with unveil for least privilege in two dimensions.

Sources: pledge(2) manual · innovations · sshd + privsep

What: grant visibility to only chosen paths with chosen rights (rwxc), then lock: unveil("/var/www","r"); unveil(NULL,NULL). Everything else returns ENOENT — directory traversal, /etc/passwd reads, key theft all fail closed. Perfect pair: pledge limits what calls, unveil limits what files.

/* static file server: see only /var/www, read-only */
unveil("/var/www", "r");
unveil("/var/www/logs", "rwc");
if (pledge("stdio rpath wpath cpath", NULL) == -1)
    err(1, "pledge");
unveil(NULL, NULL);  // lock: no more unveil calls

Sources: unveil(2) · innovations

What: since 3.3, strict by default in 6.0: no page may be WRITE+EXEC. Classic shellcode injection (write bytes → jump) faults. JITs must be explicitly marked and live on wxallowed mounts — visible, auditable exceptions. Forces attackers from easy code-injection to hard code-reuse (ROP), which RETGUARD+ASLR then punish.

Sources: 6.0 release · upgrade60 + wxallowed · innovations

What: first mainstream ASLR by default (3.4); PIE everywhere (5.3); stack, heap, mmap, libs and even mmap gaps randomized per-exec. No fixed system() address to return to — attacker needs an info-leak + bypass per boot, per process. Combined with W^X, the classic ret-to-libc recipe collapses.

Sources: innovations

What: Kernel Address Randomized Link (6.2): at boot, kernel objects are re-linked in random order; /bsd unreadable to users so layout stays secret. Kernel ROP needs a fresh info-leak each reboot — persistence dies. This is boot-time kernel randomization, beyond process ASLR.

Sources: 6.2 release · innovations

What: ProPolice system-wide since 3.3 (world first); RETGUARD replaces classic cookies with per-function random cookies guarding return addresses, plus stack-pivot checks and gadget reduction. Overwrite a return address and the function epilogue aborts before the ret executes.

Sources: innovations · 5.6 notes · 6.4 notes

What: OpenBSD's allocator (by Otto Moerbeek): randomized placement, guard pages on large chunks, canaries, delayed free + protected freed pages, junk fill, aggressive abort on double-free/UAF. Plus safe APIs the world copied: reallocarray() (overflow-checked multiply), recallocarray(), freezero(ptr,len) (zero secrets before free), strlcpy/strlcat.

/* vulnerable: n * sz can wrap → tiny alloc → overflow */
p = malloc(n * sz);               // BAD
p = reallocarray(NULL, n, sz);    // GOOD: aborts on overflow
freezero(secret, secretlen);      // GOOD: scrub then free

Sources: malloc(3) · reallocarray(3) · innovations

What: pioneered in OpenSSH (2002): split daemons into a tiny privileged monitor + big unprivileged worker. Pre-auth network parsing runs as nobody in a chroot; the monitor only answers vetted requests. Later spread to bgpd, dhcpd, pfctl and dozens more. Even root bugs become nobody bugs.

Sources: innovations · sshd(8)

# /etc/pf.conf — default deny, scrub, synproxy
set skip on lo
match in all scrub (no-df random-id max-mss 1440)
block all
pass out quick inet proto { tcp udp icmp } keep state

Stateful, normalizing (scrub defeats OS-fingerprint + fragmentation tricks), SYN-proxy absorbs spoofed floods, sequence modulation, tables + anchors, ALTQ queues. Default-deny culture, not default-allow.

Sources: PF User's Guide · filtering

What: born in OpenBSD 1999, privilege-separated since 2002. Secure defaults: protocol 2 only, privilege separation + sandboxing on, weak ciphers/MACs pruned aggressively, sshd_config safe out of the box. Its security page lists every vuln transparently — the honesty competitors hide.

Sources: OpenSSH security · sshd(8)

What: 2014 fork after Heartbleed: removed 150k+ lines of compat cruft, aggressive cleanup, modern APIs (libtls), pledge/unveil inside, developed in-tree then ported. Goal: a TLS stack you can actually audit.

Sources: libressl.org · 5.6 release

    -m SHA256.sig -x SHA256

Every release + patch signed with small, auditable Ed25519 tooling. syspatch closes the “I know, I'll reboot later” gap with binary patches.

Sources: signify paper · syspatch(8) · ports FAQ

What: 6.4 shipped Meltdown PTI, retpoline (Spectre v2), SpectreRSB, L1TF, eager FPU — and disabled Intel SMT/Hyper-Threading by default because shared-core speculative state leaks across threads. Plus getentropy(2)/arc4random(3): never-fail, always-seeded randomness (no Debian-OpenSSL déjà vu).

Sources: 6.4 release · faq10 SMT · getentropy(2)

What breaks attackers

The stack that breaks methodologies

  • W^X + RETGUARD + ASLR: kills write→jump shellcode, then kills the ROP fallback.
  • KARL: kills kernel-exploit persistence across reboots.
  • pledge + unveil + privsep: turns code-exec into a sandbox with no exec, no network, no files.
  • malloc + strl*/reallocarray: shrinks the bug pool itself — fewer overflows to start from.
What doesn't make it invincible

Honest limits (read this)

  • Logic bugs, misconfigurations and enabled services are still on you.
  • pledge/unveil only help if developers use them correctly.
  • Speculative-execution fixes are arch/CPU-dependent.
  • Third-party ports are not fully audited — OpenBSD says so itself.

Ref: security.html · ports FAQ

07

Network & crypto trinity: PF · OpenSSH · LibreSSL

pf(4) · in-kernel

Filtering, NAT, normalization, queues — one grammar

PF scrubs packets (reassembles, normalizes IDs/TTLs) so NIDS-evasion and fingerprinting tricks die at the border; stateful keep state, synproxy for spoofed SYN floods, modulate state for weak ISNs, tables for brute-force jails, anchors for apps (authpf, ftp-proxy), ALTQ for bufferbloat-free shaping. Readable enough to audit — powerful enough to run ISPs.

Full guide: PF User's Guide · filtering · pf(4)

OpenSSH · since 1999

Privilege separation before it was cool

Pre-auth parsing as unprivileged sandboxed child; monitor holds keys. Protocol-cleanups (legacy ciphers removed fast), VerifyHostKeyDNS, DisableForwarding, sandbox pledges per platform. Every vuln published at openssh.org/security — compare that honesty to vendors who silently patch.

LibreSSL · since 2014

Fork, delete, harden, repeat

Forked a month after Heartbleed; removed Windows/Mac cruft, custom memory pools, arc4random everywhere, libtls — TLS in ~10 calls instead of 200 lines of OpenSSL footguns. Developed in OpenBSD base first.

libressl.org · 5.6 release notes

02

Filosofia: correcção é segurança

O lema famoso do OpenBSD não é marketing — é o resultado de uma cultura de engenharia fanática, liderada por Theo de Raadt desde o fork do NetBSD em 1995.

Simplicidade

Sem botões de que não precisas

Um pf.conf, um rcctl, um sistema base. Menos caminhos de código, menos erros. O OpenBSD quebra compatibilidade para eliminar uma API má — ver strlcpy a substituir strcpy em todo o lado.

Ref: innovations · style(9)

Auditoria proactiva

Corrigir antes de ser CVE

Desde 1996, revisão ficheiro a ficheiro de toda a árvore, repetida à medida que novas classes de erro são aprendidas. Milhares de overflows, corridas e fugas corrigidos só em 1996–97. Erros corrigidos mesmo sem prova de conceito.

Ref: security.html

Divulgação total

Nada de segurança por obscuridade

Avisos, errata e correcções publicados depressa e em público. Os administradores avaliam o risco real em vez de esperarem por um comunicado do fabricante.

Ref: errata · CERT VU#986425

Livre e documentado

As man pages são lei

Cada syscall documentada, cada alteração actualiza a man page. style(9) impõe código legível para que a revisão seja possível. Os ports compilam sem root.

Ref: faq1 · FAQ dos ports

«Reformulamos componentes mesmo com custo de compatibilidade, procuramos o mesmo erro no resto depois de encontrar uma falha e usamos mitigações para tornar os erros mais difíceis de explorar.» — Theo de Raadt, entrevista de 2006
03

Cronologia: primeiro no mundo, vezes sem conta

O OpenBSD não seguiu modas de endurecimento — inventou-as. Usa o filtro para percorrer o arsenal.

1996 — começa a Grande Auditoria

Revisão ficheiro a ficheiro de toda a árvore de código. Milhares de buffer overflows, erros de protocolo e fugas de informação corrigidos. A base de tudo. security.html

1999 — nasce o OpenSSH

Um SSH limpo, separado e auditado, saído do OpenBSD. Hoje é o SSH do mundo. Foi o primeiro com separação de privilégios (2002, 3.2). segurança do OpenSSH

2001 — filtro de pacotes PF (3.0)

Um firewall legível, com estado e normalização, a substituir o ipf. Proxy SYN, scrub, filas. Guia PF

2003 — W^X + ProPolice (3.3/3.4)

Primeiro sistema com W^X em várias arquitecturas e protector de pilha ProPolice em todo o sistema por omissão. Memória que não é escribível nem executável. innovations

2003 — ASLR por omissão (3.4)

Primeiro sistema amplamente usado com ASLR ligado por omissão. Depois: PIE em todo o lado (5.3), malloc e ordem das bibliotecas aleatórios. innovations

2008–2014 — strlcpy · reallocarray · malloc endurecido

APIs seguras de strings exportadas para o mundo; reallocarray() com verificação de overflow, freezero(), canários, páginas de guarda e enchimento com lixo. malloc(3)

2014 — fork do LibreSSL (5.6)

Depois do Heartbleed, o OpenBSD fez fork do OpenSSL, apagou mais de 150 mil linhas e modernizou-o. O desenvolvimento principal passou para o sistema base. libressl.org · 5.6

2015 — pledge(2) (5.9)

Um syscall para largar poder de forma irreversível: pledge("stdio rpath", NULL). Centenas de programas do sistema base passaram a fazer pledge. pledge(2)

2016 — W^X estrito + prévia do KARL (6.0/6.2)

W^X aplicado com rigor (excepção em wxallowed); o KARL volta a ligar o kernel em cada arranque — disposição nova a cada reinício. 6.0 · 6.2

2018 — unveil(2) (6.4) + RETGUARD + conjunto Spectre/Meltdown

Sandbox de ficheiros + cookies de endereço de retorno + retpoline, SMT desligado por omissão e correcções L1TF no mesmo lançamento. unveil(2) · 6.4

Hoje — signify + syspatch + vmm + wireguard

Tudo assinado, patches num só comando, hipervisor auditado e VPN moderna no sistema base. artigo signify

04

Análise profunda: as mitigações explicadas como um programador de exploits

Cada peça abaixo é um muro. Sozinha, atrasa-te; empilhadas, quebram metodologias inteiras. Clica em qualquer muro para abrir as entranhas, o código e as fontes.

O que é: um processo declara de que grupos de syscalls precisa — por exemplo stdio rpath wpath cpath inet dns — e o kernel mata-o (SIGABRT) se tocar em mais alguma coisa. As promessas só podem encolher, nunca crescer. Um httpd comprometido que fez pledge de stdio rpath não pode fazer exec, abrir sockets nem ptrace — o exploit morre dentro da sandbox que ele próprio construiu.

/* caminho de render do httpd: depois de ler a configuração, larga tudo */
#include <unistd.h>
if (pledge("stdio rpath", NULL) == -1)
    err(1, "pledge");
/* daqui em diante: sem exec, sem socket, sem prot_exec — RCE passa a DoS */

Porque é seguro: leva a política para dentro do programa, onde a intenção é conhecida; a API é minúscula (uma chamada), logo a adopção é enorme — mais de 500 programas do base com pledge. Combina com unveil para privilégio mínimo em duas dimensões.

Fontes: manual do pledge(2) · innovations · sshd + privsep

O que é: dá visibilidade apenas aos caminhos escolhidos, com os direitos escolhidos (rwxc), e depois tranca: unveil("/var/www","r"); unveil(NULL,NULL). Tudo o resto devolve ENOENT — travessia de directórios, leitura de /etc/passwd e roubo de chaves falham em segurança. Par perfeito: pledge limita que chamadas, unveil limita que ficheiros.

/* servidor de ficheiros estático: vê só /var/www, em leitura */
unveil("/var/www", "r");
unveil("/var/www/logs", "rwc");
if (pledge("stdio rpath wpath cpath", NULL) == -1)
    err(1, "pledge");
unveil(NULL, NULL);  // tranca: não há mais chamadas a unveil

Fontes: unveil(2) · innovations

O que é: desde a 3.3 e estrito por omissão na 6.0, nenhuma página pode ser WRITE+EXEC. A injecção clássica de shellcode (escrever bytes → saltar) provoca falha. Os JIT têm de ser marcados explicitamente e viver em montagens wxallowed — excepções visíveis e auditáveis. Empurra o atacante da injecção fácil para a reutilização de código difícil (ROP), que o RETGUARD e o ASLR punem.

Fontes: lançamento 6.0 · upgrade60 + wxallowed · innovations

O que é: o primeiro ASLR por omissão num sistema de uso corrente (3.4); PIE em todo o lado (5.3); pilha, heap, mmap, bibliotecas e até os intervalos de mmap aleatórios a cada execução. Não há um endereço fixo de system() para onde voltar — o atacante precisa de uma fuga de informação por arranque e por processo. Com o W^X, a receita clássica de ret-to-libc desmorona.

Fontes: innovations

O que é: Kernel Address Randomized Link (6.2): no arranque, os objectos do kernel são religados por ordem aleatória; o /bsd é ilegível para os utilizadores, por isso a disposição fica secreta. Um ROP no kernel precisa de uma fuga nova a cada reinício — a persistência morre. É aleatoriedade do kernel em tempo de arranque, além do ASLR por processo.

Fontes: lançamento 6.2 · innovations

O que é: ProPolice em todo o sistema desde a 3.3 (primeiro do mundo); o RETGUARD substitui os cookies clássicos por cookies aleatórios por função a guardar os endereços de retorno, com verificação de stack pivots e redução de gadgets. Se escreveres por cima de um endereço de retorno, o epílogo da função aborta antes de o ret executar.

Fontes: innovations · notas 5.6 · notas 6.4

O que é: o alocador do OpenBSD (de Otto Moerbeek): colocação aleatória, páginas de guarda nos blocos grandes, canários, libertação adiada com páginas protegidas, enchimento com lixo e aborto agressivo em double-free e uso depois de liberto. Mais as APIs seguras que o mundo copiou: reallocarray() (multiplicação verificada), recallocarray(), freezero(ptr,len) (limpa segredos antes de libertar), strlcpy/strlcat.

/* vulnerável: n * sz pode dar a volta → alocação minúscula → overflow */
p = malloc(n * sz);               // MAU
p = reallocarray(NULL, n, sz);    // BOM: aborta no overflow
freezero(secret, secretlen);      // BOM: limpa e só depois liberta

Fontes: malloc(3) · reallocarray(3) · innovations

O que é: pioneira no OpenSSH (2002): dividir daemons num monitor pequeno com privilégios e num trabalhador grande sem eles. O parsing de rede antes da autenticação corre como nobody, dentro de chroot; o monitor só responde a pedidos validados. Depois espalhou-se pelo bgpd, dhcpd, pfctl e dezenas de outros. Mesmo os erros de root passam a erros de nobody.

Fontes: innovations · sshd(8)

# /etc/pf.conf — nega por omissão, scrub, synproxy
set skip on lo
match in all scrub (no-df random-id max-mss 1440)
block all
pass out quick inet proto { tcp udp icmp } keep state
pass in on egress proto tcp to port 443 \
    flags S/SA synproxy modulate state
pass in on egress proto tcp to port 22 \
    flags S/SA keep state (max-src-conn 5, overload <brute> flush)

Com estado, normalizador (scrub derrota o fingerprinting de sistema e os truques de fragmentação), proxy SYN que absorve inundações falsificadas, modulação de sequências, tabelas e anchors, filas ALTQ. Cultura de negar por omissão, não de permitir por omissão.

Fontes: Guia do PF · filtragem

O que é: nasceu no OpenBSD em 1999, com separação de privilégios desde 2002. Predefinições seguras: só protocolo 2, separação de privilégios e sandbox ligadas, cifras e MAC fracos cortados sem hesitação, sshd_config seguro de origem. A sua página de segurança lista todas as vulnerabilidades com transparência — a honestidade que os concorrentes escondem.

Fontes: segurança do OpenSSH · sshd(8)

O que é: fork de 2014 depois do Heartbleed: mais de 150 mil linhas de compatibilidade removidas, limpeza agressiva, APIs modernas (libtls), pledge e unveil por dentro, desenvolvimento na árvore e depois portado. O objectivo é uma pilha TLS que se consiga realmente auditar.

Fontes: libressl.org · lançamento 5.6

$ signify -Cp /etc/signify/openbsd-78-base.pub \
    -m SHA256.sig -x SHA256
$ syspatch   # obtém, verifica e instala patches do base
$ pkg_add -u # pacotes assinados (sem passo extra de verificação)

Cada versão e cada patch é assinado com ferramentas Ed25519 pequenas e auditáveis. O syspatch fecha a lacuna do «eu sei, reinicio logo» com patches binários.

Fontes: artigo signify · syspatch(8) · FAQ dos ports

O que é: a 6.4 trouxe PTI para o Meltdown, retpoline (Spectre v2), SpectreRSB, L1TF e FPU eager — e desligou o SMT/Hyper-Threading da Intel por omissão, porque o estado especulativo partilhado no núcleo se escapa entre threads. Mais getentropy(2) e arc4random(3): aleatoriedade que nunca falha e está sempre semeada (nada de repetir o OpenSSL do Debian).

Fontes: lançamento 6.4 · faq10 SMT · getentropy(2)

Modelo de brinquedo, só para dar intuição — a explorabilidade real depende do erro concreto, da arquitectura e da configuração. A pontuação honesta é, em si, um valor do OpenBSD: divulgação total em vez de propaganda.

O que quebra os atacantes

A pilha que quebra metodologias

  • W^X + RETGUARD + ASLR: mata o shellcode de escrever→saltar e depois mata o recurso ao ROP.
  • KARL: mata a persistência de um exploit de kernel entre arranques.
  • pledge + unveil + privsep: transforma a execução de código numa sandbox sem exec, sem rede e sem ficheiros.
  • malloc + strl*/reallocarray: encolhe o próprio reservatório de erros — há menos overflows de onde partir.
O que não o torna invencível

Limites honestos (lê isto)

  • Erros de lógica, más configurações e serviços ligados continuam por tua conta.
  • pledge e unveil só ajudam se os programadores os usarem bem.
  • As correcções de execução especulativa dependem da arquitectura e do processador.
  • Os ports de terceiros não são totalmente auditados — o próprio OpenBSD o diz.

Ref: security.html · FAQ dos ports

07

Trindade de rede e criptografia: PF · OpenSSH · LibreSSL

pf(4) · no kernel

Filtragem, NAT, normalização e filas — uma só gramática

O PF limpa os pacotes (reagrupa, normaliza IDs e TTL), por isso as fugas aos sistemas de detecção e os truques de fingerprinting morrem na fronteira; keep state com estado, synproxy contra inundações SYN falsificadas, modulate state para ISNs fracos, tabelas para bloquear força bruta, anchors para aplicações (authpf, ftp-proxy) e ALTQ para modelar tráfego sem bufferbloat. Legível o suficiente para auditar, forte o suficiente para operar operadores de telecomunicações.

Guia completo: Guia do PF · filtragem · pf(4)

OpenSSH · desde 1999

Separação de privilégios antes de ser moda

O parsing antes da autenticação corre num processo filho sem privilégios e em sandbox; o monitor guarda as chaves. Limpezas de protocolo (as cifras antigas são removidas depressa), VerifyHostKeyDNS, DisableForwarding e pledges de sandbox por plataforma. Todas as vulnerabilidades são publicadas em openssh.org/security — compara essa honestidade com os fabricantes que corrigem em silêncio.

LibreSSL · desde 2014

Fork, apagar, endurecer, repetir

Fork feito um mês depois do Heartbleed; tralha de Windows e Mac removida, pools de memória próprios, arc4random em todo o lado, libtls — TLS em cerca de dez chamadas em vez de duzentas linhas de armadilhas do OpenSSL. Desenvolvido primeiro no sistema base do OpenBSD.
