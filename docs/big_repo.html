Big Big Big Repository

I normally like to clone some repositories to explore them at home, offline, but sometimes, some repos are bigger than I could ever Imagine.

https://github.com/mthcht/awesome-lists have about 25GB :o

Hopefully this repo is full of details that I will find them useful.

Metadata: after removing metadata, 900MB is the real size

What 25GB means for a clone

A clone is not a copy of the files you see on the web page. It is a copy of the entire history, every version of every file, and every message that describes why the change happened. When a repository collects lists of links, the lists change constantly, and each change leaves a version behind. Twenty thousand small edits produce twenty thousand snapshots of the same text.

That is where the size comes from, and it is also why the number felt absurd to me at first. The content I wanted was a few hundred pages of plain text. The container around it was twenty five gigabytes.

The metadata is the weight

Remove the history and the same repository fits in less than a gigabyte. This is the same lesson I keep finding everywhere: the useful part is small, the bookkeeping around it is enormous. File systems do the same thing, mail servers do the same thing, and any folder with a thousand small files will spend more space on the map than on the territory.

It is not a defect. Metadata is what makes the data findable, comparable and recoverable. It is the reason I can ask a repository what changed last month and get an answer. But it is also the reason I check the size before I start a clone on a machine with a small disk.

How I clone now

A shallow clone takes the last version and leaves the history on the server. If I only want to read the lists, that is all I need, and the download becomes minutes instead of an afternoon. If I later want the history of one file, I can ask for exactly that file.

I still keep the full clone of the repositories I care about, because reading old commits is the cheapest way to understand why a project is shaped the way it is. The trick is to decide before pressing enter, not after the disk is full.
