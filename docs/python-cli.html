The Shell, Extended

Python's best software does not live in an app store. It lives in a terminal, in a repository with a README, behind one command that installs it. This manual is about that command: how to build a virtual environment, how to keep it out of the system, and thirty real GitHub projects worth the trouble — from posting to Mastodon to OCR on a scanned contract.

01Never install into the system Python

Almost every broken Python install starts with one of two sentences: "it worked on my machine" and "I ran it with sudo". Both are the same mistake — installing a project's dependencies into the one interpreter your operating system uses to run itself. There is a rule that removes the whole class of problem, and it fits in three lines.

  1. One: the system Python belongs to the system

    Debian, Ubuntu, Fedora, macOS and Arch all ship Python because parts of the operating system are written in it. Installing packages into it means two projects can demand two versions of the same library, and the loser is usually your desktop. Modern distributions now refuse: pip exits with error: externally-managed-environment, which is not a bug, it is a locked door with a reason.

  2. Two: a project gets a venv, an app gets pipx

    If you will import the thing from your own code, it belongs in a virtual environment inside the project folder. If you will only type its name at the prompt, it belongs in pipx (or uv), which gives the app its own private venv and puts a single launcher on your PATH. Nothing else on the machine sees it.

  3. Three: no sudo, ever, for pip

    The single exception is your distribution's package manager — apt install python3-venv, dnf install python3-pip — which installs the tooling, never a project's dependencies. If a README tells you to sudo pip install, the README is old; use the project's pyproject or the PyPI name with pipx.

What that error actually says

PEP 668 lets a distribution mark its interpreter as externally managed, with an EXTERNALLY-MANAGED marker file next to the standard library. pip reads it and stops. You can override it with --break-system-packages; you should not, and no command in this manual needs it. The escape hatch is a venv, which is one command away.

Three tools, three jobs

Tool What it is for Use it when What it costs
venv A folder with its own Python, its own pip and its own site-packages. Built into Python since 3.3. You are writing code that imports the library, or you need an exact pinned set of versions for one project. 20–200 MB per environment, and one activation command per terminal.
pipx A manager of isolated environments, one per command-line app, with a launcher symlinked into ~/.local/bin. The package provides a command you run (yt-dlp, toot, csvkit) and you never import it. A few MB per app; the disk cost is the price of never having a dependency conflict again.
uv A single fast binary that does venvs, pip installs, Python version downloads and tool installs — the same jobs, in seconds. You install tools often, or you are tired of waiting for a resolver. uvx also runs an app without installing it at all. One more binary to trust and to update; it is written in Rust, not Python.

The whole idea, on one screen

One environment per app, no activation needed, and the command is addressed by its full path. This is the pattern the rest of the manual refines; everything else is convenience built on top of it.

python3 -m venv ~/.venvs/media
~/.venvs/media/bin/pip install --upgrade pip
~/.venvs/media/bin/pip install yt-dlp
~/.venvs/media/bin/yt-dlp --version

Nothing was installed system-wide, nothing needs sudo, and deleting ~/.venvs/media removes every trace. The three drawbacks are that the path is long, that each app needs its own folder, and that you have to remember which folder holds what — which is exactly what pipx removes.

02The virtual environment, from zero

A venv is not a virtual machine and it is not magic: it is a directory containing a symlink to your Python, a copy of the launcher scripts, and a site-packages folder that pip writes into. Activating it changes one environment variable, PATH, so that python means this folder instead of the system one. That is the entire mechanism.

Seven commands, in order

  1. Check what you have

    python3 --version should print 3.11 or newer for most of the apps in this manual (mitmproxy, for one, wants 3.12 — each project states its floor on PyPI). If the version is older than a project needs, install a newer interpreter next to the old one rather than replacing the system's.

  2. Install the venv module, if your distribution split it out

    Debian and Ubuntu ship Python without ensurepip, which makes python3 -m venv fail with "ensurepip is not available". One package fixes it permanently: sudo apt install python3-venv. Fedora and Arch already include it; macOS from python.org includes it; Homebrew's Python does too.

  3. Create it inside the project

    Name it .venv and put it in the project root — editors, linters and every tutorial already look there. The folder is disposable: no data lives in it, only symlinks and wheels.

  4. Activate it

    Activation is a convenience, not a requirement. It exists so that typing python and pip does the right thing; the environment works identically if you call .venv/bin/python directly, which is what cron jobs and scripts should do.

  5. Install with pip, then freeze

    Install what you need, confirm it imports, then write the exact versions to a file. pip freeze records everything including transitive dependencies; a hand-written requirements.txt records only your intent. For applications, freeze. For libraries, pin the direct dependencies and let the resolver work.

  6. Leave, and come back later

    deactivate restores the old PATH. Next session, activate again, or skip activation and use the full path. On a server, always skip it: a script that depends on an activated shell breaks the first time it runs from cron.

  7. Delete it when it rots

    When upgrades go wrong, the fastest fix is rm -rf .venv and create it again from requirements.txt. Ten seconds, no residue. This is the habit that makes the rest of this manual safe: environments are cheap, so never repair one for an hour.

The same three commands on each system

System Create Activate Leave
Linux / macOS (bash, zsh) python3 -m venv .venv source .venv/bin/activate deactivate
fish python3 -m venv .venv source .venv/bin/activate.fish deactivate
Windows (PowerShell) py -m venv .venv .venv\Scripts\Activate.ps1 deactivate
Windows (cmd) py -m venv .venv .venv\Scripts\activate.bat deactivate
PowerShell blocks the activation script

By default Windows refuses to run Activate.ps1 because it is an unsigned script. The fix is per-user, not per-machine: Set-ExecutionPolicy -Scope CurrentUser RemoteSigned. If you would rather not touch policy at all, call .venv\Scripts\python.exe directly and never activate.

A real session, with the output it should give

cd ~/projects/scrape
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install requests beautifulsoup4
python -c "import requests, bs4; print(requests.__version__, bs4.__version__)"
pip freeze > requirements.txt
deactivate

From another machine, or after deleting the folder: python3 -m venv .venv && source .venv/bin/activate && pip install -r requirements.txt. That one line is the entire portability story of a Python project, and it is why requirements.txt is committed while .venv is not.

What goes into git

Commit requirements.txt (or pyproject.toml with a lock file). Never commit .venv: it contains absolute paths, platform-specific binaries and tens of megabytes. One line in .gitignore — .venv/ — prevents a hundred confusing clones.

The two flags that cause trouble

--system-site-packages lets an environment see the system's packages, which quietly reintroduces the conflict you were escaping. --without-pip creates an environment with no installer; you then need python -m ensurepip. Neither is needed for anything in this manual.

03pipx: one command per app, no conflicts

pipx is the answer to a specific question: what if I want the command, not the library? It creates a private venv for each app under ~/.local/pipx/venvs, installs the package there with the right interpreter, and symlinks only the launcher into ~/.local/bin. Two apps can then depend on two incompatible versions of the same library and neither notices the other exists.

Start here

# Debian / Ubuntu
sudo apt install pipx
# Fedora
sudo dnf install pipx
# macOS (Homebrew)
brew install pipx
# or, with any Python already installed
python3 -m pip install --user pipx

pipx ensurepath
# open a new terminal, then
pipx install toot
toot --help

ensurepath writes the PATH line in your shell's startup file. If the next shell still says command not found, the file was the wrong one — see part 05 — or the shell cached its command list and needs hash -r.

The eight pipx commands worth memorising

Command What it does Why you would type it
pipx install NAMECreates a venv and links the launcher.The normal case. Add extras in quotes: pipx install "qrcode[pil]".
pipx listShows every app, its version and its command names.When you cannot remember whether you already installed something.
pipx upgrade NAMEUpgrades that app only, in its own venv.yt-dlp and gallery-dl need this often: sites change weekly.
pipx upgrade-allUpgrades every app pipx manages.A monthly habit, not a daily one.
pipx uninstall NAMERemoves the venv and the launcher.A clean removal with no leftovers in site-packages.
pipx inject NAME PKGAdds a library to that app's venv.For plugins and optional backends, without touching other apps.
pipx run NAMERuns the app in a temporary venv that is thrown away.Trying something once without committing to it.
pipx reinstall NAME --python 3.12Rebuilds that app's venv with another interpreter.When an app needs a newer (or older) Python than the default.

The plugin pattern

A command with an ecosystem — beets, llm, mkdocs — usually wants a plugin. Install the app, then pipx inject beets beets-fetchart. The plugin lands in the same private venv, so it cannot break any other tool, and pipx upgrade beets leaves it alone.

When an app must not move

pipx has no lock file by design: it is for tools you want current. If a version must be frozen — a publishing pipeline, a scraper with brittle selectors — use a venv with a pinned requirements file, or uv tool install NAME==1.2.3, and treat it as a project rather than a tool.

04uv: the same jobs, in seconds

uv is a single binary from Astral that replaces the slow parts of the Python toolchain: creating environments, resolving dependencies, downloading interpreters, installing command-line tools. It is not a Python package (there is a pip-installable wheel, but the supported install is the binary), and it is the one tool in this manual that is worth learning for its own sake. 

# install the binary (Linux / macOS)
curl -LsSf https://astral.sh/uv/install.sh | sh

# a tool, isolated, with its launcher on PATH
uv tool install yt-dlp
uv tool list
uv tool upgrade --all
uv tool uninstall yt-dlp

# run something once, without installing it
uvx csvlook data.csv

# a project environment, pip-compatible
uv venv .venv
uv pip install -r requirements.txt
uv python install 3.12
uvx is the feature that changes habits

uvx NAME downloads the app into a cached environment, runs it with the arguments you gave, and leaves your PATH untouched. For a one-off conversion, a single csvsql query or a quick gallery-dl run, that is faster than deciding whether you want the tool permanently. The cache means the second run is instant.

pipx or uv?

Both produce the same result: an isolated environment and a launcher in ~/.local/bin. pipx is the conservative choice — it is packaged by every major distribution, its behaviour is stable, and it only manages tools. uv is faster and broader, and it will also manage your project environments and Python versions, which is either convenient or one dependency too many, depending on your taste. The manual uses pipx in its commands and notes the uv equivalent; nothing here needs both.

05PATH, and where things actually go

The most common failure in this manual is not a broken package. It is a correct install whose command cannot be found, because the launcher was written to a directory your shell does not search. Knowing the four directories removes the mystery.

DirectoryWhat lives thereShould you touch it?
~/.local/binLaunchers from pipx and uv, plus any pip install --user script.No — but it must be on PATH. This is the directory ensurepath adds.
~/.local/pipx/venvs/<app>The private environment of each pipx app, with its dependencies.Never by hand. pipx owns it; edit through inject or reinstall.
~/.venvsEnvironments that belong to no project — a scratch toolbox of your own.Yes, freely. It is just folders you invented; delete them when bored.
/usr/local/binSystem-wide launchers, usually from your distribution or a make install.Only with sudo, and only for things the package manager did not provide.

Adding it once, per shell

# bash — ~/.bashrc     zsh — ~/.zshrc
export PATH="$HOME/.local/bin:$PATH"

# fish
fish_add_path ~/.local/bin

# then, in the current shell
source ~/.bashrc
command -v toot

On Windows the equivalent is setx PATH "%PATH%;%USERPROFILE%\AppData\Roaming\Python\Scripts" in a fresh cmd, and a restart of the terminal. If command -v prints nothing but the file exists, the shell is using a cached list: hash -r in bash, rehash in zsh, or simply open a new window.

The check that settles it

ls ~/.local/bin | head shows whether the launcher exists; echo $PATH | tr ':' '\n' | grep local shows whether the shell looks there. Those two commands answer "why is my command not found" in five seconds, and they are always the first thing to run before reading an error message twice.

07Posting: Mastodon, APIs and the web, from the prompt

Two of the most useful tools in this manual do the thing a browser tab does, without the tab: toot speaks the Mastodon API, and posting is a terminal client for any HTTP API. Between them, publishing and testing an endpoint stop being a reason to open a window.

toot — a Mastodon client in the terminal

A Python CLI for Mastodon and compatible servers (Pleroma, GoToSocial, Akkoma). It authenticates with an app token stored in your config, so the password never appears in a command line. It posts, threads, uploads media, reads timelines and can run scheduled posts through cron.

pipx install toot
toot login                      # choose the instance, paste the code
toot post "first post from the shell"
toot post "a thread" --visibility unlisted
toot tui                        # a full terminal interface
toot timeline --local --num 20
toot upload photo.jpg --description "a caption for screen readers"

The TUI is the part people miss: toot tui gives a keyboard-driven timeline with replies and boosts, useful on a server over SSH. For automation, toot post returns the new status URL, so a script can chain it.

posting — an API client that lives in the terminal

Postman, for people who live in a shell: requests stored as YAML files in a collection, environments with variables, syntax highlighting, and keyboard-only editing. It is the fastest way to exercise an endpoint you are building, and the collection is a text file you can commit.

pipx install posting     # the PyPI package is Python; the repo now also ships a Go build
posting                  # opens the TUI, current folder as collection
posting --collection ~/api/requests
posting request.posting.yaml --env dev

A request file is a small YAML document — method, URL, headers, body — so it reviews in a diff and travels with the repository. The Python distribution on PyPI is what pipx installs; the project's README documents the newer standalone binary if you prefer that route.

HTTPie — the readable curl

curl is always there and always cryptic. HTTPie turns a request into something closer to a sentence: JSON is assumed, headers are coloured, and the response is formatted instead of concatenated. It is the tool to reach for when you are debugging an API by hand.

pipx install httpie
http GET https://api.github.com/repos/pypa/pipx
http POST https://httpbin.org/post name=oscar tags:= '["shell","python"]'
http --auth user:token GET https://api.example.com/me
http --download https://example.com/file.tar.gz
https example.com          # the same, over TLS, in three letters
Tokens are files, not arguments

A token typed after a command is stored in your shell history, and shell history is world-readable more often than people think. toot login keeps its token in ~/.config/toot/config.json; for HTTPie, put the credential in a session (--session=api) or read it from an environment variable. If you have already leaked one, revoke it — do not edit the history and hope.

08Media: download, archive, convert

The most-installed command-line Python apps in the world are media downloaders, and for good reason: they do one job better than any website, they are scriptable, and they keep working after the site changes. All four here want ffmpeg installed by the system, not by pip — that is the single most common reason a download "succeeds" and produces no file. 

# the system dependency all four share
sudo apt install ffmpeg        # Debian / Ubuntu
sudo dnf install ffmpeg        # Fedora (RPM Fusion)
brew install ffmpeg            # macOS

yt-dlp — the reference implementation of "download that"

A fork of youtube-dl that is updated weekly and supports well over a thousand sites. Formats, subtitles, chapters, playlists, archives that skip what you already have, and a config file for the options you always pass.

pipx install yt-dlp
yt-dlp "https://example.com/video"
yt-dlp -f "bestvideo[height<=1080]+bestaudio/best" URL
yt-dlp -x --audio-format mp3 URL
yt-dlp --write-subs --sub-langs "pt.*,en.*" URL
yt-dlp --download-archive seen.txt URL     # a channel, once, cleanly

The --download-archive flag is the one that turns a downloader into a subscription: run it from cron, and each pass fetches only what is new. Keep the archive file with the media, not in /tmp.

gallery-dl — image galleries, not videos

The companion tool for the sites yt-dlp does not cover: image boards, artist pages, manga readers, photo feeds. It preserves the post metadata as JSON next to the files, which makes an archive searchable years later.

pipx install gallery-dl
gallery-dl "https://example.com/artist"
gallery-dl --range 1-50 "https://example.com/gallery"
gallery-dl -g URL                # print the URLs instead of downloading
gallery-dl --write-metadata URL  # JSON sidecars

streamlink — live streams into a player

Takes a page URL that is playing a stream and hands the stream itself to mpv or VLC, at a quality you choose. No browser, no ads, no compositor. It also records, which is the difference between "I watched it" and "I have it".

pipx install streamlink
streamlink URL best              # default player
streamlink --player mpv URL 720p
streamlink --output stream.ts URL best

spotdl — playlists to files

Reads a Spotify playlist or track, finds a matching audio source, and writes tagged files with cover art. Treat it as a tool for material you already have the right to keep: it matches audio from public sources, and what it writes is your responsibility, not the tool's.

pipx install spotdl
spotdl "https://open.spotify.com/playlist/..."
spotdl URL --output "{artist}/{album}/{title}.{output-ext}"
The legal line, in one paragraph

Downloading is not the same as owning. Copyright applies to the file, the site's terms apply to the access, and neither is suspended because the tool is open source. Keep what you have the right to keep, archive your own uploads, use the tools for research and accessibility where the law allows it, and do not build a business on redistributing other people's work. The four projects above document their limits; read them once.

09Watching the machine: CPU, GPU, and why it is slow

Three tools, three questions. What is the whole machine doing right now? Is the GPU the bottleneck? And which line of my Python is spending the time? None of them needs root, and all three produce output you can paste into a bug report.

Glances — the whole machine, on one screen

CPU, memory, disks, network, sensors, containers and the top processes, in a layout that fits an 80-column terminal and refreshes itself. The same process can serve that view over HTTP, which makes it a monitoring dashboard for a headless box with no agent to install.

pipx install glances
glances                          # interactive
glances -w                       # web mode: open http://localhost:61208
glances -t 2                     # refresh every two seconds
glances --export csv --export-csv-file load.csv

Nvitop — the GPU answer

An NVIDIA GPU monitor that shows per-process memory, utilisation and temperature, with the tree of processes that own each card — the thing nvidia-smi almost does. It installs as a Python app but talks to the driver directly; no CUDA toolkit is required, only a working driver.

pipx install nvitop
nvitop                           # full monitor
nvitop -m                        # compact, one line per GPU
nvitop --once                    # print and exit, for scripts

pyinstrument — a profiler you can read

Statistical profiler with a human-first report: it shows the call stack as a tree of time, not a wall of numbers. Run it on a script, or attach it to a running process, and export an HTML file you can open later.

pipx install pyinstrument
pyinstrument script.py
pyinstrument -r html -o profile.html script.py
pyinstrument -m mypackage.cli

For a web request that feels slow, the useful pattern is to wrap the handler rather than the server: profile the function, not the framework. And profile twice — a single run is an anecdote, two runs with the same shape are a measurement.

10Data: SQLite, CSV, JSON, Postgres

Most "data work" is not a notebook. It is a file with rows, a question about those rows, and a shell where the file already is. These five tools answer the question without opening an editor: datasette publishes a database as a browsable site, sqlite-utils builds and edits it, csvkit slices text files, jc converts any command's output to JSON, and pgcli gives Postgres autocomplete.

Datasette — a database with a URL

Point it at a SQLite file and it serves a browsable, filterable, facetable interface with a JSON API on every table. It is the fastest way to let someone else look at your data without sending them the file, and it needs no server configuration at all.

pipx install datasette
datasette mydata.db                    # http://127.0.0.1:8001
datasette mydata.db -m metadata.json --port 8080
datasette mydata.db --cors --setting sql_time_limit_ms 5000

Every table also answers as JSON: append .json to the URL. That single feature replaces a small API project more often than people expect.

sqlite-utils — the database, from the command line

Inserts CSV and JSON into SQLite, creates tables from the data's shape, runs queries, alters schemas and converts columns — the operations you would otherwise write twelve lines of Python for, every time.

pipx install sqlite-utils
sqlite-utils insert data.db readings readings.csv --csv --detect-types
sqlite-utils schema data.db
sqlite-utils query data.db "select month, avg(value) from readings group by 1"
sqlite-utils convert data.db readings value 'float(value.strip())'

csvkit — fourteen commands, one idea

Each utility does one transformation and writes CSV to stdout, so they compose in a pipe: cut columns, filter rows, sort, join, describe, then query the result with SQL. It also reads XLSX, which makes it the bridge between a spreadsheet and everything else.

pipx install csvkit
csvlook sales.csv
csvcut -c 1,3,7 sales.csv | csvsort -c 3 -r | head
csvgrep -c country -m "PT" sales.csv
in2csv report.xlsx > report.csv
csvsql --query "select country, sum(total) from sales group by 1" sales.csv

jc — JSON from any command

Takes the text output of a hundred familiar commands — ls, ps, df, ip, dig, systemctl — and returns structured JSON, so the next step can be jq instead of awk. It also parses the formats that have no parser: ini, csv, yaml, syslog, crontab.

pipx install jc
ls -l | jc --ls -p | jq '.[] | select(.size > 1000000) | .filename'
df -h | jc --df -p
cat /etc/hosts | jc --hosts -p

pgcli — Postgres with autocomplete

A Postgres client that knows your schema: table and column names complete as you type, syntax is coloured, and the results page themselves. The same family includes mycli for MySQL and litecli for SQLite, from the same maintainers.

pipx install pgcli
pgcli postgresql://user@localhost:5432/mydb
# inside the prompt
\d                     # tables, views, sequences
\d+ users              # columns, indexes, constraints
\dp                    # permissions

11Documents: scan, print, label

Three small tools with the same shape: input on the left, a file on the right, no application window. OCR turns a scan into text, WeasyPrint turns HTML and CSS into a print PDF, and qrcode turns a string into something a phone can read.

OCRmyPDF — a scanned PDF that can be searched

Adds a text layer to an image-only PDF, keeping the original scan underneath: it looks identical, and Ctrl+F works. It is the difference between an archive and a pile of pictures of documents. Tesseract and Ghostscript are system packages, not pip packages.

sudo apt install tesseract-ocr tesseract-ocr-por ghostscript
pipx install ocrmypdf
ocrmypdf scan.pdf searchable.pdf -l por
ocrmypdf --skip-text batch.pdf out.pdf      # leave existing text alone
ocrmypdf --deskew --clean --rotate-pages in.pdf out.pdf
ocrmypdf -l por+eng --jobs 4 in.pdf out.pdf

Language packs are the usual surprise: tesseract-ocr-por for Portuguese, -eng for English, -spa for Spanish. Without the pack, OCR runs with an English model and mangles every accent.

WeasyPrint — HTML to PDF, properly

Renders HTML with real CSS support, including paged media: margins, running headers, page numbers, footnotes and page breaks. It is how a generated invoice, a report or a book stops being a screenshot of a browser.

sudo apt install libpango-1.0-0 libpangoft2-1.0-0     # Debian 12+
brew install pango                                    # macOS
pipx install weasyprint
weasyprint invoice.html invoice.pdf
weasyprint --base-url ./assets report.html report.pdf

The CSS to learn is small: @page { size: A4; margin: 2cm }, @page { @bottom-center { content: counter(page) } }, and break-before: page. That is most of a printable document.

qrcode — a QR code from the prompt

Small, old, and still the quickest way to put a URL into a room: generate a PNG or an SVG, print it, stick it on a shelf label or a business card. The CLI is called qr, and it needs the image extra.

pipx install "qrcode[pil]"
qr "https://blog.odicforcesounds.com" > qr.png
qr --factory=svg "https://example.com" > qr.svg
qr --error-correction=H "long text here" > big.png

Higher error correction means a denser image that still reads when partly covered — worth it for anything printed small or placed outdoors.

12Terminal craft: files, mistakes, memory

Four tools that make the shell itself better: a file manager that never leaves the keyboard, a corrector for the command you just mistyped, a manual with examples instead of flags, and a renderer that makes Markdown and code readable at the prompt.

ranger — three columns, no mouse

A terminal file manager with a preview pane: text, images (in a suitable terminal), PDFs, archives. Moving, copying, bulk renaming and opening a shell in the current directory are single keys. It is the answer for a server where ls is not enough and a desktop is not available.

pipx install ranger-fm
ranger
# hjkl move, space select, yy copy, dd cut, pp paste
# :mkdir name   :rename   S  shell here   ?  keys

thefuck — the correction after the swear word

When a command fails because of a typo or a missing sudo, type fuck and it proposes the corrected command, which you accept with Enter. It reads the previous command and its error, not your intentions — which is why it works so often.

pipx install thefuck
# add once to ~/.bashrc or ~/.zshrc
eval $(thefuck --alias)
# then
fuck
fuck --yeah      # accept without asking
fuck --repeat    # keep fixing until it works

tldr — the manual, with examples

Man pages list every flag; tldr pages show the five invocations people actually use. The Python client downloads the community pages and caches them locally, so lookups are instant and offline after the first update.

pipx install tldr
tldr tar
tldr --update
tldr --list | head

rich-cli — Markdown and code, rendered

Prints a file the way it was meant to look: Markdown with headings and tables, source code with syntax highlighting and line numbers, JSON pretty-printed, CSV as a table. Useful for READMEs over SSH and for checking generated output before it ships.

pipx install rich-cli
rich README.md
rich --syntax -n script.py
rich --json data.json
rich --csv table.csv --head 10

13A personal library that outlives the app

The best argument for command-line tools is not speed, it is ownership: the music library is a folder of tagged files, the bookmarks are a SQLite database, the calendar is a directory of .ics files. Nothing here needs an account, and everything can be backed up with rsync.

beets — the music library that fixes itself

Imports a folder, fingerprints the audio, looks up the release, writes correct tags, moves the files into a clean tree and stores everything in a queryable database. Once set up, beet import is the only command you need for a new album.

pipx install beets
beet import ~/Downloads/album
beet ls -a artist:radiohead
beet fetchart
beet lyrics
beet write          # push database changes back to the files

Configuration lives in ~/.config/beets/config.yaml: library path, directory format, plugins. The important habit is beet write — the database is a convenience, the files are the archive.

buku — bookmarks you own

A bookmark manager for the terminal with tags, full-text search and an HTML export. The database is one SQLite file, so it syncs, greps, and survives the death of any company.

pipx install buku
buku -a https://example.com/article python cli reading
buku -s "sqlite"
buku --export bookmarks.html
buku -p          # print the database path

khal — the calendar as files

Reads and writes calendars stored as iCalendar files in a folder — the same format every phone and mail client understands. Paired with vdirsyncer, it keeps a local copy in sync with a CalDAV server, so the terminal and the pocket agree.

pipx install khal vdirsyncer
khal list
khal list today 7d
khal new tomorrow 18:00 19:00 Dinner with Ana
ikhal          # interactive editor

The config is ~/.config/khal/config: one section per calendar, a path, a colour. Start with a single local calendar before adding a server; syncing is a second problem.

todoman — tasks as text, not as an app

Manages tasks in the same iCalendar format, one file per task, with lists, due dates, priorities and a compact table view. Because the storage is plain text, a task can be edited with any editor and still be found by the tool.

pipx install todoman
todo list
todo new "renew the passport" --due 2026-11-15 --list Personal
todo done 3
todo edit 3

14Serve and ship: docs, traffic, inspection

Two tools for putting something on the network, and one for understanding what a program sends over it. Both are Python apps that install with a single command and run from a folder, which is the whole aesthetic of this manual.

MkDocs — Markdown in, site out

A documentation generator with a live-reload server: write Markdown, keep a small mkdocs.yml, and mkdocs serve shows the site while you type. mkdocs build produces static files that any host will serve. It is also a perfectly good blog engine if you stop at the first theme.

pipx install mkdocs
mkdocs new my-docs
cd my-docs
mkdocs serve            # http://127.0.0.1:8000
mkdocs build --strict
mkdocs gh-deploy        # publish to GitHub Pages

mitmproxy — look at the traffic

An intercepting proxy with three front ends: an interactive console, a web UI, and a non-interactive mode for scripts. It is how you find out what an app actually sends — which headers, which endpoint, which payload — and how you replay a request until it behaves.

pipx install mitmproxy
mitmproxy               # console, on port 8080
mitmweb                 # browser UI
mitmdump -w session.flows
mitmdump -nr session.flows --set flow_detail=1

To see HTTPS you install mitmproxy's CA certificate in the client you are testing — the project documents it per platform. Use it on your own devices and your own traffic: intercepting someone else's is not a debugging technique, it is an attack.

15Keeping it clean for a year

An install is a decision you keep paying for: every tool has a version, a cache and a folder. The maintenance is small if it is regular — five minutes a month, four commands, and the machine never accumulates the kind of Python installation nobody dares touch. 

pipx upgrade-all                 # every app, in its own venv
uv tool upgrade --all            # if you use uv
pip cache purge                  # wheels you will never need again
uv cache clean
du -sh ~/.venvs/* | sort -h      # the environments you forgot

Audit before you trust

A tool's dependencies are code you run with your permissions. pipx run pip-audit checks an environment against the public vulnerability database, and pipx list --include-injected reminds you what you added by hand. Neither is a guarantee; both catch the obvious.

The rule of the second install

Install a tool the first time because you need it. Install it the second time — after removing it, with a different method — because you now know how you use it. Everything installed "just in case" becomes the folder you skip when backing up.

What to back up, and what not to

PathBack it up?Why
~/.config/toot, ~/.config/khal, ~/.config/beetsYesConfiguration and tokens: half an hour to recreate, impossible to remember.
~/.local/share/buku, the beets databaseYesYour bookmarks and library index. Small files, years of decisions.
~/.local/pipx/venvs, ~/.cache/uvNoRebuilt from a name and a version in one command.

16The ten messages that stop an install

These are not ten problems. They are three: the wrong interpreter, a missing system library, or a directory the shell cannot see. The table maps the message to the cause, because the message is almost never the cause.

Message What it means Fix
error: externally-managed-environment You are installing into the distribution's Python, which PEP 668 now blocks on purpose. Create a venv, or use pipx install. Do not use --break-system-packages.
command not found: yt-dlp after a successful install The launcher is in ~/.local/bin, which is not on PATH in this shell. Run pipx ensurepath, open a new terminal, or export PATH="$HOME/.local/bin:$PATH" and hash -r.
ModuleNotFoundError: No module named 'X' The package is installed for a different interpreter than the one running the script. Compare which python with the install line, then reinstall using python -m pip from the same environment.
error: Microsoft Visual C++ 14.0 or greater is required No prebuilt wheel exists for this package and this Python on Windows. Try a newer Python (more wheels), use --only-binary :all: to see what is available, or install the Build Tools.
fatal error: Python.h: No such file or directory The package compiles a C extension and the Python development headers are missing. sudo apt install python3-dev (Debian), python3-devel (Fedora), then retry.
ERROR: No matching distribution found for X Usually a Python version below the project's floor, a misspelled name, or no network. Check the project's Requires-Python on PyPI, confirm the exact package name, then try a newer interpreter.
SSL: CERTIFICATE_VERIFY_FAILED The Python from python.org on macOS ships without a certificate bundle, or a proxy intercepts TLS. Run Install Certificates.command in the Python folder, or pip install --upgrade certifi. On a corporate proxy, set REQUESTS_CA_BUNDLE.
Killed while building a package The compiler ran out of memory — common on a 1 GB VPS with a large source build. Add swap, or avoid compiling: prefer --only-binary :all:, or install the app where wheels exist for your platform.
Permission denied: /usr/lib/python3/dist-packages A previous sudo pip install left root-owned files, and now pip cannot clean up after itself. Stop using sudo for pip. Uninstall what you added with sudo, fix ownership if needed (sudo chown -R $USER on the user-writable parts), and move to venv or pipx.
Could not build wheels for X, which is required to install pyproject.toml-based projects The package needs a system library or a compiler the machine does not have — pango, ffmpeg, tesseract, libpq. Install the system package named in the error, then retry. The app chapters in this manual list which one each tool needs.
Read the last line, not the first

pip prints a page of resolver output and the useful sentence is at the very end, after ERROR:. Copy the last ten lines, not the whole log, when you search for the message — and add the Python version and the operating system, because half the answers online are for a different pair.
