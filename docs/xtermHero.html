xterm — From Nothing to Hero

The terminal that is already there before you pick an emulator. It has no opinions, no plugins and no settings UI — but it has menus hidden behind mouse chords, a resource database, a 256-colour palette and a translation system for keys. Everything in one page.

01From nothing

xterm is the X Window System's own terminal emulator — the original one, shipped with X itself since the 1980s and still maintained. That placement is its whole personality:

  • It is always there. Install X on BSD or Linux and xterm appears with it. When your fancy emulator breaks, when you are setting up a new window manager, when you ssh into a machine with no dotfiles — it is the window you open next.
  • It does not fight. No shells inside the emulator, no plugin sandboxes, no theme marketplace. Features are negotiated with the X server like it is 1985, which means they are all still documented.
  • It is the reference. Ctrl-click menus, clipboard semantics, mouse support, 256 colours — if a modern emulator implements something differently, xterm's way is what the man page compares against first.

On most systems it comes as a standalone package (x11/xterm on BSD, xterm everywhere else), which drags in one small friend worth celebrating later: resize(1).

Note: “hero” here means: you can configure xterm without a drinking problem, name menus by their chords, and fix five classic puzzles (frozen screen, ghost Alt, vanished titles, stale size after split, missing clipboard bridge). Those five, named and fixed in a minute — that is the hero part.

02First launch that sticks

From an X session (cwm, twm, anything with a launcher), the zeroth xterm is one command:

$ xterm &

And the four flags that cover every practical first launch:

$ xterm -ls              # login shell, reads .profile like a console
$ xterm -e htop          # run a command instead of a shell
$ xterm -title doughnut  # name the window; joyriders' favourite
$ xterm -geometry 100x34+60+40

The geometry syntax is COLS×ROWS+X+Y — columns first, then pixels for the corner. It reads odd the first three times and obvious forever after.

Note: xterm -e goes away with the shell inside it — close htop, window closes. For a window that survives the command, use -hold (see the hero vocabulary, section 12) to watch errors at the end of scripts that flash by too fast.

03The three mouse menus

xterm's “settings UI” never made it into a GUI box; it is three pop-up menus wired to Control chords while the pointer is over the window. No one would design this today; everyone who has learned it refuses to give it back.

ChordMenuWhat lives there
Ctrl + Left-clickMain OptionsLog to File, Print, Secure Keyboard (screen grab), Interrupt / Terminate / Kill, Continue / Suspend, Signal SIGQUIT — the emergency room.
Ctrl + Middle-clickVT OptionsScrollbar toggle, Jump Scroll, Reverse Video, Auto Wrap, Curses Emulation, Select to Clipboard, Locator — the daily behaviour panel.
Ctrl + Right-clickVT FontsFont sizes (Largest to Tiny), Escape (default), ASCII, fonts by name — the fast font dial.

Two entries deserve a second sentence:

  • Secure Keyboard grabs input exclusively for this window; other clients (your IME daemon, anything) stop reading the keyboard. Useful for passwords when you want to be sure.
  • Select to Clipboard flips the copy behaviour to fill the modern CLIPBOARD — section 08 explains why that single menu entry ends the ancient “xterm cannot copy” myth.
Warn: in the Main Options menu, Interrupt/Terminate/Kill are what their names say. Ctrl-Left-click exists precisely so nobody lands there by habit.

04Fonts, honestly

By default xterm draws with its bitmap font, which is why it looks like a library scan from 1989. The moment you point it at a TrueType face it becomes a modern citizen:

$ xterm -fa "Liberation Mono" -fs 12
# or, once, in resources (section 06):
XTerm*faceName: Liberation Mono
XTerm*faceSize: 12
  • -fa / faceName: any font your X server knows. Run fc-list to see the list; monospace is a good idea, but xterm will not scold you.
  • -fs / faceSize: point size. Set it once; the font menu then cycles sizes relative to it.
  • Ctrl + Right-click → VT Fonts is the size dial for the session; resources are what survives the dial.
  • UXTerm: the same program pre-wired for Unicode; if your terminal draws ?-boxes for non-ASCII, try the UXTerm street name before debugging anything.
My font change worked until I resized — then it went back?
Menu changes are session-only; resources are permanent. Anything set through a menu dies at the next reboot, anything in .Xresources is for tomorrow. That rule resolves half of xterm folklore.

05Colors and the 16 known faces

xterm speaks 256 colours: the 16 classic ones (resources color0 through color15), the 6×6×6 cube, and 24 greys. Applications using ESC sequences or the xterm-256color terminfo can address all of them.

The 16 faces every theme talks about — pure CSS, exactly as they ship by default:

0 black 1 red 2 green 3 yellow 4 blue 5 magenta 6 cyan 7 white 8 brblack 9 brred 10 brgreen 11 bryellow 12 brblue 13 brmagenta 14 brcyan 15 brwhite

Redefine any of them in resources, with the base pair thrown in:

XTerm*foreground:  #eef0f8
XTerm*background:  #0d0c17
XTerm*color1:  #ff5f5f
XTerm*color8:  #8a8a8a
XTerm*cursorColor: #ffd66b

And two parlor tricks for the session, no resources needed:

$ printf '\033]11;#101820\007'   # repaint the background, live
$ printf '\033[0;31mred\033[0m' # see? classic red
Note: themes from old Unix seasons still work: the menu entry Reverse Video (Ctrl + Middle-click) flips the pair for five seconds of bluescreen comedy.

06The resource database

This is the heart of hero-land. xterm has no config file of its own; it reads the X resource database. In practice you write them in ~/.Xresources and load:

$ xrdb -merge ~/.Xresources

Then new xterms inherit. A starter file that combines this page's earlier sections:

# ~/.Xresources — xterm block
XTerm*loginShell:        true
XTerm*faceName:          Liberation Mono
XTerm*faceSize:          12
XTerm*scrollBar:         true
XTerm*scrollbar*thickness: 12
XTerm*saveLines:         4096
XTerm*scrollKey:         true
XTerm*foreground:        #eef0f8
XTerm*background:        #0d0c17
XTerm*cursorColor:       #ffd66b
XTerm*selectToClipboard: true

How to find every button's name without reading the source:

$ appres xterm XTerm        # full resource dump for the class
Note: the hierarchy is Class.instance*resource (or * to skip levels). XTerm*faceName hits all xterms; xterm.debugshell*faceName would hit one named instance only. Wildcards are free; laziness with them is not.
Note: some systems ship .Xdefaults plumbing instead; it works the same at X startup day one. The two-file confusion dissolves the moment you standardise on .Xresources + xrdb -merge.

07Scrollback and the frozen screen

The two experiences people actually have with scrollback: history that stops being kept (the buffer was small), and a screen that stops moving (the famous Ctrl+S accident).

History that stops dying

XTerm*saveLines: 4096      # default is 1024; give back some RAM
XTerm*scrollBar: true
XTerm*scrollKey: true      # any key output scrolls back to the prompt

Use it: Shift+PgUp/Shift+PgDn line-wise, Ctrl+PgUp faster (per translations, section 12 for custom chords), or drag the scrollbar you switched on above.

The frozen screen sheet

If output freezes while you type — and typing still works — that is not xterm dying. Press Ctrl+S out of habit, you paused the pipe:

Ctrl+Q    # unfreeze (xon)
$ stty -ixon            # in your shell rc: no Ctrl+S/Q at all, ever
Warn: everything else on this page is configuration. This trap is not: the classic “xterm hangs” complaint is usually the flow control that the session inherited and the user did not know was there.

08Copy-paste without mystery

X11 has two buffers, and xterm behaves like the person who insists on the rule rather than the spirit:

BufferFilled byPasted byMeaning
PRIMARYSimply selecting textMiddle-clickThe original X way — selection is the copy.
CLIPBOARDExplicit copy actionsCtrl+V in modern appsThe other systems' way, arrived in X via the desktops.

xterm by default works in PRIMARY: select, middle-click, done. Two bridges to the modern world, pick one:

  1. One resource line — the friendly one:
# ~/.Xresources — selection also lands in CLIPBOARD
XTerm*selectToClipboard: true
  1. Custom chord — explicit copy keys, like every modern editor (this uses translations, the same machinery as section 10):
XTerm*VT100.translations: #override \n\
    Ctrl Shift <Key>C: copy-selection(CLIPBOARD) \n\
    Ctrl Shift <Key>V: insert-selection(CLIPBOARD)

The Ctrl+Shift chord version is what anyone coming from a modern editor tries first; the resource version is what your muscle memory will thank you for. Doing both is also legal.

Note: they left double-click word selection smart (charClass in the hero vocabulary teaches it what “a word” is in URLs and paths), and triple-click selects the line. That is 90% of daily needs, and nothing installs to provide them.

09Alt, Meta and other ghost stories

xterm predates convention convergence, so it keeps knobs for the two ghosts: one where Alt does not reach your shell's readline (Alt-b goes forward a word in bash, but on some feet it does not), and one where 8-bit bytes arrive where escape sequences were expected.

# ~/.Xresources — the two ghost exterminators
XTerm*metaSendsEscape:  true   # Alt-b arrives as ESC b, readline understands
XTerm*eightBitInput:    false  # no raw 8th-bit mode; escape prefixes instead
  • metaSendsEscape is the fix for “Alt chords do nothing in the shell, but do in other terminals”. With it, Alt arrives as the ESC prefix your readline always wanted; it is what most modern emulators hard-code.
  • eightBitInput:false keeps everything inside a 7-bit world of control sequences, where remote shells and TUIs thank you daily.
  • Verify with the shell's own report instead of guessing: stty -a (look for ixon, isig), and the terminal's own vocabulary: TERM=xterm-256color tput colors.
Note: if delete/backward keys argue back (sending ^? or ^H, often depending whether you came through PuTTY, ssh, or your own machine), the resources backarrowKey and deleteIsDEL are the honest dials. On a well-configured stack both end up matching the shell's expectations — test, then set.

10Titles by escape sequence

Programs can rename the window or the icon with simple escape output; xterm accepts it if window operations are allowed for that window.

$ printf '\033]2;doughnut shop\007'   # rename the window title
$ printf '\033]1;icon name\007'       # rename the icon title

If nothing happened, that is privacy-by-default, not a bug:

XTerm*allowWindowOps:  true   # let escape sequences run window ops
XTerm*dynamicColors:   true   # let them re-paint the palette too

11The resize ritual

Split the screen, drag a pane, and the shell inside still believes the old size — wrapping lines at column 80 in a 200-wide window, or worse: truncating the right half silently on the next long command. This is not xterm's fault; it is the shell's knowledge of the geometry lagging behind:

$ resize           # tells the shell the true size, right now
$ resize -u        # else export two stty lines for eval
$ eval "$(resize -u)"   # the way it is actually used in fish/zsh/rc files

Resizing locally, without the helper, uses the shell itself:

$ stty rows 34 columns 100
Note: most modern shells catch SIGWINCH and follow along by themselves. When one does not, resize is the five-letter command that ends the conversation. It ships with xterm, which is why this manual keeps insisting you install the package and not some appimage of it.

12Hero vocabulary

The one-time dose: flags and resources that separate “it opens” from “I steer it”:

SpellWhat it does
-holdWindow survives the -e command; script output sticks around instead of flashing by.
-rv / *reverseVideoStart reversed (bg/fg swapped); old soul, new mood.
-l / Log to FileSession tape recording — training, bug reports, receipts.
Secure KeyboardInput grab: whole desktop keyboard belongs to this window (password theatre with a badge).
-ti vt220 / -tn xterm-256colorLie about your hardware to old programs (vt series) or name the terminfo key.
-cc class[:range,...]Teach double-click what counts as “a word” — URLs, paths, hyphens and all.
-xrm "resource: value"One-shot resource override on the command line — perfect for experiments without touching the files.
*translationsThe key-translation table — per-key bindings, per-chord scroll, per-button paste. The section 08 example is your template.
*charClassThe same word-selection teaching, as a resource (persistent cousin of -cc).
~/.XterminatorThe name you give your .Xresources block when you want to feel like a wizard — loading it stays an xrdb job.
Warn: a hero vocabulary does not mean writing resources for every window. Settle the 12 lines of section 06 in .Xresources, add the two chips of section 09, and stop. The machines of people with 300 resource lines are no faster; they are just harder to reproduce on the next laptop.
Note: truth scoreboard: all of the above is documented in xterm(1) and xterm-ctlseqs(7), two documents remarkably grounded comparing to the field. Reading them once beats a forum thread; keeping both in your MANPATH beats ten.
