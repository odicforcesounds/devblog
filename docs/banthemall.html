Ban Them All

I start using my self-hosted server.

Using Linux, with tmux help, I can monitor all activity.

Fail2ban is awesome to block them all.

Watching before blocking

The first days of a new server are the best lessons. Open a tmux session, split the window, put the web server log on one side and the packet count on the other, and the pattern appears before the coffee is cold. A handful of addresses repeat the same requests at the same rhythm. Human readers do not behave like that.

tmux matters here for a boring reason: the monitoring must survive the closed terminal. A session that keeps running when the laptop lid falls is the difference between watching a log and guessing about it.

How the ban actually works

Fail2ban is not a firewall. It is a reader. It reads the log, matches the lines against a rule, and when an address crosses the limit it asks the firewall to drop that address for a while. That is all. No magic, no intelligence, just patience and a rule that says how many failures are allowed inside how many minutes.

Two settings decide almost everything: how long the ban lasts and how wide the window is. Too short and the address returns before the lesson is learned. Too wide and an honest reader who mistyped a password three times is locked out of his own site.

Ban them all, except yourself

The first ban I ever made was mine. A typo, four attempts, and the server stopped answering me from my own network. Since then every configuration starts with the same line: the local addresses are always allowed. A tool that protects the door should never keep the owner outside.

After that, the server became quiet. The noise is still out there, it just no longer reaches the page. That is the whole promise of a ban: not to punish anyone, only to keep the conversation small enough to be readable.
