Não Identifica o Dispositivo

Quando configuras 2FA em algumas das tuas contas, de cada vez que entras numa plataforma, a mensagem que recebes é «Identifica o teu dispositivo», que envia um código numérico para verificar. Mas a verdade é que o que o código QR ou as chaves de autoridade fazem é identificar o código gerado pela identificação do QR, não o dispositivo. Por isso, se apagares a conta do teu dispositivo e configurares o mesmo dispositivo com a mesma conta, o teu 2FA de autoridade deixa de funcionar, porque não identifica o teu dispositivo, mas aquele código aleatório gerado no momento em que leste o QR. Isto não é segurança, é falsa segurança. Útil, mas falsa.

O que o código QR contém na realidade

Um segredo, codificado num formato que a aplicação sabe ler. Esse segredo é combinado com a hora atual para produzir seis dígitos, e o mesmo cálculo é repetido no servidor. Se os dois números coincidirem, o início de sessão é aceite.

Não há impressão digital do telefone nesse cálculo, nem o nome da pessoa. O código prova que o dispositivo guarda o segredo, não que o dispositivo é teu.

Porque é que apagar a conta estraga tudo

Quando a conta é removida da aplicação, o segredo é removido com ela. O telefone é o mesmo, o utilizador é o mesmo, o número do SIM é o mesmo, mas aquilo que produzia os seis dígitos desapareceu. Configurar a conta outra vez gera um segredo novo, e o servidor substitui o antigo, e é por isso que os códigos antigos deixam de funcionar.

De fora parece um problema de dispositivo. De dentro é um problema de segredo, e a diferença importa: um dispositivo pode ser reconhecido, um segredo só pode ser conhecido.

A palavra que o ecrã devia usar

«Identifica o teu dispositivo» é uma promessa que o protocolo nunca fez. Identifica um segredo partilhado, que é uma afirmação muito mais pequena, e muito mais honesta. A proteção é real, no sentido em que uma palavra-passe roubada de uma base de dados já não basta, mas é proteção contra uma cópia da palavra-passe, não contra uma pessoa que tem o teu telefone.

Útil mas falsa, como diz o título. Continuo a usá-la, porque útil e imperfeita é melhor do que perfeita e ausente.

Does Not Identify the Device

When you setup 2FA for some of your accounts, everytime you login into some platform, the message you get is "Identify Your Device", which send some numeric code to verify. But the truth is that, what QR code or Authority Keys do, is that they identify the code that was generated by the QR code identification, not the device. So, if you delete your account from your device, and setup the same device with the same account, your Authority 2FA will not work anymore, because it doesn't identify Your device, but that random code generated in the moment you can the QR code. This is not security, this is false security. Useful but false.

What the QR code actually contains

A secret, encoded in a format that the application knows how to read. That secret is combined with the current time to produce six digits, and the same calculation is repeated on the server. If the two numbers match, the login is accepted.

There is no fingerprint of the phone in that calculation, and there is no name of the person. The code proves that the device holds the secret, not that the device is yours.

Why deleting the account breaks everything

When the account is removed from the application, the secret is removed with it. The phone is the same, the user is the same, the number of the SIM is the same, but the thing that produced the six digits is gone. Setting the account up again generates a new secret, and the server replaces the old one, which is why the old codes no longer work.

From the outside this looks like a device problem. From the inside it is a secret problem, and the difference matters: a device can be recognised, a secret can only be known.

The word the screen should use

"Identify your device" is a promise the protocol never made. It identifies a shared secret, which is a much smaller claim, and a much more honest one. The protection is real, in the sense that a password stolen from a database is not enough anymore, but it is protection against a copy of the password, not against a person who has your phone.

Useful but false, as the title says. I still use it, because useful and imperfect is better than perfect and absent.
