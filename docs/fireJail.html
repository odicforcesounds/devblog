Ignition — your first jail in 60 seconds

0.1 What Firejail actually is

Firejail is a SUID sandbox launcher for Linux. It runs as root for a few milliseconds — just long enough to build a cage from kernel primitives — then drops privilege and executes your program as you. The cage is not emulation: it is the Linux kernel itself (namespaces, seccomp-bpf, capabilities, raqm, AppArmor/Landlock hooks) told to lie to one process tree.

🧠 Mental model: Firejail = mount namespace (fake filesystem) + PID/UTS/IPC namespaces (fake identity) + optional net/user namespaces + seccomp-bpf (forbidden syscalls) + capabilities + no_new_privs (no escalation) + profile (which rules apply). Lose any layer and you are weaker — that is why this manual is paranoid at every level.

Install & first run

# Debian / Ubuntu / Mint
sudo apt install firejail firetools # firetools = optional Qt GUI
firejail --version

# The hello-world of sandboxing:
firejail firefox
firejail --private vlc
firejail --net=none --private evince secret.pdf

# Who is jailed right now?
firemon --list --tree
firemon --seccomp --caps --netstats
⚠️ SUID warning (read twice): firejail is installed setuid-root. On a true multi-user shell server, any SUID binary widens attack surface. Upstream advises thinking hard before deploying it there. On a single-user laptop/desktop — the target of this manual — the trade-off is overwhelmingly worth it.

Try it: fake terminal (type help)

operator@paranoid: ~ — firejail sim
Type `help` and press Enter. Try: firejail firefox | firejail --net=none vlc | firemon --list | firecfg --list
$ 
💡 This terminal is simulated with vanilla JS — no backend. It teaches syntax before you touch a real shell.

LEVEL 1

The six walls — Linux namespaces

CLEARANCE: WATCHER • PREREQ: L0
🔒 SEALED — clear Level 0 to break this seal.

A namespace gives a process a private view of one kernel resource. Same kernel, different lies. Firejail's default sandbox always takes mount + PID + UTS; you add net, IPC, user for paranoia.

🧱 MNT — private filesystem table (always on)
👁 PID — jailed app is PID 1, cannot see host processes
🏷 UTS — fake hostname (no fingerprinting your box)
📡 IPC — no shared memory / semaphores with host
🌐 NET — private network stack (--net=none / --net=eth0)
🧤 USER — map you to nobody, fake root (--noroot)
🔥 YOUR APP (thinks it owns the machine)
Click a layer…
# See the lies yourself
firejail --noprofile --ipc --net=none --private bash
ps aux          # only jail processes!
hostname; ip a  # fake/lo-only world
ls /proc/1/exe  # your shell, not systemd
exit
☠ Paranoid rule: always add ipc-namespace, net none (or filtered net), and noroot unless the app provably needs otherwise. Defaults are sane; paranoia is six walls, not three.

Files & contexts — what "visible" really means

CLEARANCE: ARCHIVIST • PREREQ: L1
🔒 SEALED — clear Level 1 first.

2.1 Four layers of "file context" — do not confuse them

A file's context is every answer to "who may do what with it, and who decides?" A paranoid operator reads all four:

#Context layerDecided byExampleFirejail changes it?
1DAC — classic Unix owner/group/mode + ACLsfilesystem bits-rw------- alice alice ~/.ssh/id_rsaNo — but jail can hide the file entirely
2xattr / MAC label — SELinux context, AppArmor attachmentkernel policyunconfined_u:object_r:user_home_t:s0, ls -ZNo — labels still enforced inside the jail
3Firejail view — blacklist / whitelist / read-only / privateprofileblacklist ~/.ssh, whitelist ~/DocsYes — this is the whole level
4Landlock / sandbox extras — unprivileged per-process FS rulesprofile + kernellandlock.enforce + landlock.fs.read /tmpYes (experimental, additive)
⚠️ Key truth: blacklist ≠ SELinux relabeling. Firejail shapes the view; SELinux/AppArmor still judge every surviving access. They stack. Check both: ls -l and ls -Z.

SELinux context anatomy (real example)

$ ls -Z ~/Docs/secret.pdf
unconfined_u:object_r:user_home_t:s0 ~/Docs/secret.pdf
  │            │           │          └─ level (MLS: s0 = lowest)
  │            │           └─ type (policy rules target THIS)
  │            └─ role (which roles may touch it)
  └─ SELinux user (not your login name!)
# Change it persistently via policy, never bare chcon on production:
semanage fcontext -a -t user_home_t "$HOME/Docs(/.*)?"
restorecon -Rv ~/Docs

LEVEL 3

Syscalls, capabilities & no-new-privs

CLEARANCE: WARDEN • PREREQ: L2
🔒 SEALED — clear Level 2 first.

Namespaces hide things. seccomp-bpf hides abilities. Every exploit finally begs the kernel via a syscall (open, execve, ptrace, mount, socket, keyctl…). Firejail installs a BPF filter that kills the process if it touches a forbidden one — for the app and all its children.

▲ syscalls fall from the app    ▬ BPF filter    ▼ survivors reach the kernel
🟥 blocked → process killed🟩 allowed → reaches kernelstats: —
# The paranoid stack (add AFTER reading the shipped profile!)
seccomp                          # default blacklist (~300 dangerous calls)
seccomp.block-secondary          # kill 32-bit compat ABI abuse
memory-deny-write-execute        # no W+X mappings: breaks JIT shellcode
restrict-namespaces              # app may not create new namespaces
protocol unix,inet,inet6          # no bluetooth, raw packet, etc.
caps.drop all
nonewprivs
noroot
# scalpel instead of hammer, when you know the app:
# seccomp.keep read,write,open,openat,close,fstat,mmap,brk,exit_group
☠ Paranoid order of operations: seccomp first, then caps.drop all, then nonewprivs + noroot. Capabilities without nonewprivs still let a setuid helper re-escalate. Verify with firemon --seccomp --caps.

LEVEL 4

Network namespaces — unplug or filter the jail

CLEARANCE: SIGNAL • PREREQ: L3
🔒 SEALED — clear Level 3 first.

A fresh network namespace is a machine with the cables pulled: only lo. From there you choose: stay dark (net none — strongest), or re-attach through a filtered virtual cable (--net=eth0 + --netfilter=).

🔥 JAILED APP
firefox
🌐 TARGET
192.168.1.5 (your LAN)
policy: —
Pick a mode. Packets animate; the log explains the verdict.
# Dark (media players, PDF, office):
firejail --net=none evince secret.pdf

# Filtered browser (profile snippet):
net eth0
netfilter /etc/firejail/nolocal.net
dns 9.9.9.9
protocol unix,inet,inet6
# nolocal.net drops 192.168/16, 10/8, 172.16/12, 127/8 egress
# → internet works, printer/router snooping dies
⚠️ A net namespace alone is not a firewall. Pair every net eth0 with a netfilter file, or stay net none. Check with firemon --netstats and ip a inside.

LEVEL 5

X11, D-Bus & IPC — the desktop betrays you

CLEARANCE: GHOST • PREREQ: L4
🔒 SEALED — clear Level 4 first.

Your filesystem can be perfect and still lose: on classic X11, any client can keylog any other. On D-Bus, any app can chat with secrets services. Paranoia means a second X server + a D-Bus muzzle.

💻 victim window — type happens here…

☠ attacker window (jailed evil app)

Press a mode button, then watch keystrokes leak (or not).
# Current Firejail X11 path uses Xephyr (Xpra support removed upstream)
firejail --x11=xephyr firefox

# D-Bus muzzle (profile): needs xdg-dbus-proxy for filtering
dbus-user none
dbus-system none

# dbus-user.filter / dbus-user.talk org.freedesktop.Notifications

# Shared-memory / signals between jailed + host:
ipc-namespace
☠ X11 law: hiding /tmp/.X11-unix alone is insufficient (abstract sockets survive). You need --x11 plus a net namespace / protocol without raw unix tricks. Verify with firemon --x11.

LEVEL 6

Profiles like a maintainer

CLEARANCE: AUTHOR • PREREQ: L5
🔒 SEALED — clear Level 5 first.

Profiles are plain text. System: /etc/firejail/*.profile. Yours wins: ~/.config/firejail/app.profile. Persistent sysadmin tweaks: *.local. Always include, never fork-and-forget.

# ~/.config/firejail/vlc.profile — sound, no spy
include /etc/firejail/vlc.profile
net none
private-tmp
private-dev         # keep sound working? test; add nosound only if you must mute
caps.drop all
nonewprivs
noroot

# Audacity with its OWN persistent home (create ~/myaudio first)
# ~/.config/firejail/audacity.profile
include /etc/firejail/audacity.profile
private ~/myaudio
net none
# Lifecycle commands
sudo firecfg              # symlink supported apps via /usr/local/bin
firecfg --list; sudo firecfg --clean
firejail --build=/tmp/vlc.profile vlc   # GENERATOR: relaxed run → starter whitelist. Review + tighten!
firemon --list --tree --seccomp --caps --apparmor --netstats --x11
# jailcheck (root) reports visible dirs / net status — a heuristic, not proof
