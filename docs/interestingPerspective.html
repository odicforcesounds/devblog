Será que a IA consegue rever código no processo de desenvolvimento de aplicações?

Com base nas últimas notícias de programadores que são YouTubers, pensamos sobre o que descrevem e, por isso, podemos tentar entender como e porquê. É fácil escrever 20.000 linhas por dia com IA e, naturalmente, é fácil rever 20.000 linhas de código com IA. Mas a principal pergunta que me vem à cabeça é: a IA cria um ambiente dedicado para testar o código que está a rever? Porque é preciso testar o código, e o teste é como se sabe que o código funciona, mesmo que se possa rever o código para entender como o «problema» foi resolvido e para ver se há algumas linhas extra que não precisam de existir naquele pedaço de código em particular.

Então pergunto: a IA cria um ambiente dedicado para testar o código que está a rever?

De facto, gostaria de saber isso, porque no fim é só isso que importa. Mas para entender se uma função não devia estar num pedaço de código, é preciso entender todos os outros pedaços e a estrutura inteira da aplicação, enquanto na minha interpretação a IA pode rever amostras de código sem as incluir em todos os outros pedaços de código que a aplicação final tem. Como não sei, pergunto.

A complexidade de construir uma aplicação é Grande, porque não é só a funcionalidade, mas o «Ponteiro» que faz a funcionalidade, bem aplicado numa estrutura lógica específica que depende de muitas outras condições que não são a Aplicação em si, mas Utilizadores, Bots, Exploits, etc... E com isso temos sistemas como o OpenBSD, que têm esse tipo de «Filosofias» que dizem aos programadores: «Encontra o Bug antes do Hacker o encontrar». Com isso, entendemos que a maioria dos bugs de código são, de facto, o resultado de programadores que não passaram tempo suficiente a pensar no que estavam a fazer.

Rápido e Bom, Poucos Conseguem, já que a Maioria Falha e produz muitos Erros
