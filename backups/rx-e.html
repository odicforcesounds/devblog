16The ten messages that stop a build

Rust's errors are precise about the source code and vague about the machine, which is why the ones below are the ones people paste into a search engine. Each row links the message to the cause, because the cause is usually one package, one directory, or one version away.

Message What it means Fix
error: linker `cc` not found There is a compiler but no C linker. Every Rust binary links against the system C library, so a bare container fails here. Install build-essential (Debian), base-devel (Arch), xcode-select --install (macOS), or the C++ build tools on Windows.
failed to run custom build command for `openssl-sys` A crate wants to link a C library and its headers or pkg-config are missing. Install pkg-config libssl-dev, or build with --no-default-features and a rustls feature if the project offers one.
package `x` cannot be built because it requires rustc 1.95 or newer The crate's declared MSRV is above your compiler. Nothing is wrong with the crate. rustup update stable. If you are pinned in a rust-toolchain.toml, raise it deliberately — or install an older version of the tool.
error: could not compile `x` (signal: 9, SIGKILL: kill) The linker ran out of memory. Rust's final link step is the memory-hungry part, and a container with 2 GB will be killed. Build with fewer jobs (cargo install -j 1), add swap, or use a linker that uses less memory such as lld.
No space left on device The build directory filled the disk — usually several gigabytes for one large crate. Clear old target directories and the registry cache; part 04 has the commands and the sizes.
error: failed to select a version for the requirement `x = "^2"` No published version satisfies the resolver, often because a dependency was yanked after the lock file was written. Drop --locked to let Cargo re-resolve, or cargo update -p x in the project. A yanked crate can still be built if it is in your lock file.
error: binary `fd` already exists in destination Another crate ships a binary with the same name, or you are reinstalling the same version. Add --force if you meant to overwrite. Check cargo install --list to see what was there first.
error: no such command: `binstall` Cargo looks for subcommands as binaries named cargo-* on PATH. The binary is installed somewhere your shell does not see, or not at all. Install it (cargo install --locked cargo-binstall) and check command -v cargo-binstall before blaming the tool.
warning: be sure to add `~/.cargo/bin` to your PATH The install worked; the shell cannot find the result. Part 05. export PATH="$HOME/.cargo/bin:$PATH" in the profile your shell actually reads, then start a login shell.
error: failed to download ... SSL certificate problem A proxy, a corporate TLS inspection certificate, or a missing CA bundle between you and crates.io. Set https_proxy, point CARGO_HTTP_CAINFO at the corporate bundle, or use CARGO_NET_GIT_FETCH_WITH_CLI=true for git dependencies.
The two failures that look like the machine dying

A build that ends in Killed ran out of memory at the link step — add swap or reduce jobs, and it will finish. A build that takes eight minutes the first time and three seconds the second is the incremental and registry caches doing their job; cargo clean resets it to the slow version, so there is no reason to. Neither is a sign that the tool is broken.

17Which route for this tool

There are four honest ways to get a Rust binary onto a machine, and the right one depends on who will run it and where. Answer three questions and the verdict below names the route, the reason, and the command — including the case where the answer is "do not compile this here".

Route Good for What it costs
cargo install --locked Your workstation, the newest version, reproducibility. Minutes of compile time, and a dependency tree that must compile cleanly.
cargo binstall Any machine that can download a release artefact, especially a CI image. Trust in the project's release pipeline, and the fallback compile when there is no artefact.
distro / nix A fleet you do not want compiling, and a version that arrives with the system's updates. An older version than upstream — occasionally far older — and names that differ from upstream's.
cargo build --release + copy A server with no toolchain: build once here, copy the binary, done. You own the build: matching libc and architecture, and the update is your problem.

The cross-compilation footnote is worth knowing before it surprises you: a binary built on a glibc distribution will not run on a musl system such as Alpine. Build with the x86_64-unknown-linux-musl target for a static binary, or build inside the image you will deploy.

18Sources, and what each one settles

The manual is built from the projects' own documentation and from the metadata each crate publishes. Every tool in part 06 links to its repository, which is the authority on its own flags — and the pages below are the authority on the toolchain itself.

  • rustup.rs — The installer used in part 02, with the profiles and the components it can add.
  • The rustup book — Toolchains, overrides, rust-toolchain.toml and what rustup show is telling you.
  • cargo install — Every flag in the table of part 03, including --locked, --root and --git.
  • Cargo configuration — Where config.toml lives, and the environment variables that override it, including the registry and proxy settings.
  • crates.io — The register itself: every crate, version, MSRV and repository link used here.
  • The edition guide — What an edition changes, which editions a compiler supports, and why edition 2024 needs Rust 1.85.
  • The Rust blog — Release announcements every six weeks, the source of the version numbers quoted here.
  • The manifest reference — The rust-version field, which is where a crate's declared MSRV actually lives.
  • cargo-binstall — How a prebuilt artefact is located for each platform, and what happens when none exists.
  • RustSec — The advisory database behind cargo audit, and the format of the entries it matches.
  • Platform support — Which targets are tier 1, tier 2 or tier 3, and therefore which cross-compiles are expected to work.
  • Build scripts — Why a crate can fail before your code compiles, and what pkg-config is doing in a Rust build.

The versions in part 06 are the newest published crates on 29 October 2026, and each MSRV is the one declared in that release's metadata. Both will move; the repository remains the authority, and the trailing --locked is how you keep today's build tomorrow.
