07The prompt, the cd, and the history

Three tools that change how the shell feels rather than what it runs. starship draws the prompt, zoxide replaces cd with a memory of where you have been, and atuin replaces the history file with a searchable, encrypted database. All three install the same way, and all three hook into the shell with one line.

starship — a prompt that knows where it is

One binary, one starship.toml, and a prompt that shows the git branch, the language version, the exit code of the last command, the time a build took — without a shell script per shell. It is fast because it is compiled and because it only asks the modules the current directory can use. The reason to choose it over a hand-written prompt is not beauty; it is that a new language gets supported by an upgrade instead of by editing your .bashrc.

cargo install --locked starship

# ~/.bashrc, or the zsh / fish equivalent
eval "$(starship init bash)"
eval "$(starship init zsh)"

# a minimal prompt, in ~/.config/starship.toml
add_newline = false
[character]
success_symbol = "[\$](bold green)"
error_symbol = "[\$](bold red)"
[git_branch]
format = "on [\$branch](\$style) "

zoxide — cd, but it remembers

It keeps a score for every directory you visit and lets you jump by fragment: z proj from anywhere. The ranking is what makes it work — frequency and recency, not a list you maintain. Hook it over cd with --cmd cd and it behaves like cd for paths that exist, and like a jump for anything else, which is the version people keep.

cargo install --locked zoxide
eval "$(zoxide init bash --cmd cd)"     # zsh / fish / nushell too

z blog                # best match for "blog"
z blog docs           # both fragments, any order
zi                    # pick interactively (needs fzf or skim)
zoxide query -ls      # the whole ranking, with scores

atuin — history as a database

Your shell history is a flat file that every terminal writes to at exit, which is why it loses commands, duplicates others and cannot tell you what failed. Atuin records each command with its exit code, duration, directory and session into SQLite, and gives you a search interface on Ctrl+R that filters by all of it. Sync between machines is optional and end-to-end encrypted; self-hosting is a single binary and a Postgres or SQLite database.

cargo install --locked atuin
eval "$(atuin init bash)"        # or zsh / fish / nu

atuin import auto                # bring the old history file in
atuin search -i                  # the interactive search
atuin search --exit 1 --before 2026-10-01
atuin stats                      # what you actually run

# optional: your own server, or the hosted one
atuin register -u me -p … -k …   # self-hosted
atuin login -u me

The privacy question is fair, and the answer is architectural: without atuin login nothing leaves the machine. With sync, the encryption key never leaves it either — the server stores ciphertext and cannot read your commands.

08A shell written in Rust, and two that extend yours

Nushell is a shell where everything is a table, mise is the version manager that finally replaced four others, and skim is the fuzzy finder you can script from Rust as easily as from a pipeline. Two of the three are large builds; the third is a library with a binary attached.

nushell — pipelines of structured data

In bash a pipeline carries bytes and every command re-parses them. In Nushell a pipeline carries a table with named columns, so ls can be filtered by size, ps sorted by cpu, and JSON read as a data structure rather than text. It is a different shell, not a drop-in replacement: your .bashrc does not apply, and the first hour is unlearning. What it buys is a shell where the answer to "which of these files is largest" is one expression.

cargo install --locked nu        # add --features=full for the extras
nu

ls | where size > 10mb | sort-by size --reverse | first 5
ps | where cpu > 5 | select pid name cpu mem
open package.json | get dependencies | columns
http get https://api.github.com/repos/nushell/nushell | get stargazers_count
ls **/*.rs | group-by { path parse | get extension } | transpose ext files

mise — one version manager for every language

Node, Python, Go, Ruby, Java, Terraform and the rest, with one command and one configuration file. It reads the same .tool-versions as asdf, so migrating is a copy, and adds a task runner and an environment manager that reads .env files. If you have ever had three version managers with three activation lines in one profile, this is the one that replaces them.

cargo install --locked mise
eval "$(mise activate bash)"        # or zsh / fish

mise use --global node@22
mise use python@3.13                # writes .mise.toml in the project
mise install
mise ls --current
mise exec -- node --version

# .mise.toml, committed with the project
[tools]
node = "22"
python = "3.13"

[tasks.test]
run = "cargo nextest run"

skim — a fuzzy finder you can link against

The same idea as fzf, written as a Rust library with a CLI on top — which is why it is fast on a million-line input and why other Rust programs embed it. The interface is compatible enough that most fzf habits transfer, and the extras are the reason to switch: a built-in interactive mode that re-runs the search command on every keystroke, and a tmux popup wrapper.

cargo install --locked skim        # the binary is sk

sk                                  # files under the current directory
sk --ansi -i -c 'rg --color=always --line-number "{}"'
git ls-files | sk --preview 'bat --color=always {}'
sk-tmux -d 40%                      # in a tmux popup
vim "$(sk)"

09Find, read, list: the four that replace the classics

ripgrep replaces grep, fd replaces find, bat replaces cat and eza replaces ls. None of them is a wrapper around the original, and none of them is installed by default — which is why the first week feels like using someone else's kitchen and the second week feels like your own.

ripgrep — grep, with the right defaults

It respects .gitignore, skips binary files, searches recursively by default, and uses a regex engine that is fast enough to make the flags unnecessary. The behaviour change that matters is the silence: it does not descend into node_modules or target unless you ask, so the results are the files you meant.

cargo install --locked ripgrep

rg 'fn main'                        # recursive, ignores .gitignore
rg -n --hidden -g '!target' 'TODO'
rg -t py 'import requests'
rg -l 'deprecated' | xargs sed -i 's/deprecated/obsolete/g'
rg --stats 'unsafe'                 # counts, files, time
rg -C 3 'panic!'

fd — find, without the incantation

The syntax is fd PATTERN, the pattern is a regex on the file name, and it is recursive and gitignore-aware by default. Everything that took a manual page to learn in find is a flag: -e for extension, -x to run a command per result, -X to run one command with all of them. On Debian and Ubuntu the package installs the binary as fdfind to avoid a name clash, which is the single most common "it did not install" report.

cargo install --locked fd-find        # binary: fd

fd '\.rs$'                          # regex on names
fd -e rs -e toml                    # by extension
fd -H -I 'config'                   # include hidden and ignored
fd -e jpg -x convert {} {.}.webp    # per file; {.} is the stem
fd -e log -X rm                    # one invocation, all paths
fd -td -d 2                         # directories, two levels down

bat — cat with syntax colours and a pager

A cat that highlights the file by its language, shows line numbers when the output is a terminal, adds a header with the file name and size, and pages long files. It also integrates with git to mark changed lines, which turns "read this file" into "see what changed in this file" without opening a diff.

cargo install --locked bat

bat src/main.rs
bat --diff src/main.rs              # git changes in the margin
bat -A .env                         # show invisible characters
bat --plain --language json x.json  # no decoration, for piping
bat --list-themes | head

# as the pager for man pages, in ~/.bashrc
export MANPAGER="sh -c 'col -bx | bat -l man -p'"

eza — ls with the columns you wanted

Git status per file, a tree view, icons, human-readable sizes, and a grid that stays readable in a narrow terminal. The one that changes daily use is --git: a directory listing that also says which files are modified or untracked, without a second command.

cargo install --locked eza

eza -la --git --group-directories-first
eza --tree -L 2 --git-ignore
eza -l --sort=modified --reverse | head
eza --icons=auto -T -L 1

10Text surgery, counting, bytes, Markdown

Four small tools with sharp edges. sd does find-and-replace with a syntax you can remember, tokei counts code the way a report needs it, hexyl makes a hex dump legible, and mdcat renders Markdown in a terminal that can show pictures.

sd — search and displace

The signature is sd PATTERN REPLACEMENT [FILES], the pattern is a regex, and the default is to write in place. That last part is the danger and the point: no -i flag to remember, no backup file to clean up, and a preview mode when you want to look first.

cargo install --locked sd

sd 'foo' 'bar' file.txt             # in place
sd -p 'foo' 'bar' file.txt          # preview only
sd '(\d{4})-(\d{2})-(\d{2})' '$3/$2/$1' dates.txt
fd -e md -x sd 'localhost:8080' 'example.com' {}
sd 'fn (\w+)\(' 'pub fn $1(' src/lib.rs

tokei — how much code is actually here

Counts lines, code, comments and blanks per language, in parallel, with the language detected from the extension. It respects .gitignore, excludes vendored directories by default in the common cases, and outputs JSON or YAML when the number is going into a report rather than a terminal.

cargo install --locked tokei

tokei
tokei --sort code
tokei -e target,node_modules,dist
tokei --output json | jq '.Rust.code'
tokei src tests --compact

hexyl — a hex dump with colour

The columns are offset, bytes and ASCII, and the colours distinguish printable characters, whitespace, control codes and the null byte. That sounds cosmetic until you are looking for a stray \r\n in a protocol capture or a BOM at the start of a file; then the colour is the whole feature.

cargo install --locked hexyl

hexyl firmware.bin
hexyl -n 64 secrets.txt             # first 64 bytes only
hexyl -s 128 -n 32 data.bin         # a window
hexyl --border none --color always dump.bin | head

mdcat — read a README without leaving the shell

Renders Markdown with headings, tables, lists, syntax highlighting and, in terminals that support it, inline images. The renderer is strict about CommonMark and picks up local links, so a document with a table of contents behaves like a document. For a repository you have just cloned, it is the fastest way to read the instructions you are about to ignore.

cargo install --locked mdcat

mdcat README.md
mdcat docs/guide.md | less -R
mdcat --paginate CHANGELOG.md

11The machine: processes, disk, and who is using the network

bottom is top with graphs, procs is ps with colour and real sorting, dust is du that finishes, and bandwhich answers the question none of the others can: which process is using the bandwidth right now.

bottom — top, if top had been designed this decade

CPU, memory, network, disk and temperature in widgets you can rearrange, with mouse support, zoom, filters and a config file. It runs over SSH without complaint, and the search-and-kill flow (/ then dd) is the reason to keep it open on a server.

cargo install --locked bottom        # binary: btm

btm
btm --basic                          # no graphs, for a slow link
btm --battery
btm -t 500                           # sample every 500 ms

procs — ps with the columns that matter

Readable by default: colour per process state, a tree view, sortable by CPU or memory as a number rather than as a string. It also shows the command with its arguments wrapped instead of truncated, which is the difference between seeing a process and guessing at it.

cargo install --locked procs

procs
procs --tree
procs firefox
procs --sortd cpu | head -15
procs --or --and --watch 1

dust — du, drawn as a tree

It walks directories in parallel, then prints a tree of the largest entries with bars, so the answer to "what is eating the disk" is the first screen rather than a sorted list you have to read. The binary is dust; the crate is du-dust, which is the kind of registry detail this manual exists to record.

cargo install --locked du-dust        # binary: dust

dust
dust -d 2                            # two levels
dust -n 15                           # fifteen lines
dust -r                              # smallest first
dust -X target                       # skip a directory

bandwhich — the network, per process

Shows connections grouped by process and by remote address, with current throughput and totals, refreshing in place. It needs raw socket access to see other processes' traffic: run it with sudo, or grant the binary the capability once so it does not need a password. It is a diagnostic, not a firewall — nothing it shows is blocked by it.

cargo install --locked bandwhich

sudo bandwhich
sudo bandwhich -i wlan0
sudo setcap cap_net_raw,cap_net_admin=eip ~/.cargo/bin/bandwhich
bandwhich --total-utilization
