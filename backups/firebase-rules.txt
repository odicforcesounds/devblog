Signed-in-only comments — Firestore rules and provider setup
============================================================

What changed in docs/index.html
-------------------------------
- The comment widget now signs the reader in with Firebase Authentication before
  the form unlocks. The methods offered are Google, e-mail with password, and
  phone with an SMS code (see comments-login-failure.md for why the OAuth list
  shrank to the one provider the project actually has enabled).
- Anonymous sign-in is not imported, not called and not offered anywhere. There
  is no way to post without a provider account.
- The name input was removed: the name comes from the provider profile
  (displayName, or the local part of the email), capped at 60 characters.
- Each new document is written with:
    uid:       request.auth.uid of the signed-in user
    name:      display name from the provider, 1..60 characters
    photo:     profile picture URL (may be an empty string), <= 300 characters
    provider:  e.g. "google.com", "github.com", <= 40 characters
    message:   1..2000 characters
    createdAt: serverTimestamp()
- Comments are still readable by everyone; only writing requires an account.
- Existing documents without uid/photo/provider (written before this change)
  keep rendering normally. They are shown as plain names, without avatar.

The rules
---------
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    match /comments/{commentId} {
      // Anyone can read the thread.
      allow read: if true;

      // Only a signed-in user may write, and only as themselves.
      allow create: if request.auth != null
                       && request.resource.data.keys().hasOnly(
                            ['uid', 'name', 'photo', 'provider', 'message', 'createdAt'])
                       && request.resource.data.keys().hasAll(['uid', 'name', 'message', 'createdAt'])
                       && request.resource.data.uid == request.auth.uid
                       && request.resource.data.name is string
                       && request.resource.data.name.size() > 0
                       && request.resource.data.name.size() <= 60
                       && request.resource.data.message is string
                       && request.resource.data.message.size() > 0
                       && request.resource.data.message.size() <= 2000
                       && (!('photo' in request.resource.data)
                           || (request.resource.data.photo is string
                               && request.resource.data.photo.size() <= 300))
                       && (!('provider' in request.resource.data)
                           || (request.resource.data.provider is string
                               && request.resource.data.provider.size() <= 40))
                       && request.resource.data.createdAt == request.time;

      // No edits, no deletes from any client. Moderate from the console or with
      // an admin SDK that bypasses these rules.
      allow update, delete: if false;
    }
  }
}

Why each clause is there
------------------------
- request.auth != null: the only thing that stops anonymous writes. Client-side
  disabling of the button is UX; this clause is the actual lock.
- uid == request.auth.uid: a signed-in user cannot post as somebody else's uid,
  so two accounts cannot be confused later.
- keys().hasOnly([...]) plus hasAll([...]): rejects extra fields (nobody can
  smuggle an "isAdmin", "pinned" or "html" field into the document) while still
  accepting the optional photo/provider of older clients.
- name/message size caps: the same limits the page applies, enforced server-side.
- createdAt == request.time: matches serverTimestamp() exactly; a client cannot
  backdate or forward-date a comment.
- update/delete denied: comments are append-only from the browser.

Deployment
----------
Firebase console -> Firestore Database -> Rules: paste the block above and
publish. Or, with the CLI in the project root:

    firebase deploy --only firestore:rules

Keep the index for the query the page runs (orderBy createdAt desc, limit 50);
Firestore normally creates the single-field one automatically.

Enabling the providers (this part is console work, not code)
------------------------------------------------------------
Authentication -> Sign-in method. Enable only what you intend to support; the
page shows every button, and a provider that is not enabled answers with
"auth/operation-not-allowed", which the page reports as
"This sign-in provider is not enabled in the Firebase project yet."

Google
  1. Enable Google.
  2. Pick a project support email.
  Nothing else is needed.

GitHub
  1. GitHub -> Settings -> Developer settings -> OAuth Apps -> New OAuth App.
  2. Homepage URL: https://blog.odicforcesounds.com
  3. Authorization callback URL:
     https://blog-comments-6b4f5.firebaseapp.com/__/auth/handler
  4. Copy the Client ID and Client Secret into the GitHub provider in Firebase.

Microsoft
  1. Azure Portal -> App registrations -> New registration.
  2. Redirect URI (Web):
     https://blog-comments-6b4f5.firebaseapp.com/__/auth/handler
  3. Copy the Application (client) ID and create a client secret.

Apple
  1. Requires a paid Apple Developer account.
  2. Create a Services ID and a Sign in with Apple key.
  3. Return URL: https://blog-comments-6b4f5.firebaseapp.com/__/auth/handler
  4. Firebase asks for the Services ID, Team ID, Key ID and the .p8 key.

X / Twitter
  1. developer.x.com -> Project and App with OAuth 1.0a read/write.
  2. Callback URL: https://blog-comments-6b4f5.firebaseapp.com/__/auth/handler
  3. Copy API Key and API Secret into Firebase.

Facebook
  1. developers.facebook.com -> Create app -> Facebook Login.
  2. Valid OAuth Redirect URI:
     https://blog-comments-6b4f5.firebaseapp.com/__/auth/handler
  3. Copy App ID and App Secret. Facebook Login needs app review before it works
     for people who are not admins of the app.

Yahoo
  1. developer.yahoo.com -> Create app.
  2. Redirect URI: https://blog-comments-6b4f5.firebaseapp.com/__/auth/handler
  3. Copy Client ID and Client Secret.

Authorised domains
------------------
Authentication -> Settings -> Authorised domains must include:

    blog.odicforcesounds.com
    localhost            (only if you test locally)

Without that, sign-in fails with auth/unauthorized-domain.

Recommended extra lock: App Check
---------------------------------
The web API key is public by design, so anyone can call Firestore directly with
it. The rules above already stop anonymous writes, but App Check (reCAPTCHA v3)
also rejects traffic that is not coming from your pages. Enable App Check for
Firestore, register the web app with a reCAPTCHA v3 key, and add the initialisation
to the page when you are ready to enforce it. Enforce only after watching the
metrics for a few days, otherwise legitimate readers get blocked.

Optional: only your own accounts
--------------------------------
Requiring a provider still lets any GitHub or Google user post. If you want the
thread closed to everybody except a few people, keep the same rules and add the
uid allowlist. Sign in once with each account you want, read its uid in the
Firebase console (Authentication -> Users) and paste them here:

    allow create: if request.auth != null
                     && request.auth.uid in [
                          'UID_FIRST_ACCOUNT',
                          'UID_SECOND_ACCOUNT'
                        ]
                     && request.resource.data.uid == request.auth.uid
                     && ... the same field checks as above ...

The uid never changes, while an email or a display name can, so an allowlist on
uid survives profile edits and provider changes.

What this does NOT solve
------------------------
- Spam by a real, signed-in account. Rules cannot judge content; use moderation
  in the console, or a Cloud Function that checks rate per uid.
- Rate limiting per user. Firestore rules cannot count previous writes; a
  Cloud Function or App Check quota is the tool for that.
- Content moderation. Nothing here reads the message.

Social Tool Kit application collections
=======================================

docs/socialToolKitApp.html writes five collections in the same project,
blog-comments-6b4f5. Add these match blocks inside the existing
`match /databases/{database}/documents` block (the one under "The rules"
above), then publish. Nothing in the comments block changes.

    match /stk_users/{uid} {
      allow read: if true;
      allow create, update: if request.auth != null
        && request.auth.uid == uid
        && request.resource.data.keys().hasOnly(['name', 'email', 'repGroupId', 'createdAt'])
        && request.resource.data.keys().hasAll(['name', 'email', 'repGroupId'])
        && request.resource.data.name is string
        && request.resource.data.name.size() <= 60
        && request.resource.data.email is string
        && request.resource.data.email.size() <= 120
        && request.resource.data.repGroupId is string
        && (request.resource.data.repGroupId == ''
            || exists(/databases/$(database)/documents/stk_members/$(request.resource.data.repGroupId + '__' + request.auth.token.email.lower())));
      allow delete: if false;
    }

    match /stk_groups/{groupId} {
      allow read: if true;
      allow create: if request.auth != null
        && request.resource.data.keys().hasOnly(['name', 'site', 'leaderUid', 'leaderName', 'createdAt'])
        && request.resource.data.leaderUid == request.auth.uid
        && request.resource.data.name is string
        && request.resource.data.name.size() >= 2
        && request.resource.data.name.size() <= 60
        && request.resource.data.leaderName is string
        && request.resource.data.leaderName.size() <= 60
        && request.resource.data.site is string
        && request.resource.data.site.size() <= 120
        && request.resource.data.createdAt == request.time;
      allow update: if request.auth != null
        && resource.data.leaderUid == request.auth.uid
        && request.resource.data.diff(resource.data).affectedKeys().hasOnly(['name', 'site'])
        && request.resource.data.name is string
        && request.resource.data.name.size() >= 2
        && request.resource.data.name.size() <= 60
        && request.resource.data.site is string
        && request.resource.data.site.size() <= 120;
      allow delete: if request.auth != null && resource.data.leaderUid == request.auth.uid;
    }

    match /stk_members/{memberId} {
      allow read: if true;
      allow create: if request.auth != null
        && memberId == request.resource.data.groupId + '__' + request.resource.data.email
        && request.resource.data.keys().hasOnly(['groupId', 'email', 'name', 'addedBy', 'createdAt'])
        && request.resource.data.addedBy == request.auth.uid
        && request.resource.data.email is string
        && request.resource.data.email.size() > 3
        && request.resource.data.email.size() <= 120
        && request.resource.data.name is string
        && request.resource.data.name.size() <= 60
        && get(/databases/$(database)/documents/stk_groups/$(request.resource.data.groupId)).data.leaderUid == request.auth.uid
        && request.resource.data.createdAt == request.time;
      allow delete: if request.auth != null
        && (resource.data.addedBy == request.auth.uid
            || get(/databases/$(database)/documents/stk_groups/$(resource.data.groupId)).data.leaderUid == request.auth.uid);
    }

    match /stk_challenges/{challengeId} {
      allow read: if true;
      allow create: if request.auth != null
        && request.resource.data.keys().hasOnly(['title', 'path', 'coins', 'url', 'provider', 'videoId', 'authorUid', 'authorName', 'groupId', 'status', 'available', 'views', 'createdAt'])
        && request.resource.data.authorUid == request.auth.uid
        && request.resource.data.status == 'open'
        && request.resource.data.title is string
        && request.resource.data.title.size() >= 3
        && request.resource.data.title.size() <= 60
        && request.resource.data.path in ['NCP', 'ACP', 'HCP']
        && request.resource.data.coins is number
        && request.resource.data.coins >= 5
        && request.resource.data.coins <= 200
        && request.resource.data.coins == request.resource.data.coins.floor()
        && request.resource.data.url is string
        && request.resource.data.url.size() <= 300
        && request.resource.data.provider is string
        && request.resource.data.videoId is string
        && request.resource.data.views.size() == 0
        && request.resource.data.available.size() == 0
        && request.resource.data.createdAt == request.time;
      allow update: if request.auth != null
        && request.resource.data.authorUid == resource.data.authorUid
        && request.resource.data.coins == resource.data.coins
        && request.resource.data.title == resource.data.title
        && request.resource.data.path == resource.data.path
        && request.resource.data.url == resource.data.url
        && request.resource.data.provider == resource.data.provider
        && request.resource.data.videoId == resource.data.videoId
        && request.resource.data.groupId == resource.data.groupId
        && request.resource.data.diff(resource.data).affectedKeys().hasOnly(
             ['status', 'solverGroupId', 'solverName', 'available', 'proof', 'proofBy', 'proofAt', 'views', 'payout', 'publishedAt'])
        && (
          (request.resource.data.diff(resource.data).affectedKeys().hasOnly(['views'])
            && request.resource.data.views == resource.data.views.concat([request.auth.uid]))
          || (request.resource.data.diff(resource.data).affectedKeys().hasOnly(['available'])
            && resource.data.solverGroupId is string
            && exists(/databases/$(database)/documents/stk_members/$(resource.data.solverGroupId + '__' + request.auth.token.email.lower())))
          || (request.resource.data.diff(resource.data).affectedKeys().hasOnly(['status', 'solverGroupId', 'solverName'])
            && resource.data.status == 'open'
            && request.resource.data.status == 'assigned'
            && request.resource.data.authorUid != request.auth.uid
            && request.resource.data.solverGroupId == get(/databases/$(database)/documents/stk_users/$(request.auth.uid)).data.repGroupId)
          || (request.resource.data.diff(resource.data).affectedKeys().hasOnly(['proof', 'proofBy', 'proofAt'])
            && resource.data.solverGroupId is string
            && request.resource.data.proof is string
            && request.resource.data.proof.size() <= 300
            && exists(/databases/$(database)/documents/stk_members/$(resource.data.solverGroupId + '__' + request.auth.token.email.lower())))
          || (request.resource.data.diff(resource.data).affectedKeys().hasOnly(['status', 'publishedAt', 'payout'])
            && resource.data.status == 'assigned'
            && request.resource.data.status == 'published')
        );
      allow delete: if request.auth != null && resource.data.authorUid == request.auth.uid;
    }

    match /stk_ratings/{ratingId} {
      allow read: if true;
      allow create: if request.auth != null
        && ratingId == request.resource.data.challengeId + '__' + request.auth.uid
        && request.resource.data.uid == request.auth.uid
        && request.resource.data.keys().hasOnly(['challengeId', 'uid', 'verdict', 'createdAt'])
        && (request.resource.data.verdict == 'approve' || request.resource.data.verdict == 'refuse')
        && get(/databases/$(database)/documents/stk_challenges/$(request.resource.data.challengeId)).data.proof is string
        && get(/databases/$(database)/documents/stk_challenges/$(request.resource.data.challengeId)).data.authorUid != request.auth.uid
        && get(/databases/$(database)/documents/stk_challenges/$(request.resource.data.challengeId)).data.solverGroupId != get(/databases/$(database)/documents/stk_users/$(request.auth.uid)).data.repGroupId
        && request.resource.data.createdAt == request.time;
      allow update, delete: if false;
    }

Why each clause is there
------------------------
- One account, one identity: every document carries request.auth.uid, so a
  signed-in reader cannot write as somebody else.
- The member document id is the group id and the email, which lets the rules
  prove that a representing account really belongs to the group it claims.
  `exists()` is how a rule reads that membership document.
- Leader-only membership: a member document is created or deleted only by the
  account named as the group's leader (or by whoever added it).
- Coins and the video are fixed at publication. An update may move one
  challenge through its life but cannot change its title, link, coins or author.
- The views branch accepts exactly one value appended: the writer's own uid. A
  second attempt produces the same array and fails the equality test.
- A rating needs a proof, refuses the author and refuses the solving group. One
  document per account and challenge; no edits afterwards.
- The result branch only moves `assigned` to `published` and writes the payout
  plan with it.

What the rules cannot do
------------------------
- Count seven approvals. Rules cannot query a collection, so the page counts
  them and writes `published`. A Cloud Function is the place to make the
  seventh approval the only writer.
- Move coins. The payout is a plan stored on the challenge; a transfer needs a
  transaction with admin credentials, which never belong in a page.
- Rate-limit publishing. App Check and a counter in a function are the tools.

Deployment
----------
Firebase console -> Firestore Database -> Rules: merge the five blocks into the
existing service block and publish. The comments block stays as it is. Test
with two accounts before inviting anyone: one creates a group and adds the
other by email; the other represents it, takes a challenge and watches it once.
