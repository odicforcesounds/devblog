14The machine: what is using the disk

Two answers to one question. duf shows the filesystems — which mount has room, which is full, what is mounted but forgotten. gdu shows the folders inside one of them, sorted by weight, fast enough to point at a home directory.

duf — df, with the columns you wanted

Mount points grouped by device, usage bars, inode counts and a JSON output for scripts. It reads better than df -h because it stops pretending a network mount and a USB stick are the same kind of thing, and it works on Linux, macOS and Windows.

go install github.com/muesli/duf@v0.9.1
duf
duf -only local
duf --json | head -20

gdu — disk usage, in parallel

An interactive tree of what is large, with the option to delete without leaving the interface. It uses goroutines to read directories in parallel, which is why it finishes on a home folder while du is still thinking about it.

go install github.com/dundee/gdu/v5/cmd/gdu@v5.38.0
gdu
gdu ~/Downloads
gdu -n /            # non-interactive, for scripts

15Security: scan, sign, store, encrypt

Four tools with four different jobs: trivy finds known vulnerabilities, gitleaks finds secrets that should not be in a repository, gopass keeps the passwords, and age encrypts a file with a key you can hold in your head.

Trivy — what is vulnerable, exactly

Scans container images, filesystems, repositories and IaC files against vulnerability and misconfiguration databases, with severity filters and a JSON output for CI. It needs no daemon and no agent: point it at an image name and it downloads the metadata it needs.

go install github.com/aquasecurity/trivy/cmd/trivy@v0.76.1
trivy image alpine:3.20
trivy fs --severity HIGH,CRITICAL .
trivy repo https://github.com/owner/project
trivy config .

gitleaks — secrets do not belong in git

Scans a repository's history for API keys, tokens and private keys, using a rule set of provider patterns and entropy checks. It also runs as a pre-commit hook, which is the only moment when removing a leaked key is still cheap.

go install github.com/gitleaks/gitleaks/v8@v8.30.1
gitleaks git . --verbose
gitleaks dir . --verbose
gitleaks git --staged          # pre-commit

A secret committed once is compromised the moment it is pushed. Rotate it first, then clean the history — rewriting the past without rotating the credential cleans the evidence, not the problem.

gopass — passwords in a git repository

A pass-compatible password store: each secret is a GPG-encrypted file in a git repository you control, with recipients per folder and a clipboard mode. No account, no sync service, and a backup that is just a clone.

go install github.com/gopasspw/gopass@v1.17.4
gopass init
gopass insert -c work/mail
gopass show -c work/mail
gopass generate -c web/github 32
gopass ls

age — encryption with one key, one line

Modern file encryption with a deliberately small design: an X25519 key pair, a passphrase mode, and a format you can read in a spec. It replaced GPG for the case "encrypt this file for that person", and it composes: tar into age into ssh is a backup in one pipe.

go install filippo.io/age/cmd/age@latest
age-keygen -o key.txt
age -r age1ql3z7... -o backup.tar.age backup.tar
age -d -i key.txt backup.tar.age > backup.tar
age -p -o secret.age secret.txt      # passphrase instead of a key

16Sync and backup: the two that must not lie

rclone moves files between anything and anything — local disk, S3, Drive, SFTP, WebDAV. restic keeps encrypted, deduplicated snapshots that you can restore selectively. Sync is not backup, and the pair makes the difference obvious.

rclone — one client for every remote

Configure a remote once, then copy, sync, check, mount or serve it with the same flags. sync makes the destination match the source — including deletions — so it is a mirror, not an archive; copy only adds. Knowing which one you typed is the whole discipline.

go install github.com/rclone/rclone@v1.75.2
rclone config
rclone copy ~/Photos remote:backup/Photos -P
rclone sync ~/Docs remote:docs --dry-run
rclone check ~/Docs remote:docs
rclone mount remote: /mnt/remote

restic — encrypted snapshots with retention

A repository holds snapshots; each snapshot references deduplicated, encrypted chunks. forget --prune applies a retention policy, and restore can bring back one file from three years ago. The repository can live on a local disk, an SFTP host or an S3 bucket.

go install github.com/restic/restic/cmd/restic@v0.19.1
export RESTIC_REPOSITORY=/mnt/backup/restic
export RESTIC_PASSWORD_FILE=~/.restic-pass
restic init
restic backup ~/Documents ~/Projects
restic snapshots
restic restore latest --target /tmp/restore --include "Projects/x"
restic forget --keep-daily 7 --keep-weekly 4 --prune
restic check

Test the restore before you trust the backup. A repository that has never been restored is a hypothesis, and restic check --read-data is the command that turns it into evidence.

17Serve and reach: sites, TLS, network

Hugo builds a site from Markdown in milliseconds, Caddy serves it with automatic HTTPS, and Tailscale makes the machine reachable without opening a port. Three binaries, no runtime, one small server.

Hugo — a static site in one binary

Content in Markdown, layouts in Go templates, output as files. It is the generator this blog's neighbours use when a build has to finish before a coffee does, and it ships as a single executable with no plugin runtime.

go install github.com/gohugoio/hugo@v0.169.0
hugo new site myblog
cd myblog
hugo new content posts/hello.md
hugo server -D
hugo --minify

Caddy — a web server with certificates included

A Caddyfile is four lines, and HTTPS is not one of them: certificates are obtained and renewed automatically for any domain that resolves to the machine. It also proxies, rewrites and serves PHP or FastCGI when asked, with a JSON config for anything the Caddyfile cannot express.

go install github.com/caddyserver/caddy/v2/cmd/caddy@v2.11.7
# Caddyfile
example.com {
    root * /srv/site
    file_server
}
caddy validate --config Caddyfile
caddy run
caddy fmt --overwrite Caddyfile

Tailscale — your own private network

A WireGuard mesh that connects your machines wherever they are, with identity instead of firewall rules. tailscale serve exposes a local port to your own devices only; tailscale ssh authenticates with the same identity, so a home server stops needing a public IP or an open port.

go install tailscale.com/cmd/tailscale@latest
sudo tailscale up
tailscale status
tailscale ip -4
tailscale serve 8080
tailscale ssh server

On Linux the daemon needs root; the client does not. That is why the install line is followed by sudo tailscale up and not by sudo go install — the binary belongs to you, the network interface belongs to the system.

18The ten messages that stop a build

Go's errors are unusually literal, which is a gift: each line below names the thing that is wrong. The table maps the message to the cause, because the cause is usually one directory or one version away from the message.

Message What it means Fix
go: command not found The toolchain is not on PATH — either not installed, or installed into /usr/local/go without the export line. Add /usr/local/go/bin to PATH, open a new shell, then go version.
command not found: lazygit after a successful install The binary is in $(go env GOPATH)/bin (or GOBIN) and the shell does not search there. Add that directory to PATH, or set GOBIN to one already on it. Part 05.
go: go.mod file not found in current directory or any parent directory You ran go build, go run or go test outside a module. go mod init example.com/me/thing in the project root — or use go install pkg@version, which needs no module.
cannot use path@version syntax in GOPATH mode GO111MODULE=off is set, which disables modules entirely. go env -u GO111MODULE and retry. Modules are the only supported mode.
go: go.mod requires go >= 1.26.0 (running go 1.22.1; GOTOOLCHAIN=local) The project needs a newer Go, and automatic toolchain switching is disabled. go env -w GOTOOLCHAIN=auto, or install the newer release from go.dev/dl.
no required module provides package X; to add it: go get X The import exists in the code but not in go.mod. go get X then go mod tidy.
module github.com/a/b@latest found (v1.2.3), but does not contain package github.com/a/b/cmd/c The module is right; the subdirectory in the path is not. The main package lives elsewhere. Look at the repository tree for the directory holding main.go, and use that path.
verifying github.com/a/b@v1.2.3: checksum mismatch The cached copy does not match the recorded hash, usually a corrupted download or a retagged release. go clean -modcache and retry. If it persists, the upstream tag genuinely changed — do not disable the checksum database to silence it.
dial tcp … i/o timeout or 403 Forbidden fetching a module The module proxy is unreachable, blocked, or the module is private. Check GOPROXY; for private modules set GOPRIVATE=github.com/yourorg/* and use SSH credentials.
permission denied writing to /usr/local/bin GOBIN points at a root-owned directory, or the command was run with sudo. Unset GOBIN and let it write to ~/go/bin. Never sudo go install.
The two failures that look like the machine dying

A build that ends in Killed ran out of memory — add swap, or build the specific package instead of the whole module. A build that compiles for twenty minutes the first time and two seconds afterwards is the build cache doing its job; go clean -cache resets it, and the long wait is not a sign that something is wrong.

19Sources, and what each one settles

The manual is built from the Go project's own documentation and from the module metadata each tool publishes. Every tool in part 07 links to its repository, which is the authority on its own flags.

  • go.dev/dl — downloads Every release archive and installer, with checksums, for every supported platform.
  • go.dev — install The official removal-and-extract procedure used in part 02, per operating system.
  • Go modules reference Module paths, versions, the module cache, and the exact semantics of go install pkg@version.
  • Go toolchains How GOTOOLCHAIN decides to download a newer compiler, and what auto and local mean.
  • cmd/go documentation The command reference, including the environment variables table used in part 02.
  • GOPATH and workspaces What GOPATH still governs now that modules own dependency resolution.
  • Module proxy protocol The protocol go install speaks — and the reason a plain URL can be checked for a version.
  • Release and support policy Which Go versions still receive fixes, and why the newest two matter for a tool you install.
  • pkg.go.dev The package index: module paths, versions and documentation for everything named here.
  • Deprecation of go get for executables The change that split installing a tool from adding a dependency, and the migration it asks for.
  • Go wiki — modules The community-maintained notes on module behaviour, including the corner cases the reference leaves implicit.
  • golangci-lint documentation Configuration, the linter list and the formatter command used in part 12.

Versions in part 07 are the newest tags resolved through the public module proxy on 29 October 2026, and the Go requirement is the one written in each version's go.mod. Both will move; the repository remains the authority.
