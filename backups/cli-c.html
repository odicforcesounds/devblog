11Data: SQLite, CSV, JSON, Postgres

Most "data work" is not a notebook. It is a file with rows, a question about those rows, and a shell where the file already is. These five tools answer the question without opening an editor: datasette publishes a database as a browsable site, sqlite-utils builds and edits it, csvkit slices text files, jc converts any command's output to JSON, and pgcli gives Postgres autocomplete.

Datasette — a database with a URL

Point it at a SQLite file and it serves a browsable, filterable, facetable interface with a JSON API on every table. It is the fastest way to let someone else look at your data without sending them the file, and it needs no server configuration at all.

pipx install datasette
datasette mydata.db                    # http://127.0.0.1:8001
datasette mydata.db -m metadata.json --port 8080
datasette mydata.db --cors --setting sql_time_limit_ms 5000

Every table also answers as JSON: append .json to the URL. That single feature replaces a small API project more often than people expect.

sqlite-utils — the database, from the command line

Inserts CSV and JSON into SQLite, creates tables from the data's shape, runs queries, alters schemas and converts columns — the operations you would otherwise write twelve lines of Python for, every time.

pipx install sqlite-utils
sqlite-utils insert data.db readings readings.csv --csv --detect-types
sqlite-utils schema data.db
sqlite-utils query data.db "select month, avg(value) from readings group by 1"
sqlite-utils convert data.db readings value 'float(value.strip())'

csvkit — fourteen commands, one idea

Each utility does one transformation and writes CSV to stdout, so they compose in a pipe: cut columns, filter rows, sort, join, describe, then query the result with SQL. It also reads XLSX, which makes it the bridge between a spreadsheet and everything else.

pipx install csvkit
csvlook sales.csv
csvcut -c 1,3,7 sales.csv | csvsort -c 3 -r | head
csvgrep -c country -m "PT" sales.csv
in2csv report.xlsx > report.csv
csvsql --query "select country, sum(total) from sales group by 1" sales.csv

jc — JSON from any command

Takes the text output of a hundred familiar commands — ls, ps, df, ip, dig, systemctl — and returns structured JSON, so the next step can be jq instead of awk. It also parses the formats that have no parser: ini, csv, yaml, syslog, crontab.

pipx install jc
ls -l | jc --ls -p | jq '.[] | select(.size > 1000000) | .filename'
df -h | jc --df -p
cat /etc/hosts | jc --hosts -p

pgcli — Postgres with autocomplete

A Postgres client that knows your schema: table and column names complete as you type, syntax is coloured, and the results page themselves. The same family includes mycli for MySQL and litecli for SQLite, from the same maintainers.

pipx install pgcli
pgcli postgresql://user@localhost:5432/mydb
# inside the prompt
\d                     # tables, views, sequences
\d+ users              # columns, indexes, constraints
\dp                    # permissions

12Documents: scan, print, label

Three small tools with the same shape: input on the left, a file on the right, no application window. OCR turns a scan into text, WeasyPrint turns HTML and CSS into a print PDF, and qrcode turns a string into something a phone can read.

OCRmyPDF — a scanned PDF that can be searched

Adds a text layer to an image-only PDF, keeping the original scan underneath: it looks identical, and Ctrl+F works. It is the difference between an archive and a pile of pictures of documents. Tesseract and Ghostscript are system packages, not pip packages.

sudo apt install tesseract-ocr tesseract-ocr-por ghostscript
pipx install ocrmypdf
ocrmypdf scan.pdf searchable.pdf -l por
ocrmypdf --skip-text batch.pdf out.pdf      # leave existing text alone
ocrmypdf --deskew --clean --rotate-pages in.pdf out.pdf
ocrmypdf -l por+eng --jobs 4 in.pdf out.pdf

Language packs are the usual surprise: tesseract-ocr-por for Portuguese, -eng for English, -spa for Spanish. Without the pack, OCR runs with an English model and mangles every accent.

WeasyPrint — HTML to PDF, properly

Renders HTML with real CSS support, including paged media: margins, running headers, page numbers, footnotes and page breaks. It is how a generated invoice, a report or a book stops being a screenshot of a browser.

sudo apt install libpango-1.0-0 libpangoft2-1.0-0     # Debian 12+
brew install pango                                    # macOS
pipx install weasyprint
weasyprint invoice.html invoice.pdf
weasyprint --base-url ./assets report.html report.pdf

The CSS to learn is small: @page { size: A4; margin: 2cm }, @page { @bottom-center { content: counter(page) } }, and break-before: page. That is most of a printable document.

qrcode — a QR code from the prompt

Small, old, and still the quickest way to put a URL into a room: generate a PNG or an SVG, print it, stick it on a shelf label or a business card. The CLI is called qr, and it needs the image extra.

pipx install "qrcode[pil]"
qr "https://blog.odicforcesounds.com" > qr.png
qr --factory=svg "wifi://..." > qr.svg
qr --version=5 --error-correction=H "long text here" > big.png

Higher error correction means a denser image that still reads when partly covered — worth it for anything printed small or placed outdoors.

13Terminal craft: files, mistakes, memory

Four tools that make the shell itself better: a file manager that never leaves the keyboard, a corrector for the command you just mistyped, a manual with examples instead of flags, and a renderer that makes Markdown and code readable at the prompt.

ranger — three columns, no mouse

A terminal file manager with a preview pane: text, images (in a suitable terminal), PDFs, archives. Moving, copying, bulk renaming and opening a shell in the current directory are single keys. It is the answer for a server where ls is not enough and a desktop is not available.

pipx install ranger-fm
ranger
# hjkl move, space select, yy copy, dd cut, pp paste
# :mkdir name   :rename   S  shell here   ?  keys

thefuck — the correction after the swear word

When a command fails because of a typo or a missing sudo, type fuck and it proposes the corrected command, which you accept with Enter. It reads the previous command and its error, not your intentions — which is why it works so often.

pipx install thefuck
# add once to ~/.bashrc or ~/.zshrc
eval $(thefuck --alias)
# then
fuck
fuck --yeah      # accept without asking
fuck --repeat    # keep fixing until it works

tldr — the manual, with examples

Man pages list every flag; tldr pages show the five invocations people actually use. The Python client downloads the community pages and caches them locally, so lookups are instant and offline after the first update.

pipx install tldr
tldr tar
tldr --update
tldr --list | head

rich-cli — Markdown and code, rendered

Prints a file the way it was meant to look: Markdown with headings and tables, source code with syntax highlighting and line numbers, JSON pretty-printed, CSV as a table. Useful for READMEs over SSH and for checking generated output before it ships.

pipx install rich-cli
rich README.md
rich --syntax python script.py
rich --json data.json
rich --csv table.csv --columns 1,3

14A personal library that outlives the app

The best argument for command-line tools is not speed, it is ownership: the music library is a folder of tagged files, the bookmarks are a SQLite database, the calendar is a directory of .ics files. Nothing here needs an account, and everything can be backed up with rsync.

beets — the music library that fixes itself

Imports a folder, fingerprints the audio, looks up the release, writes correct tags, moves the files into a clean tree and stores everything in a queryable database. Once set up, beet import is the only command you need for a new album.

pipx install beets
beet import ~/Downloads/album
beet ls -a artist:radiohead
beet fetchart
beet lyrics
beet write          # push database changes back to the files

Configuration lives in ~/.config/beets/config.yaml: library path, directory format, plugins. The important habit is beet write — the database is a convenience, the files are the archive.

buku — bookmarks you own

A bookmark manager for the terminal with tags, full-text search and an HTML export. The database is one SQLite file, so it syncs, greps, and survives the death of any company.

pipx install buku
buku -a https://example.com/article python cli reading
buku -s "sqlite"
buku --export bookmarks.html
buku -p          # print the database path

khal — the calendar as files

Reads and writes calendars stored as iCalendar files in a folder — the same format every phone and mail client understands. Paired with vdirsyncer, it keeps a local copy in sync with a CalDAV server, so the terminal and the pocket agree.

pipx install khal vdirsyncer
khal list
khal list today 7d
khal new tomorrow 18:00 19:00 Dinner with Ana
ikhal          # interactive editor

The config is ~/.config/khal/config: one section per calendar, a path, a colour. Start with a single local calendar before adding a server; syncing is a second problem.

todoman — tasks as text, not as an app

Manages tasks in the same iCalendar format, one file per task, with lists, due dates, priorities and a compact table view. Because the storage is plain text, a task can be edited with any editor and still be found by the tool.

pipx install todoman
todo list
todo new "renew the passport" --due 2026-11-15 --list Personal
todo done 3
todo edit 3

15Serve and ship: docs, traffic, inspection

Two tools for putting something on the network, and one for understanding what a program sends over it. Both are Python apps that install with a single command and run from a folder, which is the whole aesthetic of this manual.

MkDocs — Markdown in, site out

A documentation generator with a live-reload server: write Markdown, keep a small mkdocs.yml, and mkdocs serve shows the site while you type. mkdocs build produces static files that any host will serve. It is also a perfectly good blog engine if you stop at the first theme.

pipx install mkdocs
mkdocs new my-docs
cd my-docs
mkdocs serve            # http://127.0.0.1:8000
mkdocs build --strict
mkdocs gh-deploy        # publish to GitHub Pages

mitmproxy — look at the traffic

An intercepting proxy with three front ends: an interactive console, a web UI, and a non-interactive mode for scripts. It is how you find out what an app actually sends — which headers, which endpoint, which payload — and how you replay a request until it behaves.

pipx install mitmproxy
mitmproxy               # console, on port 8080
mitmweb                 # browser UI
mitmdump -w session.flows
mitmdump -nr session.flows --set flow_detail=1

To see HTTPS you install mitmproxy's CA certificate in the client you are testing — the project documents it per platform. Use it on your own devices and your own traffic: intercepting someone else's is not a debugging technique, it is an attack.
