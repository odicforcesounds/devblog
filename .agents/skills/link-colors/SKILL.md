# Link colours — where a link goes, at a glance

Three destinations, three colours. A reader can tell without hovering whether a link
stays in the blog, crosses to the art site, or leaves for the wider web.

| Kind | What matches | Colour |
| --- | --- | --- |
| Local | `docs/*.html`, `./x`, `images/x`, `https://blog.odicforcesounds.com/x.html` | `--link-local` `#6fb3ff` |
| Art | `https://art.odicforcesounds.com/...` | `--link-art` `#ffd23f` |
| External | any other `http`/`https` link | `--link-external` `#ff9ecb` |
| Kept as written | `#anchor`, `mailto:`, `javascript:` — they go nowhere new | the page's own colour |

Hover and keyboard focus turn every link white, so the colour underneath says *where*
and the hover says *this one, now*.

## How it is applied

`docs/link-colors.css` is generated by `link_colors.py`, and the runner inserts one
line before `</head>` of every page except `index.html`:

```html
<link rel="stylesheet" href="link-colors.css">
```

`404.html` gets `/link-colors.css` instead, because that page is served at any depth.

Why a separate sheet rather than `article.css`:

- 156 pages do not load `article.css` (the five catalogues, `awesomeIndex.html`,
  `404.html`, older articles), and they need the same colours.
- A same-origin stylesheet is allowed by `default-src 'self'` — no page needs
  `style-src 'unsafe-inline'` for this.
- It is the **last** stylesheet in the head, so it wins the cascade against
  `article.css` (`.textbox a`, `.textbox a.external`) and against a page's own
  `<style>` block. The three colour rules carry `!important` on purpose: the pages
  already style their links with more specific selectors, and a theme rule must not
  lose to them. The four colours are custom properties on `:root`, so one edit at the
  top of the file changes the whole site.

## The art host comes from the map

`backups/art_map.json` records the art site (`"site": "https://art.odicforcesounds.com"`).
The runner reads it and writes the host into the selector, so the art rule follows the
map instead of a string typed in two places. No map, no `site` key: it falls back to
`art.odicforcesounds.com`.

## Commands

```sh
python3 .agents/skills/link-colors/link_colors.py            # sheet + one link per page
python3 .agents/skills/link-colors/link_colors.py --dry-run   # report only
python3 .agents/skills/link-colors/link_colors.py --check     # exit 1 if a page lacks it
python3 .agents/skills/link-colors/link_colors.py --remove     # take the links out
```

Both the sheet and the links are idempotent: a second run changes nothing, and
`--remove` leaves the sheet on disk (a page may still link it deliberately).

## What it counts

Every run prints the population it is colouring, read from the pages themselves:

```
links: local 5278 | art 128 | external 51285 | kept as written 3222
```

That line is the check that the selectors and the pages agree. Numbers that move
without a page change mean a selector or the art host drifted.

## After a run

```sh
python3 .agents/skills/blog-ops/check_site.py      # head tags, JSON-LD, sitemap, API
python3 .agents/skills/link-colors/link_colors.py --check
```

`index.html` is deliberately left alone: it has its own palette in `index.css`. A page
that already links the sheet is not linked twice — the runner strips its own tag first,
so the tag is always the last stylesheet in the head.
