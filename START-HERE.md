# Start here

The first file an agent reads in this repository. It sets the **scope**: what may be
touched at all. `AGENTS.md` and the skills under `.agents/skills/` say *how* to do the
work this file authorises — read them next, in that order, and load the skill that
matches the task before opening an editor.

    START-HERE.md  →  AGENTS.md  →  .agents/skills/<skill>/SKILL.md  →  the named file

If a request conflicts with this page, the request wins only where it names the file
and the change explicitly. Everything else stays as it is.

## The five limits

1. **Tools are read-only.** Never edit, rewrite, reformat or "improve" a script:
   `.agents/skills/*/*.py`, `.agents/skills/*/*.sh`, `pushit.sh`, `update.sh`,
   `docs/*.js`, `docs/tools/*`, `tools/*`, `tmp/*`. Running one is also a change when it
   rewrites files — run a generator only when the request asks for its output.
2. **Skills are read-only.** No file under `.agents/skills/**` changes: not `SKILL.md`,
   not a script beside it, not a description, not a typo. A wrong rule is reported, not
   quietly fixed.
3. **Only `docs/*` pages may change, and only the ones the request names.** Every other
   path in the repository is read-only, including `AGENTS.md`, `README.md`, this file,
   `backups/`, `templates/`, `docs/api/**`, the catalogue data, and every page the
   request did not name.
4. **Nothing is deleted, moved or renamed.** No `rm`, no `mv`, `git rm`, `git mv`, no
   emptying a file to make a check pass, no truncation. Restoring a damaged data file
   is a change to that file — it needs to be asked for.
5. **Nothing is committed or pushed unless asked.** When it is asked: no attribution of
   any kind (no `Generated with`, `Co-Authored-By`, emoji footer), and the author's own
   message. `.agents/skills/blog-ops/commitit.sh` is the per-file path.

Also: **no comments** in any file unless the request asks for them — no HTML comment
about the task, the session or the intent.

## What may change

| Path | May an agent change it? |
| --- | --- |
| `docs/Page.html` named in the request | Yes — that file only |
| Any other page under `docs/` | No |
| `docs/api/**`, `docs/sitemap.xml`, `docs/robots.txt`, `docs/living-panel.js` | No — generated |
| `docs/*.css`, `docs/*.js`, `docs/tools/**`, `docs/images/**` | No |
| `.agents/skills/**`, `AGENTS.md`, `README.md`, `START-HERE.md` | No |
| `backups/`, `templates/`, `tools/`, `tmp/`, `.github/` | No |
| Anything else | No — ask first |

## Report, do not repair

A defect found outside the request is **reported**, with the file, the line and the
evidence, and left in place. That includes a broken link on another page, a corrupted
data file, a stale path in a skill, a failing check. Repairing it is a separate request.

## Check `docs/api` first — it is the site's own index

`docs/api/index.json` is generated by `.agents/skills/blog-ops/build_api.py` and lists
every article: `path`, `slug`, `url`, `title`, `description`, `lang`, `published_at`,
`modified_at`, `words`, `chars`. `docs/api/dates.json` carries name → publication instant
for the front page, and `docs/api/text/NNN.json` holds the article text in chunks.

The contract: **every page under `docs/` is indexed except `404.html` and `home.html`**
(the error page and the redirect stub). Read the index before and after any change to a
page, and never edit it by hand.

```sh
python3 - <<'PY'
import glob, json, os
api = json.load(open('docs/api/index.json'))
indexed = {os.path.basename(a['path']) for a in api['articles']}
pages = {os.path.basename(p) for p in glob.glob('docs/*.html')}
print('pages', len(pages), '| indexed', api['count'])
print('on disk, not indexed :', sorted(pages - indexed))
print('indexed, not on disk :', sorted(indexed - pages))
PY
```

Expected output, at the time of writing:

```
pages 542 | indexed 540
on disk, not indexed : ['404.html', 'home.html']
indexed, not on disk : []
```

The index's `path` is relative to `docs/` (`index.html`, `2FA.html`), so compare by
basename — comparing `a['path']` against `docs/*.html` reports every page as missing.

- `docs/api` is **stale, not wrong**, after a page is edited — say so and stop; rebuilding
  it writes to 15 text chunks and both JSON files, so it needs to be asked for.
- If a shelf under `docs/awesome/data/` is no longer JSON, `awesomeIndex.html` cannot draw
  a single tool. Report the file and the commit that broke it; the restore is a request of
  its own.

## Read-only checks worth running

```sh
python3 .agents/skills/blog-ops/check_site.py           # expect "0 failures"
python3 .agents/skills/blog-ops/page_hygiene.py docs/Page.html   # the page you changed
git status --porcelain                                  # only the named files, nothing else
```

`check_site.py` is a read-only audit. `page_hygiene.py` is a read-only audit. Anything
that writes — `build_api.py`, `build_sitemap.py`, `enrich_schema.py`,
`.agents/skills/living-panel/*.py`, `restore_awesome_data.py`, `fix_story.py` — is out of
bounds unless the request names its output.

## Stop and ask when

- the request names no file, or names a file outside `docs/`;
- the change needs a tool or a skill edited (never do it — say which line and why);
- the change needs a file deleted, moved or renamed;
- the change would need a generator run (that rewrites hundreds of files);
- a check fails for a reason unrelated to the request;
- the request contradicts this page. Quote the line and ask which wins.
